## Outcome

Q1-P0 rules F1 before any non-trivial SQL filter exists. ADR-0021 selects a total
two-valued predicate algebra: every comparison involving an absent operand is `false`, then
Boolean composition proceeds normally. It binds the six current positions separately, decides
F3's status, and rejects optional `SUM` rather than copying PostgreSQL's silent null-skipping.

The canonical kernel now executes the absent rule in the strict G2-EK1 entry point. Its
existing one-argument runtime mode remains literal-true-only, so no query, operation, provider,
or SQL path is widened by this packet.

## Decision record

Read
[`ADR-0021-total-absent-value-semantics.md`](../../decisions/ADR-0021-total-absent-value-semantics.md).
Its decisive choices are:

- comparisons with an absent operand are false, including both `equals` and `notEquals`;
- query filters exclude on false, preconditions reject, guards disable, visibility hides,
  validation rejects, and Boolean derivations derive false;
- SQL must totalize each atomic comparison before `not`/`all`/`any`, never only coalesce the
  final `WHERE` result;
- `>=` and `<=` are required primitives but remain unadmitted here. The v2 compiler rejects
  `greaterThanOrEqual` and `lessThanOrEqual`; Q1 must add them through an explicit
  language/profile version and may not substitute negation;
- `SUM(optional)` is compile-time inadmissible. Required-field `SUM` uses zero for empty input,
  so Q1's SQL must use the typed equivalent of `COALESCE(SUM(field), 0)`.

The rejected candidates were raw Kleene three-valued propagation, a runtime error on absence,
and rejecting every optional-field comparison. The first fails the current Boolean position
result and erases the F3 distinction when collapsed at the boundary; the second makes valid
expressions partial; the third makes ordinary filters over the model's default field presence
unavailable.

## Implementation

- `predicate-kernel.ts` remains the only predicate-kind dispatch owner. Its target-evaluation
  mode parses exact wire shapes, dispatches each node version, enforces depth 24, owns absent
  conversion and Boolean composition, and returns position-stamped receipts.
- The target-owned callback supplies present-value comparison truth or an explicit `absent`
  tag. It cannot redefine what `absent` means.
- Every term is evaluated, so canonical term ordering cannot make correctness depend on
  short-circuit order.
- The literal-true runtime fence remains behaviorally unchanged. Current gateways still reject
  every non-trivial predicate.
- A new PostgreSQL suite is admitted into the exact architecture inventory and is discovered by
  the existing quoted `test/postgres/**/*.test.ts` script.

No canonical authored bytes, compiler projection bytes, release root, `.golden.bytes`, or
`.golden.sha256` artifact moved. This packet adds an evaluator/profile receipt surface without
changing an authored node or a compiled projection.

## Executed evidence

The real PostgreSQL probe printed:

```text
Q1-P0 absent probe: kernel_not_less=true raw_sql_not_less=NULL total_sql_not_less=true total_sql_greater_or_equal=false sum_optional=5 rows=3 present=2 empty_sum=NULL
```

That single row observes the required cross-target facts:

- raw `NOT(NULL < 5)` is `NULL`, disagreeing with the total kernel's `true`;
- atomic totalization makes PostgreSQL return the same `true`;
- total `NULL >= 5` is false, so it differs from `NOT(NULL < 5)` and negation cannot implement
  F3;
- PostgreSQL skips one absent element (`3` rows, `2` present, sum `5`) and returns `NULL` for an
  empty sum.

Canonical unit tests execute all six position profiles, the negated absent comparison, the
invalid-resolution rejection, both rejected F3 spellings, and the optional aggregate compile
rejection.

## What becomes newly reachable in Q1

Q1 may now design its first non-trivial filter lowerings against a named total result instead
of ambient PostgreSQL null behavior. It must:

1. totalize atoms before Boolean composition and add the differential parity corpus;
2. version and admit real `>=` / `<=` nodes before claiming F3 completeness;
3. reject optional aggregands and totalize empty required sums to zero;
4. close the already-recorded precondition field-locality defect before any non-trivial
   precondition reaches transaction-bound execution; and
5. carry the separately required policy-predicate injection seam without implementing policy
   as a post-fetch filter.

The precondition locality defect is louder now because the kernel has a semantics oracle for a
non-trivial expression, but remains unreachable in product execution: the one-argument gateway
fence still rejects it. This packet does not fix or conceal that Q1-owned hole.

## Known limits and what the gates cannot prove

- No non-trivial SQL lowering exists yet. The illustrative totalized SQL is evidence of the
  ruled result, not production SQL authority.
- Present-value decimal, money, quantity, date/time, text-collation, Unicode-fold, and
  cross-target parity remain Q1/G6 work. The target supplies present comparison truth.
- Scalar derivation nodes do not exist in PredicateExpression v0. ADR-0021 forbids a future
  scalar derivation from using host `undefined` or raw `null`, but this packet can only execute
  the current Boolean derivation profile.
- Aggregate grammar does not exist yet, so the current canonical boundary rejects every
  aggregate. The ADR constrains Q1's future narrowing to required fields; this packet cannot
  observe code that has not been written.
- The source tripwire is a proxy for duplicate evaluator dispatch. It cannot prove a future
  consumer calls the kernel; Q1's execution receipts and differential provider corpus must.
