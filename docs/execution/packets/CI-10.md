# CI-10 — a docs-only fast path for pull requests

Base: origin/main at the time of the lane cut. Tier: CI infrastructure, Critical under rule 18 (CI gate). No product code changed.

CI tier: pending full

## Why

A one-file plan amendment (PR 141) ran the whole quick tier: lint, typecheck, build, unit (about 6 min), compiler, architecture, and both full-history secret scans plus a dependency audit (4 to 5.5 min each). A Markdown change cannot affect lint, types, the build or the dependency tree, and only one unit test reads a Markdown document.

## Items

1. Selector (`.github/scripts/ci-selection.mjs`): a `docs` output, true only on a quick, non-main, non-forced run where every changed path is an added or edited Markdown file under `docs/`, `README.md` or `learnings.md`. A `base` output carries the range base. Main pushes never set it, so main still runs every fixed suite over each docs change.
2. `documentReaders` now lists `test/unit/observability.test.ts` for the plan and ADR-0032, the only unit or compiler readers of Markdown. A new architecture test refuses any unit or compiler test that names a Markdown document without a `documentReaders` entry.
3. Quality job, docs-only: skips lint, typecheck, build, both expected-red steps, unit, compiler, both release-freshness checks and the scaffold upload. It keeps install, the tier-declaration check, formatting, architecture whole, the selected node tests (the document readers, by name), and the whitespace and cleanliness check, and adds `scripts/check-records.sh` (AGENTS.md section 5).
4. Security job, docs-only: one `range` scan over the pull request's own commits (`base..HEAD`), with the synthetic-secret control kept and no install or dependency audit. Main's runs keep both full-history halves and the audit.
5. Reachability: `CI_DOCS` makes architecture the only fixed producer; `check-reachability.ts` no longer passes `fixedQuickFile` straight to `filter`, which would have fed it the index.

## Rule 8 reds (manifest `test/evidence/CI-10.expected-red.json`, 5 entries)

Fast path accepts a non-docs file or a deletion; a main push takes the fast path; an unlisted document reader; a docs run keeps the unit suite; the unit step loses its docs gate. The `range` scan has no red: it is bash over Docker, shown by the evidence pull request's security job.

## Rule 17

- Most general form: one flag from the selector gates every step a Markdown change cannot affect; one reader map covers every suite the flag skips.
- Narrower: the reader guard sees string literals only. An indirect read through a helper is not caught here; main's full fixed suites are the backstop.

2. The `range` secret scan: the base is the pull request base, an ancestor already covered by main's full-history scans.
