## Outcome

Business-key uniqueness now has one compiled physical contract:

```text
UNIQUE (tenant_id, environment_id, folded_key_column)
  WHERE archived_at IS NULL
```

The semantic unique key and its separate `caseInsensitiveUnique` index both
carry that predicate. The provider validates and safely renders only the
entity's declared archive-column `IS NULL` predicate; it does not execute an
arbitrary compiler string. Fresh tables receive both partial unique indexes,
and the catalog verifier compares both the normalized predicate and complete
index definition.

This is unconditional in the current language. Party numbers, Catalog SKUs,
and Location codes all need reuse after retirement, while no shipped module
needs permanent reservation. Paying a canonical-language event for a
hypothetical document/serial distinction would add a spelling no current
package exercises. The target remains a first-class per-key archive-scope
property when a real permanent-reservation case appears; that canonical change
is deliberately not speculated into this packet.

Location proves the user-visible outcome through the composed runtime: create
`WH-A`, reject a second active `wh-a`, archive the original, then create the
replacement successfully. A restore that now collides fails atomically with
the existing typed `MODULE_UNIQUE_VIOLATION` naming the canonical Location-code
field; the original stays archived and the replacement stays active.

## Existing-index replacement

The replacement is a platform migration rather than a storage-transition
element. Module tables are shared dynamic objects, and the current transition
grammar has no drop/replace operation. Emitting the new predicate under an old
name would make `CREATE INDEX IF NOT EXISTS` a no-op and leave the defect live.

The migration runs under the migration runner's transaction and advisory lock.
For every non-primary unique index on a managed module table with an
`archived_at` column, it:

1. leaves an already-correct `archived_at IS NULL` index unchanged;
2. fails closed on any different pre-existing predicate;
3. drops a legacy full index and recreates its exact definition with the
   archive predicate and the same physical name.

PostgreSQL's transactional DDL makes the replacement atomic: a failure rolls
back to the old full indexes, and other sessions never observe the interval
between drop and create. The operation takes locking DDL and belongs in the
online-strategy window. The executed upgrade control proves both physical
names and the `north_star_module_materializer` owner survive.

Persisted pre-packet storage targets lack the new property. The provider treats
that omission as the now-unconditional archive predicate only for semantic
unique keys and `caseInsensitiveUnique` indexes. Omission on relation and
folded-access indexes remains `null`; an explicit unsupported predicate fails
closed. This keeps old release artifacts verifiable after the database
replacement without silently widening predicate authority.

## Decided target and explicit deferrals

- **Archive scope now:** unconditional `archived_at IS NULL` for every current
  business key.
- **Eventual archive scope:** a declared property on a first-class key object,
  introduced as a canonical-language change when a permanently reserved key is
  actually required. Document and serial numbers are the motivating future
  case, not a current one.
- **Legal entity:** the already-decided composed target retains the optional
  `legal_entity_id` equality column. This packet emits no such column because
  current packages do not yet carry G3-P1b's family classification in compiled
  storage. Entity-owned families add it after that declaration lands; there is
  no default classification.
- **Restore diagnostic:** restore is closed and atomic today, but its code is
  the existing typed `MODULE_UNIQUE_VIOLATION`, not plan §5.12's eventual
  distinct restore-conflict spelling. Adding that canonical/runtime contract
  crosses KERNEL-owned paths and remains paired with the declared-key language
  event.
- **Archived-inclusive resolution:** current resolvers remain active-only.
  Archived records are addressed by stable record ID with `includeArchived`;
  no archived-inclusive business-key resolver is admitted. If one is added,
  multiple archived rows sharing a key must return `ambiguous`, never an
  arbitrary exact match.

## Test it yourself

Prerequisite: Docker is running. From the packet checkout:

```bash
node --import tsx --test \
  --test-name-pattern='Location reuses an archived code' \
  test/postgres/location-runtime.test.ts
```

Expected: 1/1 passes in under 10 minutes. The test creates `WH-A`, proves an
active case-fold duplicate is rejected, archives the original, creates `wh-a`
successfully, and proves a colliding restore fails closed without changing
either persisted row.

To inspect both physical predicates and the verifier control:

```bash
node --import tsx --test \
  --test-name-pattern='compiled module materialization is isolated' \
  test/postgres/module-storage-transition.test.ts
```

Expected: the parent and eight nested tests pass. The uniqueness subtest reads
both PostgreSQL index definitions; the READY-to-swap subtest accepts the
partial-index catalog, drops one managed index, observes drift, recreates it,
and returns to green.
