# G1-P6 — Empty fail-closed Semantic Query and Operation gateways

Status: active
Tier: Critical

## Goal and scope

Add the sole `SemanticQueryGateway` and `SemanticOperationGateway` runtime
authorities plus their authenticated API adapters. Both consume the accepted
Freeze D `RequestRuntimeView` without modification, consult current policy at
the boundary, resolve only the request-pinned query/operation catalogs, and
fail closed because the bootstrap release registers no business query or
operation.

Owned paths:

- `packages/runtime/src/semantic-query-gateway.ts`
- `packages/runtime/src/semantic-operation-gateway.ts`
- `packages/runtime/src/semantic-gateway-api-adapters.ts`
- `test/integration/semantic-gateways.test.ts`
- `docs/execution/packets/G1-P6.md`
- `docs/execution/ledger.md`
- `docs/execution/doctrine-coverage.md`

Out of scope: real Q0-Q3 or O0-O3 semantics and bindings, domain handlers,
read models, storage/provider access, compiler or canonical-model changes,
Freeze D changes, SurfaceRuntime or `apps/web`, agent runtime/tool
implementation, migrations, manifests, root `package.json`, and
`pnpm-lock.yaml`. Any need for a dependency or shared-contract change is a
stop-and-bridge request.

Runnable exit: the public adapters accept authenticated request input and a
canonical query/operation ID, obtain one issued pinned view, consult the live
policy seam, and reject the empty catalog with a typed no-such-registered
error. No dispatcher, registry, handler, transaction, provider, database,
table, SQL, source, filesystem, shell, arbitrary HTTP, or ambient-state
capability is present.

## Binding behavior

1. Each API adapter composes only the accepted
   `AuthenticatedRequestRuntimeEntryAdapter` and its corresponding semantic
   gateway. Callers cannot supply tenant, environment, release, policy,
   physical handler, table, transaction, or source authority.
2. Each gateway accepts only an issued `RequestRuntimeView`, reads only the
   matching `view.projections.query` or `view.projections.operation` catalog,
   and validates the pinned catalog envelope needed for safe empty resolution.
   It has no loader, catalog override, process-global registry, default, or
   ambient fallback.
3. Current policy is consulted with explicit trusted/pinned view identity and
   the requested canonical ID even when the catalog is empty. Policy denial
   and malformed policy decisions fail closed; policy never creates a
   contract or dispatch binding.
4. A missing ID raises a stable typed `NO_SUCH_REGISTERED_QUERY` or
   `NO_SUCH_REGISTERED_OPERATION` error carrying only canonical request and
   pinned release evidence. No side effect occurs.
5. Top-level request envelopes are closed and versioned. They expose only the
   semantic ID and immutable typed input/arguments needed by the future
   gateway seam; raw database, SQL, table, storage, source, handler, route,
   transaction, shell, filesystem, arbitrary HTTP, or generic patch
   affordances are absent.
6. G1-P6 adds no business binding or alternate registry. Later G2 packets may
   add registered read models/domain handlers behind these authorities but may
   not widen the caller-facing bypass surface.

## Review charter

Gates must be green on one frozen candidate.

In scope: an unregistered query/operation ID fails closed with a typed error
and no side effect; there is no bypass to tables, SQL, physical handlers, or
ambient state in the owned source; each gateway reads its catalog only from
the issued pinned `RequestRuntimeView`; current policy is consulted at the
boundary; and the agent-tool-prohibition seam exposes no raw database, SQL,
source, or administrative affordance.

Threat model: accidental bypass, fallthrough, catalog substitution, or
ambient access by honest code. Active obfuscation and hostile input are out of
scope.

Out of scope: real domain query/operation semantics and dispatch (G2), surface
rendering (G1-P7), agent runtime/tool schemas, compiler/canonical changes,
provider/storage implementation, and unrelated hardening. No debate expands
the packet.

Decisive questions:

- Does every well-formed invocation against the empty pinned catalog end in
  the matching typed no-such-registered error without a side effect?
- Is the only catalog authority the exact issued view passed to the gateway,
  with no caller override, reload, default, global, or process fallback?
- Is current policy actually called with explicit view/request evidence before
  resolution can lead anywhere?
- Do source and public request shapes expose no database, SQL, table, storage,
  handler, source, transaction, shell, filesystem, arbitrary-HTTP, or generic
  write capability?

Critical tier requires a fresh naive Codex `gpt-5.6-sol` xhigh review to PASS,
then Fable max on the identical unchanged SHA. Any fix creates a new SHA and a
fresh review. At most two `REVISE` rounds are permitted.

  authorities. Each constructor accepts only the accepted
  `CurrentPolicyGateway`; each invocation first asserts an issued Freeze D
  view, validates a closed immutable JSON request envelope, consults current
  policy, validates only its matching pinned projection payload, and
  terminates with a typed fail-closed error. No success, binding, dispatch,
  or effect port exists.

  `northstar.runtime:permission.semantic-query-boundary` and
