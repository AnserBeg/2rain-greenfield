# G1-P2 — Deterministic compiler output protocol (Freeze B)

Status: active
Tier: Critical
Base: `d9046f496e58f5b2d5efba13a87b305c8502d80c`

## Goal and freeze semantics

Compile normalized v0-experimental application packages through one hermetic,
deterministic, fail-closed pipeline into a complete Merkle release bundle and a
factual release diff. Freeze B freezes only the output protocol: manifest and
descriptor envelopes, canonical serialization and domain-separated hashes,
the namespaced/versioned multi-instance projection protocol, compiler
diagnostic shape/order, and release-diff envelope.

Freeze B is provisional until the empty bootstrap, minimal vertical revision
one, exact optional-field/form revision two, identical-recompile, and
partial-lowering/no-root fixtures all pass. Compiler IR, cache layout, chunk
boundaries, physical partitioning, presentation, risk policy, and payload
schemas without real consumers remain unfrozen.

## Out of scope

- Rich per-family lowering, real SQL/DDL, storage execution, runtime query or
  operation behavior, surface presentation, and policy decisions.
- Incremental/memoized/parallel compilation implementation; v1 recomputes the
  complete model while freezing the node contract and cold/cached equivalence
  invariant.
- Coordinator persistence, CAS registration, worker/process orchestration,
  activation, approval, renderer implementation, rollback, and request pinning.
- Adversarial inputs and sandbox implementation. A sandbox is a tracked release
  gate before tenant- or AI-authored definitions become untrusted input.
- Any runtime overlay, patch lineage, parent-chain evaluation, or seconds-fast
  storage usability claim.

## Review charter

- Gates must be green at every reviewed candidate.
- Threat model: accidental nondeterminism, contract drift, and completeness
  gaps introduced by honest authors or AI writers.
- In scope: the binding Freeze B design; deterministic pipeline/diagnostics;
  manifest, projection, chunk, hash, diff, node, capability, compatibility,
  policy-reference and attestation envelopes; hermetic/process-serializable
  boundary; all five required fixture cases; completeness/invariant checks;
  and the deterministic battery.
- Out of scope: adversarial input/evasion, sandbox implementation, rich family
  breadth, incremental implementation, presentation/risk policy, runtime
  behavior, and speculative payload schemas.
- Decisive questions: does every successful output form one complete directly
  resolved snapshot; does any error expose no release root; are semantic and
  layout identity distinct and domain-separated; does the exact optional-field
  revision produce surface-only and storage-transition facts; and can ambient
  process state or prose change canonical output?

## Acceptance criteria

1. The canonical-model comparator is corrected and version-noted before any
   compiler fixture lands; prose never participates in frozen ordering.
2. The explicit pipeline is decode/schema-check, symbol collection, resolution,
   type-check, whole-model validation, typed lowering, post-lowering
   validation, emission, completeness/invariant verification, then
   hierarchical leaf/projection/release hashing.
3. Diagnostics accumulate within a phase, deduplicate, cascade-suppress after
   unresolved/invalid types, stop at a deterministic limit, and never expose
   engine/Zod prose in frozen fields.
4. Release manifests contain multi-instance projection descriptors and chunk
   descriptors with stable logical scope, namespaced family identity, payload
   schema version, semantic digest, artifact root, runtime capability,
   compatibility rules, and a chunking-scheme version.
5. The required semantic, storage-target, exact-pair transition, query,
   operation, surface, policy-reference, agent-discovery, capability, and
   verification projections are complete for admitted fixtures. Shareable
   content contains no tenant/coordinator identity.
6. Compiles are pure and process-serializable. The architecture gate bans
   clock/environment/randomness/filesystem/network/database inputs from
   `packages/compiler`; coordinator failures never become canonical
   diagnostics.
7. Node contracts carry stable node ID, normalized input digest, ordered
   dependency digests, semantic-profile identity, output fingerprint, and
   invalidation rule. Future cached/parallel modes must be bit-identical to a
   cold full compile.
8. Deltas are build inputs only. Every output is a complete directly resolved
   snapshot; runtime overlays and parent-chain evaluation are forbidden.
9. The five fixture cases and deterministic battery pass, including insertion
   permutations, schedule permutations, cwd/locale/TZ/process variation,
   negative diagnostic goldens, golden bytes/hashes, and twice compile.
10. Release diff contains only deterministic factual authorization-surface and
    projection/transition facts; risk and prose remain outside it. Approval
    binding obligations are specified for G1-P4 without creating approval
    authority here.
11. Separate SLO families and a numeric full-compile budget at the effective v0
    maximum envelope are recorded. Bound increases must rerun that budget and
    measurements—not architectural drift—trigger incremental implementation.
12. Every named deferral has one doctrine-coverage row and owner.
