## Goal and scope

This packet supplies the executable half of plan §8.6. It is the pure conformance
suite left after G2-P3a moved generic semantic data binding into SurfaceRuntime.

The suite compiles a deterministic shell package containing all five ratified
archetypes (`home`, `list`, `record`, `task`, `builder`) and every fixed slot. It then:

- validates required/unique slots, strictly increasing slot order, closed status
  roles, seven-item desktop navigation, five-item compact navigation, and a
  deterministic compact projection;
- renders every compiled definition through the real issued-view app server and
  `renderSurfaceRuntime` in a 390×844 Chromium viewport;
- observes the compiled slot count in the produced DOM, exact role tokens, computed
  role-token contrast, five visible navigation targets at least 44×44px, compact shell
  transformation, and keyboard order; and
- reruns the G1 skill-document pin and production-source SurfaceRuntime-only scan,
  including an induced module-specific React screen red.

There is no product-screen or grammar change. No production `apps/web/src` file,
compiler contract, module definition, migration, dependency, release artifact, or
canonical golden changed. The conformance shell derives from the existing compiled
demo shell at test time; its temporary runtime fixtures are written outside the
repository and removed after the journey.

Out of scope remains a sixth archetype, tenant-authored layout/CSS, module-specific
screens, native apps, rich table behavior, and the G7 manual WCAG audit.

## Contract and implementation

The checker consumes compiler surface projections, counts active subjects, and emits
stable rule IDs. A zero-surface package is therefore an explicit `SG001_NO_SURFACES`
failure rather than an empty pass. The compact projection is a deterministic mapping
of active compiled surface IDs and ordered slot names; conformance separately applies
the compact navigation budget and required-slot set.

The accessibility checker uses WCAG 2.x relative luminance with a 4.5:1 normal-text
floor and measures both target dimensions against 44px. Architecture tests exercise
known token pairs and isolated failures. Browser journeys read the actual computed
status colors and actual navigation rectangles from Chromium before applying the same
numeric floors.

The fixture uses the existing registered
`northstar.shell:component.setup_checklist` for every slot. This deliberately tests
generic compiled routing rather than inventing archetype-specific components. The
architecture check observes exact slot vocabulary; the browser independently observes
one registry-rendered component per required slot and no runtime diagnostic.

The existing G1 `SURF001_RUNTIME_BYPASS` scan remains the antibody for bespoke screens.
G2-P4 re-executes it on the real tree and on a temporary
`apps/web/src/modules/party-screen.tsx` containing structural React markup.

The salvage audit admitted no prior component. Its default/icon buttons and tabs are
40px, badge variants are outside the role vocabulary, and the sidebar owns
framework/cookie state. Exact provenance, hashes, gaps, and rollback are in
[`g2-p4-components.md`](../../decisions/salvage/g2-p4-components.md).

## Known limits and what the gates cannot prove

- Automated contrast covers the closed status-role pairs exercised by every fixture;
  it is not an exhaustive pixel audit of gradients, imagery, every future component,
  zoom modes, or user styles.
- Target checks observe the compact navigation controls present in this data-less
  conformance shell. Rich forms and grids remain responsible for the same floor when
  their components land.
- The compiler-produced fixture repeats one existing registered component so the
  suite proves generic routing, slots, and layout without claiming final archetype
  ergonomics or real-module content completeness.
- The source scan observes recognized structural markup/import patterns in production
  files. It cannot prove the absence of arbitrary dynamically generated markup that
  deliberately evades those patterns; that remains a source-review and runtime-policy
  concern.
- Chromium automation is G2 accessibility evidence, not screen-reader testing,
  cognitive/usability research, or the broader manual WCAG audit reserved for G7.
- The suite proves today's deterministic compact transform. A future transform that
  hides/inlines content must keep these journeys and the `SG009` negative current.
