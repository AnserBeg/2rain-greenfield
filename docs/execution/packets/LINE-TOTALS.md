**Claims.**
1. `derivedDecimals` (optional v6): a stored decimal, money or quantity field computed on create, on every update (one locked prior-row read merged with the patch, one UPDATE, written only when its value changes) and on both template line inserts, before validations and write invariants run. Exact add, subtract and multiply, depth at most 4, rounded once, half away from zero, to the target scale (`1.5 x 0.33` stores `0.50`, `-0.125` stores `-0.13`). An absent operand (after `absentAs`) makes it absent. An integer part that does not fit refuses as `MODULE_DERIVED_VALUE_OVERFLOW`, raised after validations pass, never SQLSTATE 22003.
2. The target leaves every writable input (`fields`, `writableFieldIds`); create and update contracts carry `derivedFields`; a caller-sent value refuses as `MODULE_FIELD_UNSUPPORTED`. `assignedFields` is untouched.
3. `createOnlyFields` (optional v6): the field leaves the UPDATE contract, which names it in `createOnlyFieldIds`; an update naming it refuses by name. The editor's save (`editorFieldsToSave`, unit-tested against the compiled contracts) never sends a create-only field on a saved row or a derived value, and still throws "Editor field unavailable" for a missing field without the marker. The render path (the control shown read-only) is wired but not exercised against a declaring release.
4. Money with a stored currency compares against the literal zero only, with an ordered operator; any other bound still refuses. A release using it raises the operation floor even with no derived value.
5. `rollups` (optional v6, `materialize: 'onRead'` only): a header get computes the sum of its LIVE lines in the same statement, in the header's tenant, environment and company and under the request's verified scope (the line entity joins the verified read entities). No lines: typed zero. One absent amount: ABSENT. The total is authorized by ONE dependent-read function that List figures also call (`authorizeDependentRead`, returning its decision): denied, an unexecutable line filter, or any policy narrowing WITHHOLDS it (`withheldFieldIds`) and the header is still answered. The operation read-back omits it.
6. Line create, update, archive and restore on a totalled relation lock the existing line row, then the header `FOR NO KEY UPDATE`, after the company lock and dateTime resolution and before mutation preparation; create and restore count live lines under that lock and refuse line N+1 as `MODULE_LINE_MAXIMUM_EXCEEDED`.
7. Release verification writes small, token-distinct values into the operands of a derived value (one digit and one place, `4.7`, at a scale; a four-digit whole number at scale 0; `1` when that bound would not fit the target); a validation's own witness still wins. It reads derived values back from the create.
8. Compile refusals (`bindLineTotals`): money x money; unit x unit; mixed or mismatched currency bindings and units; a required target; depth over 4; intermediate over 76 digits or scale 36; chaining; a validation watching a derived target; mixed ownership; a stored currency not create-only and required; create-only on a numbered field, a derived target or a total; a total wider than 38 digits; `materialize: 'stored'` (not yet); a template-filled relation whose maximum is under the template bound; a derived value offered as a create value or composition input.

**Rule 17.** (a) Three general blocks: a value computed from its own row's stored inputs; a parent value summing one child field over one declared relation; a field fixed at creation. (b) Unchanged users: rental contracts (days x rate), field-service work orders (hours x rate; parts x price less discount), distribution sales and purchase orders, clinic invoices, quotes, timesheets (a quantity with no currency), TAX s2's evidence total; create-only serves a document currency, a contract type, any field fixed at creation. (c) Narrower on purpose (ADR-0094): sum only, one relation, one rounding mode, no chaining, no division, on-read totals only (stored totals are s3), no Customize member (s2), no first-party adoption (s5).

**Decisions (one line each).**
- The derivation, rounding and absence default ride `derivedFields` itself, so the interpreter reads them from the pinned operation catalog (the ADR names the key; the entry carries the compiled declaration).
- The fixture is the tenant's two Customize patches (record type, line table) with the three keys injected; it compiles with first-party provenance because no tenant path can declare them before s2 (gaps b and c).
- The compile refusal for "a template larger than the maximum" uses the structural bound (100 members plus 100 entered lines), because template content is tenant data, not release content.
- Verification operands are bounded per derivation (an interval bound with every operand at its largest candidate); the dotted form cannot be a substring of sentinel text, which the search-exclusion probe needs (the first choice, `1`, collided).
- The floor rule lives in one helper (`lineTotalsReaderFloors`) read by the compiler invariant, release registration and the runtime view load.
- Rule 21(c): the preceding-binary proof is not built; row added to FIRST-TENANT-OWED.md.
