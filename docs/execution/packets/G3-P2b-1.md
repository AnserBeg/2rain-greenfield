## Goal and boundary

This packet creates physical inventory persistence before any posting path
exists. The binding storage-plane verdict is implemented rather than reopened:

| Plane | Relations |
|---|---|
| Compiled managed module | `legal_entity`, transaction header, transaction line, movement parent plus eight partitions, movement-effect companion, and period lock |
| Platform | tenant calendar and release-recorded posting configuration only |

The movement parent is quantity-only and is partitioned immediately by tenant
business period. Its shape was frozen at `417e2b4`: primary key
`(tenant_id, business_period, environment_id, legal_entity_id, record_id)`,
eight hash leaves, and one globally unique effect-identity companion. Later
work added only derived checks and indexes; it did not change the frozen
columns, key, or partition scheme.

The split boundary remains closed. This packet chooses no stock serializer,
adds no posting or application insert path, adds no reservation contract, and
does not reserve lot, serial, bin, money, cost, value, price, or currency
columns. G3-P2b-2 owns serialization; G3-P3 owns posting; G5-P1 owns
reservations.

## Press extension and desired-state authority

`northstar.storage-target-payload/v3` is the first payload that can declare:

- `createPartition` and `createCompanionTable` constructive elements;
- `createRejectMutationTrigger`, the append-only opposite of the still-banned
  `deleteCapableTrigger`; and
- `addAbiFunctionCheck` for the business-period and base-unit ABIs.

The declaration is the pinned `INVENTORY_FACT_STORAGE_V1` domain contract.
Conformance validates it, storage lowering emits it, and the provider consumes
only generic target metadata. `removePartition`, delete-capable triggers,
truncation, cascades, and object drops remain destructive rejections.

Migration 0015 changes the kernel metadata constraint so persisted transition
receipts can name the new constructive kinds. It never creates, alters, or
drops a `north_star_module` relation. The module materializer remains the sole
desired-state authority for all fourteen compiled relations.

The materializer-only RLS policy needed by compiled entity FKs is emitted only
for legal-entity/fact targets and the fact companion. It is deliberately absent
from unchanged v1 tenant-shared tables, so a provider upgrade cannot turn an
unchanged Catalog or Location payload into false drift.

## Deadline-bound movement-contract remediation

The later Critical review at `17195c51` found two reachable one-way-door gaps.
The prior contract check compared `INVENTORY_CONTRACT_V1` only with itself;
the actual compiled movement entity could diverge. Separately, standalone
Inventory lowering skipped every pinned Item/Location relation when the target
entity was not present, allowing provider preparation without those FKs.

The actual movement entity is now checked against the frozen 16-field
quantity-only shape, including exact types and presence. Unknown fields fail;
monetary names use `INVENTORY_MOVEMENT_MONEY_FORBIDDEN`, a missing or malformed
version uses `INVENTORY_STOCK_DIMENSION_VERSION_REQUIRED`, and other shape
drift uses `INVENTORY_CONTRACT_INVALID`. This also makes a monetary projection
structurally unreachable: the current aggregate language sums one declared
numeric field, and the exact movement shape has `quantityDelta` as its only
decimal source. Storage lowering now emits all five pinned external references
whether or not their targets are present in the package; the generic provider
then fails closed with `ENTITY_TARGET_MISSING` rather than materializing an
unbound fact.
