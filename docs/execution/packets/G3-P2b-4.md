## Scope and defect

The generic module interpreter previously admitted only
`northstar.storage-target-payload/v1` by comparing every persisted version stamp
to one compile-time constant. The compiler had already emitted v2 for
entity-owned targets, and G3-P2b-1 adds v3 for partitioned inventory facts. A
valid non-v1 release therefore failed with
`MODULE_STORAGE_PROJECTION_MISSING` before any semantic operation reached
PostgreSQL.

This is the version-from-artifact defect at a fifth production layer. The fix
does not replace one local constant with a local list. The compiler protocol owns
one frozen `SUPPORTED_STORAGE_TARGET_PAYLOAD_VERSIONS` family, exported through
the compiler package. The interpreter consumes that family and additionally
requires the release reference, projection manifest, and projection payload to
declare the same admitted version. An unknown version still fails closed.

The packet also carries the period-lock privilege correction found by
G3-P2b-1: a generic update changes both `closedThrough` and the optimistic
`revision`, so granting UPDATE on only the first column causes PostgreSQL
`42501`. The correction grants exactly those two columns and does not widen
period-lock mutation authority beyond them.

## Evidence split

Evidence is intentionally split across the integration boundary:

1. **Layer 1, accepted-base independent:** synthetic artifact chains exercise
   the production admission function. Every compiler-owned version is admitted;
   an unknown version and each inconsistent stamp fail with typed diagnostics.
2. **Layer 2, after G3-P2b-1 integrates:** the real compiled v3 Inventory target
   is materialized and a period-lock update executes through the real Semantic
   Operation gateway against ephemeral PostgreSQL. This also observes the v3
   payload rather than merely asserting it.

No unreviewed FIX work is merged merely to make Layer 2 available.

## Executed reds

### The former single-version check rejects v2

With the production validator deliberately left on its former v1 equality, the
synthetic v2 chain reached the validator and printed:

```text
G3-P2b-4 pre-fix red: version=northstar.storage-target-payload/v2 code=MODULE_STORAGE_PROJECTION_MISSING message=pinned release has no supported storage target
```

The unchanged test then failed at `assert.doesNotThrow` for v2. Switching only
the validator to the compiler-owned family made the same test pass, while the
unknown `northstar.storage-target-payload/v999` control continued to require
`MODULE_STORAGE_PROJECTION_MISSING`.

### Pending Layer 2 reds

- The real v3 Inventory operation must fail with the former single-v1 check and
  succeed with family admission.
- Before the materializer grant correction, advancing a period lock must reach
  PostgreSQL and fail with `42501`; after the correction the same gateway call
  must succeed and read back the incremented revision and changed date.
