## Method and scope

The self-contained compiler test instantiates the real Party, Catalog and Location factories
under one valid application namespace, growing the composed package in that order. It does not
import `test/compiler/helpers.ts` or modify any product, domain, compiler, database or app file.

For every point it:

1. normalizes and canonicalizes the complete composed definition before timing;
2. invokes the ordinary compiler five times with no active release and requires the compiler's
   `coldFull` attestation;
3. times only each `compileApplication` call using `process.hrtime.bigint()` in the test
   coordinator and records the median;
4. counts total/searchable fields from the normalized package; and
5. decodes the emitted storage-target projection and counts its physical indexes per entity.

The artifact groups points into appendable runs. A later revision adds another run for the same
N values instead of replacing these points. Shape checks require a non-empty run, strictly
increasing N within each run, all requested dimensions, finite non-negative numeric values,
exact 40-hex SHAs and one physical count for every uniquely listed entity. No exact value,
monotonic cost trend or latency threshold is asserted.

## What this cannot prove

This curve is a composition of three first-party packages, **not a real tenant application**.
It does not measure candidate verification, transition preparation, human approval wait,
activation, read-back or platform exclusion, so it cannot claim an end-to-end `publishPath`
SLO. It also does not measure runtime write amplification from the emitted indexes.

The values are deliberately not stable. KERNEL packet 4c changes language/profile output and
FIX packet 1d changes physical index emission; both can move the numbers immediately. Their
later measurements must append points at their own SHAs so this pre-1d run remains meaningful.
