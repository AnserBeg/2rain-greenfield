## Goal and scope

Cut G3 into named, selectable packets that deliver the inventory-truth alpha in
plan §11.6 without allowing a first movement to post before every irreversible
contract is present. The cut assigns all ten accumulated G3 obligations, fixes
their first-posting deadline classification, establishes the contract-freeze
order, and exposes the query-tier dependency that controls the read half of the
stage.

Owned paths for this cut:

- `docs/execution/packets/G3-P0.md`
- `docs/execution/stage-cut-inputs.md`, only to mark the ten G3 inputs as
  dispositioned here

reopening any accepted ADR or the G3 one-way-doors verdict, implementing
reservations, valuation, G4 purchasing, or expanding availability and counts
beyond plan §11.6. This cut starts no implementation packet and claims neither
a G3 obligation nor the G3 gate complete.

Runnable exit: the accepted product remains byte-identical. The deliverable is
the complete dependency graph below, not an inventory implementation.

## Settled inputs and the two assigned decisions

The following are inputs, not questions:

- Family classification has **no default**. `legal_entity`, `party`,
  `party_role`, `item`, and `location` are `tenantShared`; movements,
  inventory transactions, reservations, and counts are `entityOwned`.
  Undeclared classification fails compilation. “No default” here means no
  *family-classification* default; it does not remove ADR-0015's declared
  default legal-entity master used by a single-entity tenant.
- `northstar.stock-dimension-set/v1` is exactly
  `(legalEntityId, itemId, locationId)`. All three have real required values at
  posting. Their v1 `unspecified` members are structurally unreachable;
  `unspecified` becomes meaningful only for dimensions added by later versions.
- `negativeStock` is `{reject, allowWithFlag, allow}` with default `reject`.
  The check runs inside the posting transaction against serialized state, never
  as preflight. Same-instant tie-breaking is one closed global rule, not a
  tenant dial.
- A balance cache is derived and addable later. A per-stock-identity
  serialization protocol is mandatory at the first posting.

The two open choices have concrete owners and closing points:

| Open choice | Owning packet | Required disposition |
|---|---|---|
| Configuration-dial scope: tenant or legal entity | **G3-P1** | Select and encode one scope before Freeze J. The choice is not a one-way door, but the first release must have one typed, compiler-checked interpretation rather than ambient lookup. |
| Concrete per-stock-identity serialization mechanism | **G3-P2** | Select either a lock point acquired by every posting for each affected stock identity, or serializable execution with a declared bounded retry contract; prove the selected mechanism with concurrent negative-stock and transfer controls before Freeze K. “Re-read locked rows” and preflight are inadmissible. |

Neither choice waits on an unnamed design exercise. G3-P1 and G3-P2 own the
decision, its executable contract, and its recorded alternatives.

## Query-tier dependency — the controlling sequence

G3 does not own aggregation semantics or SQL lowering:

```text
KERNEL
  4a: v3 version/profile dispatch
    -> 4b: v3 families, aggregate node, typed parameters, signed sub-unit decimals
      -> 4c: packages adopt v3; artifact event
        -> Q1-P3b: lower the ADR-0022 scalar SUM through the real gateway
                     with typed stock/time parameters and provider evidence

G3 deadline spine (does not need aggregate lowering)
  1d unique emitter -> G3-P1 -> G3-P2 -> G3-P3 -> G3-P4

Read convergence
  Q1-P3b + G3-P3 -> G3-P5 -> (G3-P6 || G3-P7) -> G3-P8
```

`onHand` is exactly:

```text
SUM(posted inventory_movement.quantity_delta)
  scoped by tenant, environment,
  legalEntityId, itemId, locationId,
  effectiveAt <= atTime,
  archive and policy predicates
```

It returns ADR-0022's scalar result through the registered query path. G3-P5
may not hand-author SQL in an inventory service, represent the scalar as a fake
Freeze-I list row, omit the future recorded-time horizon, or compute from a
mutable balance field. Q1-P3b is therefore a hard predecessor of G3-P5, not of
the movement-write packets.

## Three-lane parallelization map

The current lane state is respected rather than overwritten:

```text
KERNEL: 4a -> 4b -> 4c ---------------------------> Q1-P3b --------┐
                              \                                      │
                               \ serialized artifact window          │
                                -> 1d unique emitter                  │
                                                                    v
FIX:    G3-P0 --STOP-- [new user selection] -> P1 -> P2 -> P3 -> P4 -> P5
                                                                         |\
                                                                         | +-> P7
                                                                         +---> P6
                                                                               \ /
                                                                                P8

DEPLOY: 1b -> release migration ownership -> available for P2's serial window
```

Rules for the map:

1. G3-P0 ends at this document checkpoint. It grants no implementation lease.
2. `4a/4b/4c` and `1d` are artifact-moving work and integrate serially. G3-P1
   consumes their final shapes; it does not overlap their canonical/domain/
   release-root changes.
3. Once `4c` and `1d` are accepted and the orchestrator recuts paths, G3-P1 may
   run while KERNEL implements Q1-P3b because it needs no aggregate lowering.
   If its exact lease unexpectedly needs a KERNEL-held file, it serializes; the
   stage cut is not an implicit bridge.
4. G3-P2 waits for G3-P1 and for DEPLOY `1b` to release migrations. G3-P3 and
   G3-P4 then remain on the deadline/write spine and may also finish before
   Q1-P3b.
5. G3-P5 cannot start until Q1-P3b is accepted. G3-P6 and G3-P7 may author in
   parallel only after G3-P5 and G3-P4 are accepted and their final path leases
   are disjoint. G3-P8 is serial convergence.
6. Integration is one packet at a time. Every product-code main advance forces
   the later lane to merge and re-run the full matrix; a docs-only orchestrator
   advance uses the narrow `lanes.md` exception.
