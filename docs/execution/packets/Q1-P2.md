## Outcome and safety boundary

Q1-P2 checks the first Q1 SQL lowering without putting a model in any runtime
path:

- a model-authored, committed parity corpus is replayed by deterministic code;
- the canonical predicate kernel and real PostgreSQL execution are independent
  judges and must agree;
- a deterministic dispatch tripwire ratchets recognizable predicate-kind
  dispatch; and
- a model-authored scenario artifact lets a human review behavior while the
  canonical kernel judges its expected outcomes.

The replay performs no model call. The artifacts say `runtimeUse: forbidden`,
CI reads only checked-in JSON, and the PostgreSQL test replaces `fetch` with a
throwing function throughout replay. No production runtime imports any Q1-P2
artifact or checker.

The corpus found no divergence. Therefore this packet remains Behavioral and
does not change `predicate-kernel.ts`, `predicate-lowering.ts`, any provider,
domain package, or application.

## L2 — committed differential corpus

The committed artifact is
`test/fixtures/q1/predicate-parity-corpus.v1.json`: 18 predicates over 15 rows.
The test package adds optional binary-text, Unicode-case-insensitive text, and
exact-decimal fields to a cloned Party definition, compiles it through the
unchanged production press, materializes it in ephemeral PostgreSQL, creates
the rows through the Semantic Operation gateway, and invokes every predicate
through the Semantic Query gateway.

The independent IR side calls `inspectPredicateForExecution` and owns a pure
present-value comparator:

- binary and C-collated folded text compare UTF-8 byte order;
- folded text first calls the canonical `unicodeCaseFold`; and
- exact decimals compare signed, scale-aligned `BigInt` magnitudes, never
  JavaScript `Number`.

The database side uses the compiled filter plan and production interpreter,
including the database-owned `nsm_unicode_case_fold_v1`. Two complete replays
produced:

```text
Q1-P2 corpus cases=18 rows=15 ir=540 postgres_scans=36 axes=absentValues,exactDecimalOrdering,unicodeCaseFold raw_absent=false total_absent=true model_fetches=0
```

The `postgres_scans` receipt is read from PostgreSQL's
`pg_stat_user_tables.seq_scan + idx_scan` counters after forcing the runtime
backend to flush its statistics. Each of the 36 gateway verdicts must contribute
an observed source-table scan, so fewer than 36 fails. This is a database
observation rather than a counter incremented before a provider call.

The always-on raw-SQL canary is deliberately not totalized. For
`NOT(optional_decimal < 0)`, raw PostgreSQL excludes the absent row while the
kernel and production lowering include it (`raw_absent=false`,
`total_absent=true`). That observed disagreement proves the PostgreSQL oracle
is not merely another rendering of the IR answer.

### Per-axis coverage

| Axis | Status | Executed coverage |
|---|---|---|
| Absent values versus SQL three-valued logic | Covered | All four admitted comparisons, `not`, `all`, and `any`; optional binary text plus the decimal totalization canary. |
| Exact-decimal ordering versus `numeric` | Covered | `-10`, `-3`, `9`, `10`, `0.1`, and a 19-digit value across equality and ordering. Exact-decimal comparisons are admitted today. F6 decimal arithmetic is not admitted and is not claimed by this corpus. |
| Unicode case-fold parity | Covered | German sharp-s expansion, Kelvin sign, dotted I, ffi ligature, final sigma, and C-collated folded ordering against the protected database function. |

This is finite adversarial coverage, not an exhaustive proof over all Unicode
or decimal values.

### Deterministic, offline replay

The IR verdict matrix has a pinned receipt and replays inside a Linux network
namespace with no network interface:

```text
Q1-P2 offline corpus receipt cases=18 rows=15 sha256=fb68943504912eead0e68bb486fba0a6cd86e3fef43d3093825be05f18dca3a8
```

The PostgreSQL half necessarily uses loopback to its ephemeral database, but
its model/network entry point is blocked and observed at zero. The offline
receipt proves model generation is not needed to replay the committed cases;
the PostgreSQL suite separately proves parity against the database.

## L3 — dispatch tripwire

`packages/dev-tooling/src/predicate-dispatch-tripwire/index.ts` contains a
model-authored recognition inventory and a deterministic checker. It records
the exact predicate-kind literal sequence in every current production file
that contains at least three distinct predicate node kinds. An unregistered
dispatch, a changed signature, or a missing inventoried file fails.

This specifically catches the quarry failure shape: a second evaluator switch
inside `runtime-metric-service.ts`. The permanent canary also verifies the
legitimate canonical evaluator remains accepted and zero production input
fails rather than passing vacuously.

The tripwire is explicitly a proxy. It can miss a fork expressed through
imported/computed constants, a dispatcher recognizing fewer than three node
kinds, or a semantic fork inserted without changing the inventoried literal
sequence. It can also flag a legitimate structural visitor. Execution
receipts and the differential remain the semantic evidence; the tripwire only
raises review pressure where recognizable dispatch appears.

## L4 — scenarios as specification

`test/fixtures/q1/predicate-scenarios.v1.json` contains five GIVEN/WHEN/THEN
scenarios for absence, Unicode folding, and exact-decimal behavior. The
artifact carries the human-review subject (`behavior-not-implementation`),
while CI resolves its referenced corpus case and row and requires the
deterministic kernel result to equal the authored outcome:

```text
Q1-P2 scenarios=5 approval=behavior-not-implementation deterministic=kernel
```

This is an internal prototype. It is not the G6 tenant-facing L6 workflow.

## Known limits and what the gates cannot prove

- The corpus is deterministic and adversarial but finite. It cannot prove all
  Unicode scalar sequences or all precision/scale combinations.
- Exact-decimal arithmetic remains unreachable because F6 is not admitted;
  exact-decimal comparison ordering is reachable and covered.
- The dispatch tripwire is a syntax proxy with the false-negative and
  false-positive limits stated above; it is not an evaluator-uniqueness proof.
- The corpus uses test-authored optional fields in an otherwise ordinary Party
  package. It proves the generic press/gateway/provider path, not a production
  module's current field inventory.
- Q1-P1's execution-observed cost-class probes remain the planner evidence.
  Q1-P2 checks semantic parity and does not re-characterize planner access.
- This packet has no runtime or UI surface, and no model-generated content is
  promoted to runtime authority.
