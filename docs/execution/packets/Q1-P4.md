## Outcome

Q1-P4 implements ADR-0027's explicit, policy-approved legal-entity read
capability. The contract carries a nonempty authorized set and is bound by
runtime object identity to one issued `RequestRuntimeView`. The Semantic Query
gateway passes it as execution context rather than accepting it as a query
argument. The generic PostgreSQL interpreter dispatches only from
`StorageEntityTarget.legalEntity`, proves every selected UUID exists in the
tenant-visible legal-entity master, and only then constructs business SQL with
mandatory source and joined-alias predicates.

Tenant and environment remain ambient forced-RLS axes. Legal entity remains an
explicit business scope: this packet adds no GUC, trusted session function, RLS
predicate, or third identity axis. It imports no Inventory family map and does
not inspect module, entity, or query names.

This packet does not implement `onHand`; G3-P5 is its first consumer and must
require exactly one member. The generic capability intentionally admits a set
so ADR-0015's authorized consolidated reporting remains representable. Missing
scope never means all.

## Fail-closed sequence

For every query execution the provider:

1. loads and content-verifies the request-pinned storage target;
2. verifies its projection/payload versions and provider ABI shape;
3. builds source and authorized relation metadata without constructing SQL;
4. detects every source or joined alias carrying the compiler-owned
   `legalEntity` descriptor;
5. requires an issued capability bound to the exact request/view;
6. checks every selected member against the one compiled legal-entity master
   while tenant/environment RLS is forced; and
7. only then lowers the business statement with
   `legal_entity_id = ANY($n::uuid[])` for the primary source and every
   entity-owned joined alias.

Omission produces `MODULE_LEGAL_ENTITY_READ_SCOPE_REQUIRED`; a copied or
cross-view capability produces `MODULE_LEGAL_ENTITY_READ_SCOPE_INVALID`; and an
issued UUID absent from the tenant-visible master produces
`MODULE_LEGAL_ENTITY_READ_SCOPE_NOT_FOUND`. None becomes SQL `NULL`, no rows, or
aggregate zero.

## Read-path completeness

| Consumer | Enforcement |
| --- | --- |
| `get` | `loadScopedRawRecord` appends the mandatory source predicate. |
| ordinary `list` | `listRecords` appends the mandatory source predicate before paging. |
| shared List | source predicate applies to count and page; every entity-owned relation alias is restricted in its `LEFT JOIN ... ON` condition. |
| `search` | `matchRecords` appends scope before the folded match. |
| `resolve` | both identifier and advisory `exactFoldedMatches` calls append scope. |
| Q1 aggregate | scope precedes compiled and policy filters and therefore precedes `SUM`/`COALESCE`. |
| saved-filter fallback | non-saved-filter record and aggregate queries forward the exact execution request, including the capability, to the generic interpreter. |

`PostgresSavedFilterExecutor` cannot directly reach an entity-owned compiled
source: the only query IDs it owns execute against
`platform.saved_master_filters`, outside `north_star_module`. Every other query
uses the exact fallback request. The architecture control binds both facts.

## Behavior change owned here

Inventory declares Q0 get/list/search/resolve queries for
`inventory_transaction`, `inventory_transaction_line`,
`inventory_period_lock`, and `inventory_movement`. Because all four compiled
targets carry `legalEntity`, they move from tenant-wide reads to
scope-required reads. Inventory is not mounted in the accepted composed
application, so this is not user-visible today, but it is a real semantics
change rather than a test accommodation. No existing tenant-wide assertion was
relaxed.

The Inventory `legal_entity` master is `tenantShared`. Its existing Q0 List
continues to execute without scope; the PostgreSQL control observes both
tenant-visible entities. The synthetic non-Inventory control proves the same
dispatch applies to an unrelated entity-owned target, while an unrelated
tenant-shared target receives no requirement.

## Authorization posture and limits

`AllowAllLocalPolicy` and `VerificationAllowPolicy` still allow every entity.
This packet therefore enforces selected-entity correctness, capability
integrity, and tenant membership, but not a tenant's restrictive per-entity
entitlements. The identity/policy kernel in plan row 7 remains the owner of real
entity restriction. The packet and ADR deliberately do not imply otherwise.

No canonical spelling is authorized for per-query scope opt-in/opt-out, a
returned legal-entity system field, grouping by entity, or a predicate reference
to the compiler-owned column. Those remain future whole-language version events.
