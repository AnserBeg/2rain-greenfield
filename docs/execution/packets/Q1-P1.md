# Q1-P1 — Single-entity query filters lowered to PostgreSQL

Status: evidence_ready
Tier: Critical
Base: `37485ef4d687389ade4d3eb2464a6ad237250998`
Branch: `packet/q1-p1`

## Outcome

Q1-P1 opens the Semantic Query gateway to compiled Q1 single-entity filters. The compiler
emits a digest-bound, versioned PostgreSQL row-lowering plan; the gateway validates it through
the one predicate-kernel entry point; and the provider conjoins it with archive and RLS-owned
tenant/environment restrictions before executing any query path. Atomic comparisons implement
ADR-0021's total false-on-absence semantics before `not`, `all`, or `any` composition.

This is deliberately not the rest of Q1. It adds no traversal, joins, grouping, aggregation,
reports, exports, operation preconditions, module definitions, or UI-authored filter surface.

## Kernel hardening resolved before admission

The two Q1-P0 confirm observations were closed before a runtime caller could use evaluation
mode:

- evaluation parses its root at depth 1, the same origin used by normalization;
- an untyped `bindingPosition` must be an own property of the closed position-profile table.

Both focused tests were first run against the old implementation. The maximum-depth tree was
accepted (`actual evaluated`, `expected rejected`), and inherited `toString` was also accepted
as a binding-position key (`actual evaluated`, `expected rejected`). Each produced an
independent `ERR_ASSERTION`; both now return typed kernel rejection receipts.

## Versioned lowering table

The compiler-owned table is closed and ordered. Its plan version is
`northstar.predicate-lowering-plan/postgres-row-v1`, and every plan cites position profile
`northstar.predicate-position-profile/v1` plus the SHA-256 canonical predicate digest.

| Row ID | Admission | Cost class | Executed provider probe |
| --- | --- | --- | --- |
| `northstar.predicate-lowering/folded-equality-v1` | atomic `equals` on a Unicode-folded field with a declared folded index | `indexedFoldedEquality` | `Q1-P1/indexed-folded-equality` |
| `northstar.predicate-lowering/tenant-scan-comparison-v1` | every other current comparison after canonical type/locality validation | `tenantBoundedScan` | `Q1-P1/tenant-bounded-scan` |

Boolean literals and `not`/`all`/`any` preserve structure. A compound root is conservatively
`tenantBoundedScan`; it does not inherit an indexed claim merely because each child is an
indexed equality. `indexedEquality` and `indexedPrefixRange` remain named ADR-0012 cost classes
but have no admitted row here: the current predicate vocabulary has neither a raw indexed
identity-field reference nor a prefix operator. Unknown nodes and the unversioned F3 spellings
`greaterThanOrEqual` / `lessThanOrEqual` fail at the canonical compile boundary.

Q0 output is unchanged and carries no lowering plan. A Q1 catalog entry must carry one, while a
Q0 entry carrying one is malformed. The gateway checks exact plan shape, depth, row/cost
pairing, predicate digest, and structural equality between the source predicate and plan before
the provider can run. A deliberately mismatched policy plan is rejected with
`MalformedQueryPolicyNarrowingError`, with provider execution count zero.

## Total SQL semantics and query-path coverage

Each atomic comparison lowers as the sargable equivalent ADR-0021 explicitly permits:

```sql
(field IS NOT NULL AND field OP parameter)
```

This expression is always Boolean for a valid stored scalar and is composed before any
`NOT`/`AND`/`OR`. The first implementation used the illustrative
`COALESCE(field OP parameter, FALSE)`. Its real planner probe returned exact folded-index
`idx_scan delta=0`; PostgreSQL did not use the promised access path. Replacing it with the
equivalent `IS NOT NULL AND comparison` form restored exact `idx_scan delta=1`. That observed
failure is why the production form is not the superficially shorter one.

The same filter-plan array is appended in every provider query branch: get, ordinary list,
shared List count and page, search, and both resolve-match paths. Shared List still reuses one
predicate/value construction for both count and page, so Q1 does not enlarge G2-P5a's already
recorded two-statement coverage race.

The permanent minimal differential executes every current predicate node and operator
(`true`, `false`, `equals`, `notEquals`, `lessThan`, `greaterThan`, `not`, `all`, `any`) over
present and absent values. It observes both binary text and Unicode-folded text comparison.
For the decisive absent case:

```text
raw SQL NOT(absent < 'm'): absent row excluded
kernel / total SQL:        absent row included
```

The executed IDs make the disagreement concrete: raw SQL returned records `...0003` and
`...0004`, while the total kernel/provider result additionally returned absent record
`...0001`.

## Policy-predicate seam and mandatory conjunctions

`QueryPolicyNarrowingGateway` may contribute only another canonical predicate plus its
digest-bound lowering plan. The Semantic Query gateway validates that contribution and appends
its plan to the compiled filter-plan array; it cannot replace the query filter. The provider
renders all plans as parenthesized `AND` terms after its archive predicate. PostgreSQL RLS
still owns tenant and environment narrowing.

The real probe creates two same-scope active rows selected by the compiled query, contributes a
policy predicate that admits only one, observes the result narrow from two IDs to one, and
observes one row removed in the executed indexed plan. A same-name archived row, a different
tenant row, and a same-tenant/different-environment row prove the compiled filter does not erase
archive or RLS restrictions.

Round-1 review found the one other provider query executor silently discarded this same plan
array: `PostgresSavedFilterExecutor` implements bespoke SQL and contained no filter-plan
handling. It now refuses every non-empty plan with typed
`SAVED_FILTER_QUERY_INADMISSIBLE` at `$.filterPlans`. It does not lower into that bespoke SQL;
current-plan row 1c owns the prior ADR-0011 decision about whether that executor should exist.
The focused real-gateway control first created and positively listed one saved filter, then
supplied a valid constant-false policy contribution through `SemanticQueryGateway`. Before the
guard, the query returned normally and the test failed `Missing expected rejection.` With the
guard, the identical path fails closed before opening a provider transaction.

## Precondition locality and Q1-P2 obligations

This change does **not** make the precondition field-locality defect reachable. Only
`SemanticQueryGateway` accepts Q1 filter plans. `SemanticOperationGateway` still uses the
literal-true fence, and provider operation/read-back calls pass no query plans. Q1 must close
field locality before widening operation preconditions.

Q1-P2 is now owed as the paired evidence packet named by the queue:

1. L2's adversarial scalar, absence, error, version-skew, and stale-release differential
   corpus, with the differential—not an LLM—judging generated cases;
2. L3's dispatch tripwire over the new SQL target; and
3. L4's scenarios-as-specification corpus.

It must include broader numeric, money, quantity, temporal, enum, Unicode, and boundary-value
coverage. Q1-P1's differential is intentionally the required minimal structural corpus, not a
claim that the later adversarial corpus already exists.

## Known limits and what the gates cannot prove

- No production module declares a Q1 query yet, so the composed application's releases and UI
  remain Q0. The working surface for this packet is the real gateway/provider test, not a
  browser control.
- The only admitted indexed class is folded equality. Raw indexed equality and prefix range
  await canonical field/predicate shapes that can express them without inference.
- The policy seam proves in-SQL conjunction but supplies no real policy language or row-7
  policy kernel. The current product policy remains allow-all.
- The full cross-target scalar corpus is Q1-P2. This packet permanently covers all current
  structural/operator forms and both text comparison modes, plus canonical/provider type
  checks, but does not claim adversarial coverage for every scalar boundary.
- PostgreSQL plans are cost-based. The execution fixture controls population and statistics and
  asserts exact names/counters; it cannot promise the same physical plan for every future data
  distribution. The cost class is the reviewed contract, not a global latency SLO.
- Count and page remain two SQL statements. The filter is identical in both; Q1 neither fixes
  nor worsens the pre-existing G2-P5a coverage race.
- The saved-filter executor explicitly refuses policy narrowing rather than silently ignoring
  it. It remains bespoke SQL pending current-plan row 1c. The structural prevention—a query
  executor contract in which a non-empty plan cannot be discarded without either compilation
  failure or an explicit typed refusal—is named follow-on work for current-plan row 1e,
  **Consolidate the press guards**. A third executor must not reproduce this silent hole.
- No canonical authored bytes or checked-in Q0 release roots are expected to move because no
  current production definition carries a Q1 query. The final gates verify that expectation.
