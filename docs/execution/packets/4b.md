# 4b — v3 query shapes and reserved D2 family

Status: implementation evidence ready; frozen-candidate matrix and Critical review pending

Tier: Critical

Lane: KERNEL

Base: `d9a21ae`

## Outcome

The v3 reader now has a version-exclusive canonical shape rather than sharing one flat strict
object with v0/v1/v2. No checked-in package adopts v3. The adopted v2 parser and types remain
closed, every v0/v1/v2 normalized byte remains unchanged, and every pinned golden, release root,
and compiled web release is byte-identical to the packet base.

This packet takes the prompt's explicit safe boundary: it lands the version-aware schema mechanism,
all seven inventory-blocking Q1 items from ADR-0022, and D2's reserved collection shape. The later
orchestrator sequencing ruling moved capability disclosure and formula/rule to the future language
bumps serving their actual consumers rather than holding inventory-blocking v3 adoption for unused
families. D2's deadline remains closed because its top-level shape is already reserved.

## Version-aware schema mechanism

Three mechanisms were considered:

1. A flat strict shape with optional v3 collections plus a refinement. This can keep omitted fields
   out of v2 bytes, but it widens the parser's physical key set and relies on a later semantic check
   to stop v2 from carrying v3 content.
2. One flat shape assembled conditionally after parsing. This moves version dispatch outside the
   schema, makes public types overly broad, and leaves the closed-set guarantee split between two
   authorities.
3. Separate strict legacy and v3 top-level schemas, selected by a discriminated union on
   `languageVersion`, while sharing unchanged nested definitions where their vocabulary is equal.

The implementation chooses option 3. A legacy object physically has no v3 family key or aggregate
branch. The v3 object requires its own closed shape. This makes the two decisive constraints local
to schema parsing: v2 bytes do not gain defaulted keys, and v2 content cannot smuggle in a v3-only
collection.

The adopted `AuthoredApplicationPackageSchema`, `NormalizedApplicationPackageSchema`, and
`parseAuthoredApplicationPackageJson` remain v0/v1/v2 contracts. Explicit `Versioned*` schemas and
`parseVersionedAuthoredApplicationPackageJson` expose v3 without lying behind a v2 TypeScript
return type. The compiler decodes canonical normalized bytes through the new strict
`parseNormalizedApplicationPackageJson`; it no longer reparses normalized bytes as authored input.
That distinction became load-bearing once normalization derived aggregate input and result
metadata that an author is forbidden to assert.

## The seven Q1 items

The v3 query family now defines:

1. `queryType: "aggregate"`, tier `q1`, `maximumResultCount: 1`, exactly one singular
   `queryAggregateSelection`, stable `selectionId`, operator `sum`, and one source-field reference.
   The branch has no ordinary `selections` and no `groupBy` spelling.
2. At most 64 ordered `queryParameterDefinition` nodes. A v3
   `queryParameterReference` is an alternative comparison operand and is scoped to its declaring
   aggregate query.
3. Normalization-time rejection for a non-local, optional, non-exact-numeric source; unused,
   unresolved, or inconsistently typed parameters; author-asserted input/result metadata;
   non-scalar/multiple aggregate spellings; grouping; a result count other than one; and operators
   other than `sum`.
4. Compiler-derived aggregate catalog metadata: source field, derived exact result type, derived
   parameter types, exact scalar result contract, filter, permission, and cost-neutral query
   identity. Authored input cannot assert those derived types.
5. `greaterThanOrEqual` and `lessThanOrEqual` in v3 predicates only. The same literal-bearing nodes
   remain schema-invalid at v2, so ADR-0021's parked F3 boundary is preserved.
6. Canonical signed sub-unit exact-decimal, money, and quantity values such as `-0.25` at v3.
   Negative zero and trailing-zero spellings remain non-canonical; v2's scalar grammar is unchanged.
7. Unchanged v0/v1/v2 readers and rejection behavior, observed by normalized-byte and full artifact
   identity rather than inferred from source structure.

Normalization derives parameter type from the field at each comparison site. Reusing one parameter
against incompatible field types produces `CANON_QUERY_PARAMETER_TYPE_MISMATCH`; leaving a declared
parameter unused produces `CANON_QUERY_PARAMETER_UNUSED`. The aggregate source must be required and
must be `exactDecimalFieldType` or `quantityFieldType`; result precision is 38, scale is inherited,
and a quantity preserves its base unit, exactly as ADR-0022 rules.

The existing projection implementation is held by the FIX lane. `compiler.ts` therefore supplies a
bounded v3 adapter: legacy projection builders see only the unchanged row queries, while the query
catalog and semantic-model payloads are decorated from the original v3 normalized definition. The
compatibility view is never hashed as canonical authority. Q1-P3b owns SQL lowering and runtime
execution; no provider or gateway changed here.

## D2 closes its shape window without inventing content

V3 requires an `impactAnalyses` collection and `STRUCTURAL_LIMITS_V0` reserves its family bound.
Its schema is deliberately an empty tuple: no `impactAnalysisDefinition` element spelling exists,
and no reference-graph semantics were guessed before their consumers exist. This is the exact
"reserved and unpopulated" boundary. Row 4d may replace the empty element schema with its ruled
content without adding another top-level family key or moving packages that declare zero entries.

## Explicit safe-boundary deferral to consumer language events

Future consumer-driven language bumps must define:

- the distinct capability-disclosure family, its bounded structural entry, and compiled disclosure
  output while keeping `capabilityRequirements` as fail-closed runtime authority; and
- the ADR-0012 formula/rule family with binding-position profile, phase, purity, target,
  absent/error behavior, and the mandatory reason channel for boolean guard/visibility positions.

Neither family blocks 4c. Capability disclosure is N1-scheduled; formula/rule is G6/N2 and remains
subject to the section 5.12 floor. They ride those consumer language events rather than remaining
unused in every intervening release.

## Known limits and what the gates cannot prove

- No checked-in package adopts v3. That is the isolation claim, not missing evidence; 4c owns the
  artifact event and provider round-trip.
- Capability disclosure and formula/rule are not defined by this candidate. The later sequencing
  ruling assigns them to the language bumps serving their N1 and G6/N2 consumers; they are not 4c
  predecessors.
- D2 reserves only the collection key and bound. It deliberately proves nothing about reference
  graph content, element granularity, or consumers; row 4d owns those semantics.
- The compiler emits v3 aggregate catalog metadata but no SQL. Q1-P3b owns lowering, provider
  execution, policy/archive/tenant conjunctions, result overflow enforcement, and its
  execution-observed cost-class probe.
- Aggregate catalog decoration lives in `compiler.ts` because `projections.ts` is held by the FIX
  lane. It remains derived from the same normalized query and is not a second authored authority.
- The tests prove v2 artifact identity and v3 structural reachability. With no v3 package adopted,
  PostgreSQL and browser suites can prove only that existing v2 consumers were not disturbed.
