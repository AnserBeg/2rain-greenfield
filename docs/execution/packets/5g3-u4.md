## Outcome and boundary

SurfaceRuntime resolves every declared slot into exactly one closed state:
`pending`, `ready`, `empty`, or `failed`. The closed component registry remains
the dispatch authority and now also declares which registered slots own data
resolution. Structural siblings stay `ready` when the surface's one compiled
query binding fails. Data-owning slots render the failure as an inline
`role="alert"` card inside their own slot boundary.

This packet deliberately does not add multiple query bindings. The compiled
surface still carries one `dataSourceQueryId`; each slot resolves independently
against that one binding, as ruled after the packet's vocabulary stop. A future
per-slot query projection, if one is needed, belongs to U5 rather than this
runtime packet.

`empty` and `failed` are mechanically distinct. An exact-zero list result owns
`data-slot-state="empty"`, contains the existing empty-state content, contains
no alert, and leaves no failed slot. A query exception owns
`data-slot-state="failed"`, contains the typed diagnostic alert, and identifies
the existing `blocked` status role. No color literal, token, loading treatment,
client script, compiler shape, or release artifact is added.

## Failure-scope correction

The packet prompt inherited a stale citation and the lane stopped on the
resulting vocabulary gap. Reading the live branch established three distinct
paths:

- `selectSurface` catches an invalid surface manifest before composition and
  correctly returns a page-level diagnostic;
- `renderSurfaceRuntimeWithData` converts a query exception into the shared
  typed data state after a surface has been selected; and
- `renderSelectedSurface` used `recordResolutionFailed` to discard every
  declared record slot and hoist one diagnostic.

Only the last path was removed. Invalid projection, no-active-surface, unknown
surface, and request-view failures remain page-level.

## Existing assertion movement

Before this packet, the archived Party read-back control asserted exactly one
`QUERY_NOT_FOUND` diagnostic and **zero** rendered record slots. That accurately
pinned the all-or-nothing behavior, including its cost: no breadcrumb or other
working sibling survived.

The assertion now requires both data-owning slots (`keyFacts` and `sections`) to
carry inline failed-state `QUERY_NOT_FOUND` cards, while `breadcrumb`,
`titleStatus`, and `commandBar` are present and `ready`. This is a strengthening,
not a relaxation: the exact diagnostic is still required, its placement and
state are now constrained, and three real sibling surfaces must remain usable.

## Controls and negative directions

| Control | Observed fact | Negative direction |
|---|---|---|
| Forced query exception | With JavaScript disabled, `record:keyFacts` renders inline `QUERY_UNAVAILABLE`; breadcrumb, title/status, and command bar render real content | Against the pre-fix `recordResolutionFailed` branch, Playwright observed only the hoisted alert and could not find the failed slot |
| Empty versus failed | An exact-zero list is `empty`, contains “No records yet,” contains no alert, and has no failed slot | Classifying the exact-zero owner as `failed` makes the state and no-alert assertions red |
| Page-level fault | Unknown surface returns HTTP 404 with the page diagnostic `UNKNOWN_SURFACE` and zero slots | Removing or relabelling the unknown-surface branch breaks the exact status/code control |
| Closed state set | Every rendered slot has exactly one value from `pending / ready / empty / failed` | A missing or unknown state attribute fails the browser enumeration |
| Pending is non-visual | A data-grid slot rendered before data binding is `pending` and contains no spinner, skeleton, or loading copy | Adding a default loading treatment breaks the contract control |

The negative directions were executed against temporary mutations and then
restored. Collapsing `empty` into `failed` made the exact empty-slot locator
fail; removing the unknown-surface branch changed the observed HTTP status from
404 to 500; and adding `Loading` to the pending data-grid slot failed the
no-loading assertion with the rendered slot HTML. The forced-query control was
also observed red before the production change, when the runtime returned the
whole-page diagnostic and no failed slot.
