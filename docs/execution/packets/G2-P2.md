### Binding Freeze F candidate

This candidate implements the closed debate verdict without ratifying it:

- canonical language `v1` and normalization profile
  `northstar.normalization/v1` introduce Q0 `search`; v0 remains closed;
- reporting is a new projection family through the sanctioned
  `newFamilyOrPayloadVersion` compatibility path;
- `northstar.storage-transition-envelope/v1` supersedes the provisional
  transition on every current compiler and diff path while `CompilerInput`
  stays hermetic and pairwise through one verified `expectedActiveRelease`;
- elements have stable identities, dependencies, total ordering,
  tenant/environment scope, storage domain/generation, preparation validity,
  coexistence matrices, and independent semantic/data/operational axes;
- physical names use domain-separated SHA-256 and lowercase unpadded base32,
  are explicit and bounded to 63 bytes, and have persisted reverse mappings;
- the exhaustive field-type table, forced-RLS/grant template, composite scope
  keys, restrict-only FKs, record identity, revision, archive, defaults,
  collation, uniqueness, and search/index mappings are compiler output;
- compiler-derived entity conformance requires storage, the Q0/O0 quartets,
  list/record/form roles, agent/reporting, and verification for active parent
  and parent-scoped child entities;
- old-writes-may-reject is blocking, existing-table indexes are deferred,
  `NOT VALID` and validation scans are not pre-approval inert, new-table
  required columns are immediately `NOT NULL` with impact none, and actual
  physical-table writer roots feed typed tightening debt;
- backfill completeness is never load-bearing; generated typed storage,
  promotion, retype, rename-as-add, destructive operations/renderers/DDL, and
  unsupported storage gaps fail stable compiler-owned diagnostics.

ADR-0011 separately freezes the exclusive kernel/managed ownership map,
cross-plane provider ABI, shared locking/starvation discipline, isolated
materializer role, v2 preparation/evidence extension to G1-P4b, pre-CAS
`READY_TO_SWAP` receipt, observational post-swap verification migration need,
materializer-side union-live-root validity, accounted additive closure,
object-level exactly-one verification, content-byte provenance recomputation,
resource governance, and ratification protocol.

### Implementation

- Canonical model: a backward-compatible versioned parser keeps accepted
  `v0-experimental` bytes reproducible and adds an opt-in v1 profile. V1
  represents search, field storage/default/uniqueness/collation/backfill intent,
  restrict-only relation actions, surface roles and renderer rejection, null
  storage class, generated storage, and the promotion capability reserve.
- Compiler protocol: adds reporting, storage target v1, transition envelope
  v1, physical mapping, compatibility, classification, renderer, backfill, and
  tightening-debt v2 types with distinct prior/candidate reader and writer
  attribution, and release-impact coverage.
- Lowering: emits dedicated typed tables, composite tenant/environment keys,
  RLS/grants, infrastructure fields, relations, explicit physical names and
  reverse mappings, reporting lineage, and deterministic transition elements.
- Validation: derives applicability per active entity and rejects missing
  family coverage, unsafe backfills, unsupported storage evolution, collisions
  or incompatible name reuse, destructive operations/renderer forms/DDL, and
  missing/null storage class with stable diagnostics in compiler source.
- Legacy G1 canonical/storage-target inputs forward-adapt into the v1 envelope;
  no current compiler or diff path emits or accepts the provisional payload.
