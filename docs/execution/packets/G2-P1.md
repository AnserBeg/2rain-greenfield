business mutation and its successful `ActionInvocation`,
`BusinessChangeDocument`, domain event, and transactional outbox fact commit
or roll back together. Freeze the reusable trust, attribution, redaction,

## Freeze E contract

Freeze E establishes:

- one issued, immutable actor envelope whose execution principal must match an
  ADR-0004 issued request context; identity resolution is a trusted gateway,
  never operation input;
- structurally distinct `HUMAN`, `AGENT`, `AUTOMATION`, `SERVICE`, and `SYSTEM`
  execution kinds, with separate subject, initiating human, approving human,
  and delegation identities;
- one accepted-mutation API that owns the PostgreSQL transaction and accepts a
  module-agnostic mutation callback; it exposes no standalone successful
  evidence writer;
- one non-accepted evidence API restricted to `DENIED`, `FAILED`, and
  `TIMED_OUT`, with no mutation callback and null change/event/outbox links;
- one immutable correlation set across request, action, invocation, change,
  domain-event, outbox, release, and correlation identities;
- classified evidence values: public/internal values may persist, while
  sensitive/secret inputs become classification plus `REDACTED` markers before
  any provider write;
- `BusinessChangeDocument` old/new `VALUE`, `ABSENT`, and `CLEARED` states,
  with sensitive/secret `VALUE` states retaining only redaction/classification
  markers; and
- a shared `LifecycleService` with only `archive` and `restore`, both dispatched
  through a `SemanticOperationGatewayPort`. It owns no persistence capability
  and has no delete operation.

Downstream packets consume this freeze. A later change to these shapes is a
separate serial bridge or explicit reopen, not an incidental module edit.

## Implementation

- `contracts.ts` defines versioned invocation/change/event/outbox evidence and
  classified metadata and field-state redaction. The branded actor issuer in
  the provider composition directly calls the accepted ADR-0004
  `assertTrustedRequestContext`, then resolves attribution through a trusted
  identity gateway and rejects an execution principal that differs from the
  issued context. The request-context assertion is not caller-injectable.
- `lifecycle-service.ts` constructs only canonical archive/restore Semantic
  Operation envelopes. It has no storage dependency, physical handler name, or
  delete/raw-write method.
- `PostgresTrustService` validates and redacts all evidence before starting the
  mutation unit, rechecks the tenant-scoped immutable release inside the
  trusted request transaction, runs the business callback, and writes the four
  trust facts before commit. Any callback, evidence, constraint, or commit
  failure uses the accepted G0 request-transaction rollback/cleanup path.
- Migration 0006 adds tenant/environment-qualified trust tables, exact deferred
  circular fact-set links, release and environment foreign keys, classified
  JSON exposure checks, statement-time evidence timestamps, forced RLS,
  select/insert-only runtime grants, and rejecting update/delete rules.
- Focused provider evidence uses a test-only typed business relation. Its
  deferred foreign key forces failure at commit after an outbox trigger has
  advanced a non-transactional witness sequence, proving that mutation and all
  evidence writes executed before the whole transaction rolled back.
- The PostgreSQL fixture persists one agent mutation with human subject,
  initiating/approving humans, and human-to-agent delegation; standalone
  human/automation/system denial/failure/timeout facts; and one second-tenant
  mutation through the same one-connection runtime pool.

## Testable checkpoint

## Limitations and out of scope

- No outbox dispatcher, delivery attempt, consumer, or exactly-once claim is
  included. The immutable row is only the transactional write-side seam.
- The honest-code threat model covers partial commits, ordinary
  mis-attribution, ordinary hard-delete leakage, classified-value leakage, and
  cross-tenant pool reuse. Hostile/obfuscated payload smuggling and database
  administrator tampering are not claimed.
- The same-database journal is append-only under grants, RLS, constraints, and
  rejecting rules; it is not described as externally tamper-proof.
- The shared lifecycle service only mediates archive/restore. Module-specific
  eligibility, dependent-record conflicts, registered operation bindings,
  policy, confirmation, concurrency, and read-back arrive through the Semantic
  Operation contract in G2-P2 and the walking slices.
- `test/architecture/release-persistence-boundary.test.ts` is outside this
  packet's lease and hard-codes the accepted five-file migration list. Adding
  ordered migration 0006 therefore makes that additional suite red until the
  orchestrator grants and applies a narrow serial bridge. The writer did not
  edit the out-of-lease test.
- The writer environment also mounts `.git` read-only. Product and evidence
  files are complete in the worktree, but the requested candidate cannot be
  frozen here; staging/commit must occur in a Git-writable orchestrator seat,
  followed by the required SHA-scoped database gates and review chain.
- Correction links, recovery orchestration, retention purge, external outbox
  delivery/reconciliation, and production recovery drills remain with their
  ratified later owners.
