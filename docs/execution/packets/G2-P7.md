## The factory finding came first

Before creating a branch or writing code, the original typed-unsupported
hierarchy requirement hit a real **PRESS GENERALITY FAILURE** and a plan-

The exact press constraints are:

- `packages/compiler/src/compiler.ts:716-729` rejects every active requirement
  whose status is not `supported`;
- `packages/compiler/src/compiler.ts:1362-1381` emits facts only for active,
  supported requirements; and
- `packages/compiler/src/protocol.ts:351-356` pins
  `CapabilityFact.supportStatus` to the literal `supported`.

That conflicts with plan §5.5 (`docs/greenfield-north-star-erp-platform-plan.md:
557-561`), which requires preview, planned, unsupported, deprecated, and
internal states to remain explicit. The canonical schema at
`packages/canonical-model/src/schemas.ts:727` also offers only `supported`,
`preview`, `planned`, and `unsupported`; `deprecated` and `internal` are
inexpressible. The generic `compositionSeam` describes package merging, not
hierarchy, and the runtime's unsupported query outcome is not a capability
declaration.

The writer stopped with no branch and no code, reported bucket (a), and waited.
The orchestrator confirmed the finding, recorded a separate declaration-seam
packet on `main`, and ruled that G2-P7 continue with hierarchy completely
descoped. Location therefore declares neither an active nor a retired hierarchy
capability. A retired declaration would compile only by disappearing and would
be a misleading half-measure.

## Relation disposition

The relation-access journey is also descoped, explicitly rather than silently.
The authoritative plan defines Location as `code, name, type, active state`
(`docs/greenfield-north-star-erp-platform-plan.md:807`) and the G2 cut names no
non-hierarchy Location relation. `type` is a field, implemented here as a closed
enum; inventing a Location Type entity or an unrelated child merely to retain a
relation test would exceed the plan. The only natural relation in the ruled
scope was a hierarchy self-relation, so it left with hierarchy.

This materially weakens the second factory data point: Location does not retest
the Party relation path or PR-6's relation index. It remains useful evidence for
definition-only fan-out, a required enum-shaped master, tenant code uniqueness,
exact-code resolver authority, lifecycle, trust, generic UI, and agent discovery.
The packet does not overstate that boundary.

## Delivered flat slice

One declarative Location entity contains:

- required code with tenant/environment case-insensitive uniqueness and
  identifier resolve authority;
- required name with advisory resolve authority;
- required Location Type enum (`warehouse`, `store`);
- Q0 get/list/search/resolve and O0 create/update/archive/restore;
- list/detail/form surfaces and storage, policy, query, operation, agent,
  reporting, and verification projections; and
- archive/restore as the only removal lifecycle.

There is no hierarchy, parent field, tree fallback, relation, quantity,
movement, on-hand, valuation, or hard-delete concept.

barrel line. Test scaffolding and journeys are 2,088 lines across compiler and
real-runtime fixtures plus unit, integration, PostgreSQL, agent, and browser
evidence; registration adds nine small entries/arguments. As with Catalog, the
ratio reflects executable evidence rather than module-specific runtime glue.

Mechanical work:

- allocate the `northstar.location` namespace and canonical IDs;
- reuse Catalog's definition/fixture/journey/registration structure;
- project one field inventory through the generic compiler and runtime; and
- register explicit unit and agent argv plus reviewed suite inventories.

Judgment work:

- stop rather than widen the press when unsupported hierarchy could not remain
  explicit;
- omit hierarchy entirely after the ruling rather than smuggle it in as retired;
- determine from the plan that Location Type is a field, not an invented entity;
- acknowledge that hierarchy descope removes the only natural relation; and
- model type as a required enum while keeping code exact and name advisory.

The hierarchy seam consumed more judgment than the rest of the definition; the
flat walking slice itself was predominantly mechanical reuse of the accepted
Catalog template.
