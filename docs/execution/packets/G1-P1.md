# G1-P1 — Canonical identifiers and minimal schemas

Status: active
Tier: Critical

## Goal and freeze semantics

Freeze the versioned v0-experimental canonical application language used by
downstream G1 packets: runtime-validated namespaced IDs, sparse authored and
complete normalized schemas, a pure versioned normalizer, deterministic
canonical bytes/hash profile, minimal launch-family definitions, stable
diagnostics, structural bounds, and a surface vocabulary isolated behind
opaque references.

This is a stable G1 contract with the G1-P0 bridge/reopen valve. It is not
production-v1 ratification. Production v1 requires inventory, purchasing, and
sales definitions to compile through every promised projection and is tracked
as later evidence.

## Review charter

- Gates must be green at every reviewed candidate.
- Threat model: accidental ambiguity, aliasing, nondeterminism, drift, or
  untraceable schema breadth introduced by honest authors or AI writers.
- In scope: tenets T1-T11; schema, normalization-law, strict JSON, canonical
  byte/hash, structural-bound, runtime-ID, reference, surface-token, and plain
  negative gates; field type semantics; property/family traceability; minimal
  state/relation contracts; and the falsifiable cross-package unsupported seam.
- Out of scope: adversarial parsing/evasion; future family breadth; runtime
  execution/lowering; composition semantics beyond parsing and explicit
  unsupported rejection; later release/storage/performance policies tracked in
  doctrine coverage.
- Decisive content questions: do exact decimal/money/date/time/datetime/
  quantity types carry the plan-required semantics without invented breadth;
  is every property consumed by G1/G2, an explicit reserved seam, or traceable
  to reviewed inherited design; and do relation/state schemas carry only
  parent scope and named transition semantics consumed by G2/G3?

## Acceptance criteria

1. `.gitattributes` lands before every fixture and pins repository text to LF
   while `.golden.bytes`/`.golden.sha256` remain `-text`.
2. T1-T11 are executable or explicitly documented with a deterministic gate.
3. Normalization is idempotent; equivalent authored forms converge; and
   canonical-authored round-trip is stable.
4. Normalized canonical bytes are the only future desired-state persistence
   representation; version/profile/hash metadata is present for the G1-P3
   revision envelope.
5. Unknown keys, kinds, versions, IDs, references, slots, status roles, hidden
   hooks, duplicate keys/order keys, lone surrogates, and bound breaches reject
   with stable structured diagnostics.
6. Exact business values use canonical strings, and field types make currency,
   minor unit, calendar/timezone, precision/scale, and quantity base unit
   explicit. The versioned v0 currency table is closed to evidenced CAD/2 and
   USD/2 pairs; datetime variants normalize against their referenced field.
7. Surface consumers see only stable references plus closed archetype/slot/
   status tokens; layout/component churn is not frozen here.
8. A foreign namespaced reference validates structurally and then rejects with
   `CANON_REFERENCE_CROSS_PACKAGE_UNSUPPORTED`.
9. The five requested deferrals and production-v1 gate are present in doctrine
   coverage with named execution stages/packets.
10. State storage is compiler-derived from machine identity; one child has one
    same-module top-level parent; and explicit order keys are scoped to their
    actual sibling owner.

or drift defects inside T1-T5/T7/T9/T11:

| Finding | Resolution and executable evidence |
|---|---|

Any corrected code SHA requires a fresh naive Codex xhigh review; Fable is not
launched until Codex passes, and both must review the identical unchanged SHA.

Fable max then reviewed corrected candidate
`ceefb2052afdd1965f82763a381719f758803626` and returned `REVISE` for one
