## Goal and Freeze C semantics

Persist the exact normalized Freeze A desired-state bytes and complete verified
Freeze B artifact set as immutable PostgreSQL `bytea` records. Revision,
release, verification-evidence, approval, and activation-attempt identities are
minted UUID references rather than content hashes; only immutable policy-free
artifact bytes deduplicate internally. Freeze C freezes minimal immutable
record/port and tenant/environment identity shapes for G1-P4/P5 without adding
activation, approval, pointer, rollback, or request-pinning behavior.

- Threat model: accidental mutability, minted-identity collision/derivation,

  adversarial input/evasion is excluded.
- In scope: exact Freeze A/B byte and hash consumption; revision/release/link/
  blob immutability; content collision comparison; manifest/projection/chunk
  hierarchy and closure verification; attestation and revision binding; minted
  two-tenant identity separation; forced RLS, runtime-role grants, missing
  context, and pool reuse; blob hash-oracle denial; and Freeze C shape-only
  boundaries.
- Out of scope: activation/approval semantics, pointer/CAS/rollback, request
  pinning, compiler redesign, global CAS product security, rich artifact
  payload semantics, and exotic cryptographic/adversarial failures.
- Decisive questions: can any product method or granted runtime privilege
  mutate/delete a stored row; can a corrupted, missing, mislinked, wrong-domain,
  wrong-closure, or wrongly attested bundle create a release root; can two
  tenants share bytes without sharing minted identities or rows; and can any
  missing/reused trusted context reveal a foreign release or raw blob?

## Acceptance criteria

1. Repository ports expose insert/read only; PostgreSQL grants and RLS policies
   are SELECT/INSERT-only, and twelve rewrite rules backed by an always-reject
   database guard also deny owner mutation.
2. Revision/release/evidence IDs are UUID identities, globally collision
   guarded, never hashes, and tenant/environment-qualified records remain
   distinct when compiled bytes are identical.
3. Global artifact blobs contain no tenant/environment/principal/coordinator
   columns or canonical keys. Runtime has no raw blob SELECT or hash lookup;
   release-qualified reads are the only artifact read path.
4. Forced RLS on revision/release/link tables uses the accepted trusted
   transaction context, fails closed without context, and clears state across
   a one-connection two-tenant reuse sequence.
5. Desired state and artifacts remain exact `bytea`. Freeze A digest/profile,
   every domain-separated artifact hash, root bytes, projection/chunk links,
   exact closure, compiler attestation, and tenant/revision linkage verify
   before root insertion.
6. Bootstrap and vertical-v1 fixtures round-trip every byte/hash; persisting
   the bootstrap for two tenants creates one physical blob per content hash
   and distinct tenant-qualified records/identity references.
7. Freeze C reserves `ActiveReleasePointer`, `ReleaseApproval`,
   `ReleaseActivationAttempt`, and verification-evidence identity shapes only.
8. Production persistence code does not import or call `compileApplication`;
   tests compile fixtures before repository invocation.

## Implementation and salvage record

- `@north-star/platform-runtime` owns the minimal immutable record shapes,
  generic repository port, tenant/environment identity, and reserved minted
  identities. It has no compiler/provider dependency and creates no second
  compiler protocol.

  `CompileSuccess` type. It reuses G0-P4b trusted transactions and validates

  compiler attestation before a registration transaction starts.

  security-definer staging, release-qualified artifact reads, root-kind guard,
  and immutable-write rejection rules. The G0-P4a runner retains transaction
  ownership and migration files contain no transaction-control tokens.

## Runnable exit

The repository remains buildable. A caller with a G0-P4b-issued trusted context
can insert/read one immutable revision and register/read one fully verified
compiler result. Corruption or scope mismatch leaves no reachable release root.
No release becomes active, and no serving request compiles application state.

## Limitations and deferrals

- G1-P4 owns human approval, activation-attempt claim, pointer CAS, read-back,
  history, rollback, and recovery.
- G1-P5 owns request pinning. No record in this packet selects an active
  release.
- G7 must define cross-tenant CAS authorization, encryption, existence-leak,
  and deduplication domains before any global reuse product API is enabled.
- Freeze B projection payload schemas remain provisional; this packet verifies
  their frozen envelopes and bytes, not richer business semantics.
