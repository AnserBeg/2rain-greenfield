## Slice 1 · Service appointment (`dateTime` point) — record

Status: executable; integrates on a full green of the exact integration commit. Critical paths touched: `db/migrations/0060_date_time_window_probe.sql` (definer probe), `module-storage-materializer.ts` (capture check, window index, ceiling probe). Stops taken: none.

**Claims.** (1) `addDateTimeField` parses alone and inside a change set; the preceding parser refuses it as unsupported, by kind, before any edit. (2) The logical field is one existing scalar (millisecond UTC instant) plus the optional v6 `dateTimeFields` declaration; omission emits no key, binding or floor, and a field-free customization's persisted release row equals the preceding compiler's bytes. (3) Operation, query and surface catalogs carry identical `dateTimeBindings` at surface reader rung 35; the serving loader refuses disagreeing bindings, an understated floor and a rung-35 floor without bindings; the archived production loader refuses a declaring release. (4) Typed entry, for both zone sources and every channel, refuses the DST gap with the entry preserved, asks for an offset in the repeated hour, refuses a foreign offset, unknown and `Etc/GMT±n` zones and sub-millisecond input; untouched values keep their capture. (5) Record-zone display: lists, exports and the Record print the captured civil value, offset and IANA name; the formatter prints `01:30 UTC−05:00` and `March 8, 2026` in UTC, Kiritimati and Edmonton processes. (6) Lists sort by stored instant with record ID breaking ties; filters, saved-view filters, metric sums, search, comparison, maximum-length, to-one and calculated operands refuse by logical type and field name; presence is admitted and evaluated on writes (create and an update that leaves the field out). (7) Added to a populated record type, the field runs exactly one `deferredOnlineFamily` `createIndex` in the approved attempt, ready and valid, after inert columns and before its `NOT VALID` capture check, which the catalog verifier accepts; earlier rows read absent. (8) One row over the 10,000-row ceiling — counted across every tenant's rows — refuses by name (`DATE_TIME_WINDOW_CEILING_EXCEEDED`, naming type, field and ceiling) while the source release keeps serving reads and writes. (9) The table itself refuses a partial capture and a civil/offset/instant disagreement, independent of session zone.

**Decisions.**
- Window index: a new `indexKind` literal `dateTimeWindow`, and capture checks in a new optional entity key `dateTimeCaptureChecks` (`checkKind: 'dateTimeCapture'`). Ruled under ADR-0047 §3 as anticipated widening of storage-target literal types, not a language event: emitted only when declared, payload version unchanged, field-free releases byte-identical. A literal is needed because the planner selects indexes by kind; reusing `resolveAccess` would collide with resolve-match emission.
- The probe counts physical rows through a `SECURITY DEFINER` boolean (`north_star_internal.module_table_exceeds`, `row_security = off` so an owner that RLS would filter errors instead of undercounting), because module tables force RLS and the materializer sees one tenant; it runs under the build's SHARE lock.
- Ceiling: `DATE_TIME_WINDOW_ROW_CEILING = 10_000`; `NORTH_STAR_DATE_TIME_WINDOW_ROW_CEILING` may lower it; higher values refuse. Measured writer blocking at the ceiling (B-tree, 10,000 rows): longest concurrent write 504–524 ms during a 1.6 s activation on hosted CI, 1,427 ms on a loaded laptop. Below the 2,000 ms trigger, so the ceiling stays 10,000.
- Civil storage is `timestamp(3) without time zone` (storage-only `localWallTime` contract); temporal columns leave PostgreSQL through `to_char`, so no driver `Date` or process zone touches them.
- Zones: ICU resolution plus a CLDR→IANA rename table (`Asia/Calcutta`→`Asia/Kolkata`); tzdb version is `process.versions.tz`.
- Company source uses the tenant business calendar (calendar ID = tenant ID, as Booking). An owned record uses its stored company. **Ruling 2026-11-21 (orchestrator):** a shared record uses the writer's working company, authorized by the operation's own policy at write time; with none, entry refuses `DATE_TIME_COMPANY_REQUIRED` and keeps the entry. The capture keeps civil time, offset and zone, so readers in other companies print it unchanged.
- A required field added to an existing type is refused by the storage planner (`COMPILER_BACKFILL_INADMISSIBLE`), so no appointment is invented.
- Scope notes: the viewer-zone switch follows slice 1; rung 38 and migration 0060 were assigned at merge; drafter keys come from the member schema.
- **Not proven / named ride-alongs:** PDF text (no generator on `main`; formatter proven in UTC processes and at list/export); a PostgreSQL upgrade that reopens and writes a value (`CUSTOMIZE-5-upgrade-reopen`); the archived reader answering a query (`CUSTOMIZE-5-archived-query`, rule 13); AI-BUILD-1 eval cases.

## Release and upgrade proofs for each executable slice

- Require the whole field when status is Scheduled. An absent field refuses and a complete value passes. Exercise named comparison, maximum length and numeric duration gaps, including literals, same-record and to-one comparisons and calculated operands/results. Exercise each row of the ADR’s consumer table, including saved string filters and forged bindings. Every refusal identifies the type, field and use.
- Check the database constraints against partial captures, civil/offset/instant disagreement and, for intervals, empty, reversed, non-finite or inconsistent ranges. Verify the scoped window index at activation. The new database checks reach an existing table as `NOT VALID` constraints that bind new writes; old writers are unaffected because they leave every new column null, and slice 1 must prove the catalog verifier accepts these multi-column checks. Commit before removing each independent guard and require its own regression proof to fail.
- Recompile a first-party release and a real customized release omitting both declarations against identical parents and provenance. Compare normalized bytes, entire envelopes, roots and floors read back from persisted release rows. Exercise the archived production loader immediately preceding each rung on a declaring release. After slice 2 cover date-time alone, interval alone and both together against their required floors. Missing bindings and understated floors refuse before serving.
- Reproduce the original roots, upgrade across an unrelated base addition, reopen a pre-upgrade value and write a second. Exercise a real ID collision for each kind and observe the named patch, `FIELD_COLLISION`, and continued verified source reads. Remove each allowlist entry in turn and require the vocabulary check to name it. Include ordered change-set replay. Roll back and re-activate a compatible release to read the original value again.
