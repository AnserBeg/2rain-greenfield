# G0-P3 — Executable architecture boundaries

Status: active
Tier: Behavioral

## Goal and scope

Turn the accepted constitutional dependency and authority boundaries into a
deterministic local/CI gate. The checker must pass on the greenfield repository
and return a non-zero exit for forbidden package edges, provider/framework
imports, alternate authorities, gateway bypasses, writable inventory peers,
prohibited agent tools, hard-delete paths, and duplicate trust authorities.

Owned paths:

- `package.json`
- `packages/dev-tooling/src/architecture-boundaries.ts`
- `packages/dev-tooling/src/check-boundaries.ts`
- `test/helpers/architecture-fixture.ts`
- `test/architecture/dependency-boundaries.test.ts`
- `docs/decisions/salvage/g0-p3-structural-test-technique.md`
- `docs/execution/doctrine-coverage.md`
- `docs/execution/packets/G0-P3.md`
- `docs/execution/ledger.md`
- `learnings.md`

Out of scope: CI workflow creation, runtime gateways, database/provider tests,
release activation behavior, inventory posting implementation, UI grammar,
and any G0 stage-gate claim.

## Required gates

- `corepack pnpm check:boundaries`
- `corepack pnpm test:architecture`
- `corepack pnpm typecheck`
- `corepack pnpm lint`
- `corepack pnpm build`
- `corepack pnpm test`
- `git diff --check main...HEAD`
- owned-path and salvage-admission review

## Runnable exit

The repository still installs, builds, and runs its complete scaffold test
suite. The root `test` command includes the architecture gate, so any CI job
that runs the canonical test command fails on a boundary violation.

## Test it yourself

```bash
cd /home/rvham/2rain-greenfield
corepack pnpm check:boundaries
corepack pnpm test:architecture
```

Expect the first command to print `architecture-boundaries: PASS`. Expect the
second to pass the real-repository check plus negative fixtures proving that
forbidden imports and forbidden authorities return stable rule IDs and a
non-zero CLI exit.
