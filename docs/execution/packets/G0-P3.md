# G0-P3 — Executable architecture boundaries

Status: active
Tier: Behavioral

## Goal and scope

Turn the accepted constitutional dependency and authority boundaries into a
deterministic local/CI gate. The checker must pass on the greenfield repository
and return a non-zero exit for plain forbidden package edges,
provider/framework imports, alternate authorities, gateway bypasses, writable
inventory peers, prohibited agent tools, hard-delete paths, and duplicate trust
authorities.

Owned paths:

- `package.json`
- `packages/dev-tooling/src/architecture-boundaries.ts`
- `packages/dev-tooling/src/check-boundaries.ts`
- `test/helpers/architecture-fixture.ts`
- `test/architecture/dependency-boundaries.test.ts`
- `docs/decisions/salvage/g0-p3-structural-test-technique.md`
- `docs/execution/doctrine-coverage.md`
- `docs/execution/packets/G0-P3.md`
- `docs/execution/ledger.md`
- `learnings.md`

Out of scope: CI workflow creation, runtime gateways, database/provider tests,
release activation behavior, inventory posting implementation, UI grammar,
and any G0 stage-gate claim.

## Threat model and scope boundary

G0-P3 protects a 14-file scaffold maintained by trusted contributors. Its job
is to catch accidental, plain-text structural violations during ordinary
development: direct imports and dependency names, obvious duplicate/alternate
authority declarations, direct cross-domain inventory writes, ordinary direct
storage calls, ordinary hard-delete forms, and explicit JSON tool catalogs
with a sixth tool or the wrong five-tool count.

It is not an anti-obfuscation or hostile-insider scanner. Escaped literals,
dependency aliases and override redirects, computed/quoted ORM or SQL syntax,
generated-output discovery heuristics, synonym invention, and alternate
serialization shapes are explicitly deferred. Revisit these only when real
product code exists and a concrete threat model or an observed accidental
bypass justifies a focused hardening packet. Runtime authorization, provider,
transactional, tenant-isolation, and recovery proofs remain assigned to their
later packets in the doctrine-coverage map.

| Known limitation / future hardening | Disposition | Revisit trigger |
|---|---|---|
| Adversarial obfuscation/evasion: escaped literals, dependency alias/override/protocol redirects, computed or quoted ORM/SQL, generated-output filename discovery, synonym invention, and alternate catalog serialization | DESCOPE from G0-P3; not a review blocker | Real product code plus a concrete threat model or an observed accidental bypass |

## Final review charter

- Gates already green: boundary checker, seven plain negative/positive
  architecture tests, typecheck, lint, format, build, and the complete scaffold
  suite.
- In scope: each P3-owned ADR boundary's plain accidental form in the table
  below is rejected; the real scaffold passes; CLI evidence is stable.
- Out of scope: every adversarial-obfuscation/evasion case in the known-
  limitation row and all later runtime semantics.
- Threat model: honest developers or AI writers making ordinary, visible
  structural mistakes in the G0 scaffold; no hostile insider.
- Decisive question: does the frozen checker and fixture suite honestly prove
  those plain forms, without claiming ADR-0004/ADR-0006 runtime enforcement?

## Plain negative-fixture coverage

| Boundary | Obvious rejected violation |
|---|---|
| ADR-0001 | `globalActiveRelease`, `activeOverlay`, or a duplicate canonical release authority |
| ADR-0002 | a domain/compiler/runtime package directly importing or depending on another non-contract package |
| ADR-0003 | a compiler, contract, or domain package directly importing/declaring a named provider or framework dependency |
| ADR-0004 | no P3 claim; trusted-context and tenant proofs remain at G0-P4/G1 |
| ADR-0005 | a direct `@agent-native/core` dependency/import or named compatibility facade |
| ADR-0006 | no P3 claim; human approval and activation proofs remain at G1/G6 |
| ADR-0007 | a direct cross-domain inventory write, writable balance, or update/delete of append-only facts |
| ADR-0008 | an application `db`/`database`/`repository` call or named private action registry |
| ADR-0009 | a named raw/admin tool, sixth tool, duplicate tool, or wrong five-tool count in an explicit JSON profile |
| ADR-0010 | a named duplicate trust authority, ordinary `DELETE FROM`, or named hard-delete path |

## Runnable exit

The repository still installs, builds, and runs its complete scaffold test
suite. The root `test` command includes the architecture gate, so any CI job
that runs the canonical test command fails on a boundary violation.
