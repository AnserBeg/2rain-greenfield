# U3 debate — Arm verdict: minimum client capability

## Findings that correct or extend the charter (verified by reading)

Four facts materially shape the ruling, and none of them appear in the charter:

**F1 — Zero-JS is enforced, not incidental, and the enforcement point is the natural gate.** `apps/web/src/app-server.ts:38` serves every page with `default-src 'none'; style-src 'unsafe-inline'; …` and **no `script-src`**, so browsers refuse all script execution and all `fetch`/XHR today. Any client capability of any tier must amend this header — and that is where a closed capability can be made *observable*: a CSP of `script-src 'sha256-<hash>'` pins the entire client capability to one content-hashed block. A gate that fetches the header and recomputes the hash of the served block observes the fact directly (AGENTS.md §6), with no proxy.

**F2 — The plan already commits to client JavaScript at launch, independent of ADR-0032.** Plan §8.5 makes scanning "camera-based and keyboard-wedge compatible" at launch (plan line 1711) — camera scanning is impossible without client JS (`getUserMedia`). The same section requires an installable PWA (line 1690) and a global command palette (line 1667), and §8.4 requires mutations to "converge through event invalidation with polling fallback" (line 1631). So option A is not the conservative reading of the repository's accepted decisions — it contradicts the plan's own launch contract, and its true blast radius includes §8.5, not just ADR-0032.

**F3 — The server half of determinate progress does not exist, and it is the bigger half.** `packages/runtime/src` contains no job, operation-status, or background-execution concept at all (verified by search). `submitSurfaceRuntimeIntent` awaits the gateway synchronously (`surface-runtime.ts:289`). ADR-0032 §3a forbids a bar without real progress data (ADR-0032:99-103). Therefore no client tier can deliver the >10 s band until an async operation envelope with a progress source exists — server work adjacent to U1/U5, not client capability. Today no shipped user-facing operation demonstrably exceeds 10 s (publish is budget-gated at ≤5,000 ms, ADR-0020), so the band currently has no occupant; its first occupants arrive with G3 posting/import.

**F4 — Option A's only mechanism for live progress is a documented WCAG failure.** With scripts blocked, the sole way to update a progress page is `<meta http-equiv="refresh">`. Periodic meta-refresh is WCAG failure technique **F41** (fails SC 2.2.1, Level A), and it destroys focus and scroll position on every tick — for exactly the repeat professional ADR-0032 §3 centers. Plan §8.4 binds WCAG 2.2 AA. So A cannot implement the >10 s band inside the standing constraints even crudely; striking the band is A's only honest form.

Two smaller corrections. The charter's pin worry is overstated: `checkUxGrammarPin` binds *specific fragments and vocabularies*, not file bytes — the UX004 fragment list (`surface-runtime-seam.ts:530-538`) and the SURF001 structural-markup scan (`:622`, whose element list omits `script`, `div`, `progress`, `output`, `dialog`) both survive a bounded enhancement layer untouched. And part of the charter's three-item scope is already deliverable with zero JS: section expand/collapse is native `<details>` (nav groups at `surface-runtime.ts:863`, record sections in the CSS), the bulk bar's state is pure CSS `:has()`, and native HTML constraint attributes plus `:user-invalid` styling deliver a real inline-validation floor with no script.

## 1. The ruling

**Tier B, strictly bounded — and smaller than the charter's option B.**

**May be introduced:** exactly one repository-owned progressive-enhancement script — no dependency, no framework, no build-step bundler — **inlined into the served document and hash-pinned in the CSP** (`script-src 'sha256-…'`; pages are already `cache-control: no-store` at `app-server.ts:35`, so inlining costs nothing). It may do four things only:

1. **Pending states** — on an activated control, toggle `data-`state attributes for the §8.4 `pending/accepted/failed` machine (including preventing double-activation; the server's `idempotencyKey` remains the correctness authority).
2. **Determinate progress** — poll one status resource for a running operation and update a server-rendered `<progress>` and step/elapsed text (`aria-live`), with cancel/background-handoff as server-rendered forms and links. Gated on F3: only after an async operation envelope with real progress data exists.
3. **Optimistic transitions** — apply/reconcile the compiled allow-list transitions by reading per-slot eligibility from data-attributes the server renders out of the `SurfaceDefinition` (U5's M1 projection). Never from client-held configuration.
4. **Inline validation advice** — run compiled validation rules (emitted as declarative attributes/data) on blur and pre-submit, and move focus to the first incomplete field (U7). Advice only: it may never block a submission the server would accept, and the server remains the sole validator.

**May not be introduced:** any client framework or third-party client dependency (React, htmx, Alpine — anything); hydration; client-side templating or rendering of business data; a client router; a client state store of any kind; any second script; any script-created interactive element (`form`/`input`/`button`/`select` stay server-rendered — SURF001 already half-enforces this at `surface-runtime-seam.ts:622`; extend the rule to cover the enhancement block explicitly); any network call from the script other than the operation-status resource. Every page must remain complete and correct with scripts disabled: reads fully (ADR-0032 §2's default path, now gated rather than promised), writes fully with degraded feedback.

**C is not adopted now but is the named escalation tier**, admissible later by amending ADR-0036 on measured evidence (see §8). **D is rejected**, not deferred: it re-founds the compiled-surface seam (see §4) and hands G6 a component-tree customization problem the definition model exists to avoid.

## 2. Admissibility

**ADR-0005 does not bind this choice the way the standoff framing suggests, and the "previous summary" the charter flags is indeed wrong.** Read in full, ADR-0005 is about `@agent-native/core` — identity, action registry, and *application state* in the desired-state/release sense ("Desired state, compiled releases, and active-version selection belong to the authorities governed by ADR-0001," ADR-0005:25-26). Its superseding-ADR clause (ADR-0005:36-38) attaches to adopting "it or an equivalent framework" — an equivalent *agent/identity/action/state* framework. A UI renderer is not equivalent in kind, so **no superseding ADR of ADR-0005 is required for any of B, C, or D.** What its enforcement clause (ADR-0005:61-66) does bind — and permanently — is the *shape* of anything adopted: no framework may own application state, identity, policy, or business operations. Tier B honors that trivially (there is no framework and no client-owned state); ADR-0036 should cite it as an inherited constraint, and it is the strongest standing argument against D's usual failure mode (client stores caching business truth).

**What is actually required is ADR-0036, and it is mandatory, not optional.** ADR-0032 reserved this decision explicitly and imposed a standstill: "Until it lands, no packet may introduce a client runtime to satisfy this ADR" (ADR-0032:171-178). So the answer is: **a new ADR (0036), no superseding of ADR-0005, plus one prose-level plan amendment** — §8.1's "React components do not read business tables…" (plan:1587) and §8.6's "no bespoke route or React screens" (plan:1738) become framework-neutral ("surface components," "bespoke screens"), since the plan's text presumes the substrate this debate is deciding against. I verified neither phrase is a pinned anchor: `checkPlanPin`'s required §8.6 fragments (`surface-runtime-seam.ts:404-408`) don't include the React sentence, and the skill's UX001 anchor "No bespoke route or React screen for ordinary reads/writes" (SKILL.md:89-92) stays verbatim — it remains true under B.

## 3. The smallest first increment

**Increment 0 — no JS at all, available immediately:** emit native constraint attributes (`required`, `pattern`, `min`/`max`, `inputmode`) from compiled field definitions, with `:user-invalid` styling. This is inline validation's floor, it is not a "client runtime," and it doesn't even trigger ADR-0032's standstill. It belongs to U7 but nothing forbids it sooner.

**Increment 1 — the first script, and what ADR-0036 should gate its shipping packet on:** the pending-state behavior alone — activated control gains `data-pending`, re-activation is suppressed, state clears on navigation. This serves the 400 ms–1 s ladder band on every existing form today. It ships with the full gate harness, which is the real point of doing it first: (a) CSP hash observed equal to the served block's hash; (b) a Playwright journey with `javaScriptEnabled: false` proving every read and every write path completes — the reads-need-no-JS constraint becomes an executed negative control; (c) a negative control that no pending state exists before activation.

**Determinate progress is increment 2 and gates on F3:** the first measured >10 s operation with a real server progress source (realistically G3 import or bulk posting). Its gate must include ADR-0032 §3a's fabrication control: stall the server job and observe the bar not move.

## 4. Cost at the compiled-surface seam

**Under B: near zero, and nothing pinned moves.** The compiler emits exactly what it emits today (`definition.ts:1320-1362`); when U5 lands M1, per-slot latency class and optimistic eligibility ride the existing projection and the runtime renders them as data-attributes — the script consumes attributes, never definitions. `surface-runtime.ts` gains one inlined block and some attributes; `renderSurfaceRuntime`/`renderRegisteredSurfaceComponent` fragments (UX004) are untouched; `app-server.ts` changes one header line, which is not a pinned fragment. `script` is absent from SURF001's element list, so the bypass scan is undisturbed. The `ux-grammar` pin experiences **zero mechanical breakage**; the one deliberate three-way amendment (plan + skill + vocabulary) comes later with U5's slot-state vocabulary, and that cost belongs to U5, not to this ruling.

**Under C:** the runtime must additionally render *fragments* (kept honest against the skill's no-bespoke-route anchor only by making fragment rendering a mode of the single `/` route), markup grows swap attributes, and the web app takes its first third-party runtime dependency. Pin survives mechanically; the "sole browser renderer" contract (`surface-runtime.ts:75-78`) grows a second output shape.

**Under D:** `surface-runtime.ts` (1,006 lines) and `component-registry.ts` (984 lines, a frozen registry the pin checker parses *by regex* at `surface-runtime-seam.ts:663-677`) are rewritten as component trees; the UX004 fragments, the registry parser, and SURF001's founding premise — structural markup confined to exactly two files, with `jsx(...)` calls explicitly matched (`:622`) — are all void and the enforcement layer must be re-designed, not amended. The browser suite and the G2 surface-grammar conformance suite re-anchor. That is a new seam, not a change to this one.

## 5. Cost at G6

**Under B: none structural.** Tenant customization edits `SurfaceDefinition`s; the server renders any definition, attributes included, so a tenant-customized surface gets correct feedback behavior automatically — one global script, zero per-tenant or per-module JS, and the ux-grammar rule "never raw CSS/HTML" extends naturally to "never tenant scripts" (write this into ADR-0036). The plan's promise that a generated module is "grammatically correct by construction" (plan §8.6) survives because generation still targets definitions. **Under C:** modest — fragment endpoints render the same definitions. **Under D:** tenant customization, preview, and publish-diff must all produce and host component trees; the zero-design-work guarantee now routes through a component build; the builder becomes a framework application. This is the heaviest hidden cost of D and the charter is right to flag it.

## 6. One-way-door assessment

**B at 6 months: fully reversible** — delete one block and one header line; because the no-JS gate forces every page to be complete without it, removal is a feedback regression, not a functional one. **B at 18 months: the door is scope creep**, not the tier itself — the one file quietly becoming a framework. ADR-0036 must build the tripwires in: a byte-size ratchet on the block (the same instrument as U0's hex ratchet), the no-invented-controls rule as a scan, and a Playwright-observed network assertion that the script's only request target is the status resource. Crossing any of these is the C/D boundary and requires the amendment, not a reviewer's shrug. **C at 18 months** is semi-reversible: markup gets organized around swap seams and unwinding is real work. **D is effectively permanent** — every subsequent surface packet is written against it — which is precisely why it needs affirmative evidence that B and C have failed, and none exists.

## 7. If the answer were A (it is not — priced for the reconciler)

A would require striking or deferring by ADR: the >10 s ladder row and §3a's cancel/background ruling (ADR-0032:55, 105-107), emptying the §4 allow-list, and reducing inline validation to increment 0. It would *also* require amending plan §8.5's camera-scanning, PWA, and command-palette commitments and §8.4's polling-fallback line — the cost the charter's framing of A omits, and the reason A is not actually the minimal-change option. A warehouse operator posting a 200-line batch would watch a frozen tab with a spinner in the browser chrome as the only signal, or a meta-refresh page that fails WCAG F41.

## 8. What would change my mind

**Toward C:** a *measured* interaction that cannot meet its ladder band through full-document round-trips on the 400 ms budget — the likeliest candidates are the G6 builder's edit-in-place loop and `onDemand` disclosure fetches — or the enhancement block's ratchet being pressured past its budget by legitimate requirements twice. **Toward D:** the §8.3 component registry's growth (child-line editors, drawers, palette) producing evidence that string-rendered HTML plus enhancement is unmaintainable, or N3's offline task queue entering scope, since a real offline queue genuinely needs a client runtime. **Toward A:** the user striking camera scanning and the PWA from §8.5 by ADR and accepting the ladder truncation. Absent one of these observed, the ruling stands.

**Ruling paragraph for the verdict document:**

> U3 rules Tier B, narrowed: the platform's minimum client capability is a single repository-owned, dependency-free progressive-enhancement script, inlined into the served document and content-hash-pinned in the CSP that today blocks all script (`app-server.ts:38`), limited to four behaviors — pending-state toggling, polling one operation-status resource to drive server-rendered determinate progress, applying compiled optimistic-allow-list transitions read from definition-derived data-attributes, and advisory inline validation — and forbidden everything else: frameworks, third-party client dependencies, hydration, client rendering of business data, client routing or stores, script-created interactive elements, and any second script. Reads remain fully functional with JavaScript disabled, enforced by an executed browser gate rather than a promise. ADR-0005 is not superseded and does not need to be — it governs agent-framework and authority questions, and its enforcement clause against framework-owned application state is inherited as a standing constraint, not an obstacle; what is required is the reserved ADR-0036 (mandated by ADR-0032's standstill) plus framework-neutral rewording of plan §8.1/§8.6's React phrasing, none of which is a pinned anchor. The `ux-grammar` pin suffers zero mechanical breakage; the compiler and `SurfaceDefinition` seam are untouched; G6 tenant customization inherits nothing. The first increment is native HTML constraint validation (no script at all), then the pending-state script carrying the full gate harness; determinate progress waits for the async operation envelope and the first real >10 s operation, because no job substrate exists in `packages/runtime` today and ADR-0032 §3a forbids a bar without real data. Option A is rejected because the plan itself commits to client JavaScript at launch (camera scanning, PWA, palette — §8.5) and A's only live-progress mechanism is WCAG failure F41; option C is reserved as the named escalation tier on measured evidence; option D is rejected as a re-founding of the compiled-surface seam and the G6 story, not an amendment to them.
