# ADR-0087. Date-time and interval fields on customer-built records

**Proposed · 2026-11-20.** Fable’s R1 on ADR-0086 identified the authoring gap. A dispatcher can add a service date today. To schedule a 2 pm call or a shift across midnight, the record also needs to say where the time was entered and what its end means. This proposal supplies those source fields for Calendar and resource timeline. Fable’s design read precedes implementation. [ADR-0086](ADR-0086-board-calendar-and-resource-timeline.md)

## What the owner declares in Customize

| Add-only patch member | Required declaration | Example |
| --- | --- | --- |
| `addDateTimeField` | `schemaVersion`, tenant record type ID, stable field ID, label, requiredness and a versioned zone source (`companyBusinessCalendar` or `perRecordIana`). The logical type is `dateTime`. | **Service appointment** at 14:00 in the job’s IANA zone. |
| `addIntervalField` | Its own `schemaVersion`, the same field identity and zone-source contract, `granularity` (`dateOnly` or `timed`) and `endConvention` (`inclusive` or `exclusive`). The logical type is `interval`, with an inclusive start and two finite endpoints. | **Staff shift** from 22:00 to 06:00, end exclusive. **Leave** from Monday through Friday, end inclusive. |

Both members work alone or after their owning type in an ordered change set. Keep the historical `addField`, `addRecordType.fields` and `addLineTable.fields` vocabulary closed. The preceding parser must refuse the unknown member, including inside a change set, before applying any edit. Bind one logical field through the existing form, governed create/update operation, scoped query and Record. Treat its storage components as private to that field, with the same access and classification. Compile nullable storage for an optional addition so earlier records read as absent. Apply ADR-0011’s required-field admission to the whole value and refuse a required addition that would need an invented appointment for an existing row. Show the owner the zone, granularity and end convention in the diff before approval. [ADR-0011](ADR-0011-compiled-module-storage-transitions.md) · [ADR-0079](ADR-0079-form-and-record-composition.md)

## Enter once and read in either zone

For `companyBusinessCalendar`, resolve the owning company (the authorized working company on initial entry for a shared record) through the tenant’s declared calendar. Today ADR-0018 supplies one zone and day boundary across that tenant’s companies. Capture the company/calendar identity and effective settings with the value. For `perRecordIana`, the writer selects an IANA zone stored with this field on the record. One zone governs both interval endpoints. Missing company context, a missing calendar or an unknown zone refuses entry at the field. [ADR-0018](ADR-0018-temporal-authority.md)

The server resolves each local date and time independently at millisecond precision. In a DST gap, return a field error and keep the input. In an overlap, show both offsets and require the writer to choose one. Validate any supplied offset against the zone at that local time and refuse excess precision. Preserve the entered civil value, selected offset and zone alongside the resolved UTC instant. The same checks govern the form, API and assistant. A write or explicit clear replaces the whole logical value atomically. Omitting it on update preserves it. Refuse a partial value before mutation.

**Record zone** shows the captured civil value, IANA name and offset. **Viewer zone** converts the stored instant to the viewer’s explicitly selected IANA zone and labels that zone and offset. Default to the record zone. Editing starts with the recorded values and source context. A viewer switch or later calendar change never reschedules a record. Dates entered at date-only granularity retain their civil labels in both modes.

## Which windows contain an interval?

Preserve both entered endpoints for editing and derive a normalized half-open range at write time for overlap reads. With an exclusive end, use the entered end directly. For an inclusive civil end, advance to the next civil date, then resolve its boundary. Resolve the start independently. Use the captured business-day boundary for a company calendar and local midnight for a per-record zone. Apply the same gap and explicit-offset rules to each resolved boundary. For an inclusive timed end, add one millisecond to the resolved end **instant**. Check endpoint order on civil dates or resolved instants, respectively. Refuse reversed endpoints, an unrepresentable successor or an empty normalized range. Equal inclusive endpoints describe one civil day or one millisecond. An absent optional field is Unscheduled.

A window includes a point when `from <= instant < until` and an interval when `start < until && endExclusive > from`. An ADR-0086 view over two ordinary dates still owns its endpoint pair and convention. A view over a typed field binds its stable ID and expected source contract. Refuse a contradictory convention, granularity or zone source at compile time. The view’s single axis zone governs window boundaries. The field’s captured zone governs its value. CALENDAR-1 owns the bounded reads and indexes for its views. These record fields carry no Booking capacity or move authority. ## Rule operands, readers and replay

- **Rules and calculations.** In v1 the compiler refuses both logical types by name in every validation operand position (including presence, literals, same-record fields and to-one terminals), and as calculated operands or results. Diagnostics identify the type, position and referenced field when present. Resolve the logical type before inspecting any backing scalar. Test both types through each authorable route, including forged declarations at compilation. Existing civil-date rules and exact-decimal calculations keep their contracts. - **Release admission.** Use optional v6 declarations. With neither present, compare normalized bytes, complete envelopes, roots and floors byte for byte across compilers, on identical first-party inputs and a real tenant runner with the same provenance and parent. Follow ADR-0047 for a changed compiler profile or a required language ruling. For each declaring slice, take the next mandatory surface-manifest reader rung on freshly fetched main at merge. Regenerate, run CI and re-fetch before push. Renumber if overtaken. The floor is the maximum across features. Check declaration, storage, operation/query/surface bindings and floor in both directions. Exercise the actual preceding serving reader on a release with the new type, including an interval-only and a mixed release, and refuse missing bindings or understated floors before serving. Deployment must retain the highest patch parser and reader floors used by any tenant, even after release rollback. [ADR-0047](ADR-0047-the-compiler-semantic-profile-is-the-projection-evolution-axis.md) · [ADR-0079](ADR-0079-form-and-record-composition.md)
- **Upgrade and rollback.** Each executable slice adds its member to UPGRADE-2’s independent, hand-written replay allowlist. The inventory gate must fail when either kind is in the vocabulary but missing from the allowlist. Replay must check each ordered change-set member. Give each kind a named real replay test. Reproduce the original source chain and roots, then replay unchanged patches onto a compatible new base. Read a saved value and write another through the upgraded form and query. On an occupied field ID report `FIELD_COLLISION` against that patch. On a changed bound type or scope use `INCOMPATIBLE_TYPE` or `INCOMPATIBLE_SCOPE`. Keep the verified source serving on refusal. Pointer rollback restores the compatible predecessor’s field exposure and preserves stored values.
