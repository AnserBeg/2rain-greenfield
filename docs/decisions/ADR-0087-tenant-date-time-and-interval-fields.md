# ADR-0087. Date-time and interval fields on customer-built records

**2026-11-20 · Accepted, with amendments, after Fable's 2026-11-20 re-read of A4.** A dispatcher needs to enter a 2 pm service call or an overnight shift and see it on the right day. This decision defines the source fields for Calendar and resource timeline. The existing-table index case in A4 was settled by the 2026-11-20 re-read. [ADR-0086](ADR-0086-board-calendar-and-resource-timeline.md)

## What the owner declares in Customize

| Add-only patch member | Required declaration | Example |
| --- | --- | --- |
| `addDateTimeField` | Own `schemaVersion`, target, stable field ID, label, requiredness and a versioned zone source (`companyBusinessCalendar` or `perRecordIana`). Logical type `dateTime`. | **Service appointment** at 14:00 in the job’s zone. |
| `addIntervalField` | Own `schemaVersion`, the same target, field identity and zone-source contract, plus granularity and end convention. Both members take a discriminated target, initially `{ kind: "tenantRecordType", recordTypeId }`. First-party masters, document headers and line-table rows are named target gaps. A later schema version may add a target variant to the same member. Each member works alone or after its owning type in an ordered change set. Keep the historical `addField`, `addRecordType.fields` and `addLineTable.fields` vocabularies closed. The preceding parser refuses an unknown member, including inside a change set, before applying any edit.

Bind one logical field through the form, governed create/update operation, scoped query and Record. All private components inherit the field’s access and classification. An optional addition reads as absent on earlier rows. Apply required-field admission to the whole value and refuse a required addition that would need an invented appointment. Show the zone source, granularity and end convention in the approval diff. [ADR-0011](ADR-0011-compiled-module-storage-transitions.md) · [ADR-0079](ADR-0079-form-and-record-composition.md)

## Entry, display and editing

For a company-sourced field, resolve the owning company (the authorized working company on initial entry for a shared record) through its declared business calendar. Capture the company and calendar identity, effective zone and day boundary. For a per-record field, default the zone selector to the company calendar’s zone. Store the selected canonical IANA ID, normalize IANA links and refuse unknown names and fixed-offset `Etc/GMT±n` IDs. One zone governs both endpoints. Missing required company or calendar context refuses entry. Record the time-zone database version with each capture. [ADR-0018](ADR-0018-temporal-authority.md)

The form accepts typed times in one-minute steps. The server accepts up to millisecond precision and refuses finer input before rounding. A typed time in a DST gap gets a field error that preserves the input. In a repeated hour, show both offsets and require a choice. Validate the supplied offset against the zone. Apply these rules to form, API and assistant writes. Set or clear the whole logical value atomically. Leaving the field untouched preserves its capture, including sub-minute precision. Editing opens on the recorded civil values. A changed civil entry resolves afresh using the current company calendar for a company-sourced field or the selected zone for a per-record field, and records a new capture.

The stored instant remains authoritative for a timed value after a calendar or time-zone database change. **Record zone** displays the captured civil value, IANA name and offset. **Viewer zone** converts the instant to the IANA zone explicitly selected on the Record and labels the result with its zone and offset. Carry that selection in the Record URL for the current view. Default to record zone when absent and never infer a zone from the browser or device. Date-only labels remain the entered civil dates in either mode.

Every reader without an explicit viewer switch uses record-zone display, including lists and saved views, documents and PDFs, exports, API responses, notifications and assistant text. A date-only value prints its civil date without conversion. Process, database-session and template zones cannot override the capture. In DOCS-1’s read, item 4, the Record showed a November 18 purchase order while its Edmonton PDF printed November 17 at 5 pm. Require a document generated in a UTC process to print the later Toronto overlap as **01:30 UTC−05:00** and a civil **March 8**. Inspect the generated output for both values. [CUSTOMIZE-5 proofs](../execution/packets/CUSTOMIZE-5.md#test-it-yourself)

## Which windows contain an interval?

The start is inclusive and both entered endpoints are finite. Preserve them for editing. For timed intervals the normalized range is `[startInstant, endInstant)`. For date-only intervals the entered civil dates are authoritative, including after a time-zone database change. The normalized civil range is `[startDate, endExclusiveDate)`. An inclusive end advances by one civil date. Reject reversed endpoints, an unrepresentable successor, an empty range or a partial value. For equal timed endpoints suggest a `dateTime` point. Equal inclusive dates cover one day. Open-ended intervals are reserved for a later schema version. An absent optional value is Unscheduled.

For evidence, resolve each date boundary independently at the captured business-day boundary or, for per-record zones, local midnight. Include the successor boundary for an inclusive end. Apply ADR-0083 A1 to system-derived boundaries. A gap resolves to the first valid instant after it and a repeated boundary to the earlier offset. Pin the boundary-rule version with the value. [ADR-0083, time arithmetic](ADR-0083-period-and-usage-billing.md)

A point belongs when `from <= instant < until`. An interval overlaps when `start < until && endExclusive > from`. For a date-only interval on any Calendar, compare its civil range to the window’s civil dates in the view’s axis zone. A Toronto leave for March 8 occupies only March 8 on a Vancouver calendar. Use the evidence instants only to place a bar on an instant axis and always show its civil label. Timed membership compares instants. For a typed source, the view binds the stable field ID and asserts the expected field contract. A mismatch refuses compilation. The field owns its granularity, convention and capture. The view independently chooses its axis zone. CALENDAR-1 owns bounded view reads. These fields confer no Booking capacity or move authority. [ADR-0086, time windows](ADR-0086-board-calendar-and-resource-timeline.md#time-windows-coverage-and-page-budget)

## Canonical form and storage

Use two dedicated, optional v6 declarations projecting existing scalar components as one logical field, one declaration each for `dateTime` and `interval`. Neither extends the canonical field-kind union or `dateTimeFieldType.timezoneSemantics` (`utcInstant` and `offsetDateTime`). Neither uses the `dateOnly` editor’s midnight-UTC encoding. Omission emits no normalized key, default, projection binding or floor. This fits ADR-0047 §7 without a new language ruling, subject to the persisted-byte proof below. A change to existing v6 meaning would require a separate ruling. [ADR-0047 §7](ADR-0047-the-compiler-semantic-profile-is-the-projection-evolution-axis.md#7-an-optional-authored-key-rides-the-adopted-language-version--ruled-2026-08-07-on-u5bs-review)

| Private storage per field | Columns and database invariants |
| --- | --- |
| Shared capture | Canonical IANA zone, tzdb version and zone-source tag. A company capture includes company ID, calendar ID and effective settings including day boundary. A per-record capture has no calendar components. Check all components required by the declared variant are present together, or every column of the optional field is null. |
| Point or timed endpoint | Instant (`timestamptz(3)`), entered civil timestamp (`timestamp(3) without time zone`) and signed offset in seconds. Check finite values and that civil time minus offset equals the instant expressed in UTC, independently of session zone or current tzdb. |
| Timed interval | Start and end each have the timed endpoint columns, with one shared capture. Store the normalized `tstzrange` and check it equals the range derived from the two instants. |
| Date-only interval | Entered start and end (`date`), one shared capture and boundary-rule version. Store each resolved boundary’s effective civil timestamp, offset and instant, including the exclusive successor when applicable. Check each instant against its effective civil timestamp and offset. Store the normalized `daterange` and check it against the entered dates and convention. |
| Either range | Check endpoint order and require a finite, non-empty, lower-inclusive, upper-exclusive range. Reject unbounded bounds and explicit infinity. All-or-none applies to the endpoints, range and capture as a single value. |

The field’s storage plan creates and verifies its window index together with the columns. Use a B-tree on scope, instant and stable record ID for a point. Use GiST on scope and the normalized range for an interval, with `btree_gist` for the scalar scope keys, provisioned by BOOKING-1 slice 1a. Scope follows the record’s tenant, environment and company policy. A Calendar added later consumes the field’s index.

**A4 existing-table index (settled by the 2026-11-20 re-read).** The table is the same-plan object under ADR-0011: on a record type created by the same plan the window index is pre-approval inert, and on an existing record type it is a `createIndex` element with origin `existing`, classified `deferredOnlineFamily`. A date-time or interval field may be added to an existing record type; its index is built in the approved attempt by the locking path PR-6c established (plain `CREATE INDEX`, committed atomically with its step receipts and verified ready and valid before activation), and its checks are added as `NOT VALID` constraints that bind new writes, which earlier rows and old writers satisfy by leaving every component null. Before the build, the attempt probes the table to the ceiling plus one row under the lock it will build under, and refuses with a named diagnostic that states the type, the field and the ceiling when the table is larger. The ceiling is deploy policy outside the authored revision and release bytes, initially 10,000 rows (the probe counts the physical table; if generated tables are pooled across tenants it counts every tenant's rows together, a named limit the online-index family removes; see ADR-0089 B2), and is a conservative proxy for the 2,000 ms writer-blocking trigger in runtime-slos.md; slice 1 measures the real build at the ceiling for each index shape and lowers the ceiling if the measurement reaches the trigger. Above the ceiling the field waits for the online-index family (a resumable concurrent build outside the activation transaction), which remains deferred; v1 never admits the field without its index. A view, sort or report over the field may rely on the index from first activation and never issues DDL. [ADR-0011, transition envelope](ADR-0011-compiled-module-storage-transitions.md#transition-envelope-v1)

## Rules and other consumers

Presence is admitted for both logical types on a whole value. For example, a Scheduled job can require Appointment. Use the existing validation binding, watched fields and scoped operand rules. A malformed or unreadable value refuses. Endpoint order is intrinsic to the interval type. **Comparison to another date or time**, **maximum length** and **duration as a number** are named capability gaps. Refuse comparison operands (literal, same-record or to-one) and calculated operands and results by logical type before inspecting any backing scalar. Reserve instant comparison for timed values, civil-date comparison for date-only values, and elapsed time for timed duration. The Record displays elapsed duration for a timed interval and the normalized civil day count for a date-only one. [ADR-0074](ADR-0074-formula-rule-and-workflow-projection-admission.md) · [ADR-0076](ADR-0076-cross-field-and-to-one-validation.md) · [ADR-0077](ADR-0077-exact-decimal-calculated-display.md)

| Consumer | v1 admission at the slice introducing the type |
| --- | --- |
| List column, sort, filter and saved view | Display both types. Sort `dateTime` by stored instant with stable record ID breaking ties. Refuse interval sorting and filters on either type. Apply the same rules to `saveListView` columns, sorts and string-valued filters when saved and when loaded. |
| Metric card, workflow condition, search | Refuse bindings to either type for metrics, conditions and search terms. |
| Document template/PDF, export, API, notification and assistant | Admit authorized typed query fields for display with the no-viewer rule. Use the template’s admitted output positions. Form, API and assistant entry use the whole-value contract. |
| Reminder anchor (ADR-0088) | Admit a Date, DateTime or interval end field. Take the zone and day boundary from the field's capture, including perRecordIana. Resolve derived boundaries by ADR-0083 A1 and pin boundary-rule and tzdb versions. For a date-only inclusive interval "end" is the last entered date. Refuse only a missing zone or working-day calendar. |
| Import | Refuse mapping an import column to either type in v1. |

Each refusal identifies the logical type, field and requested consumer or operand position. Test each admitted path and each refusal through its normal entry point, including forged declarations at compilation. ## Reader admission and replay

- Compare normalized bytes, complete envelopes, roots and floors across compilers on identical first-party inputs and a real tenant runner with the same provenance and parent. Read and compare the persisted release rows. Follow ADR-0047 for compiler profile evolution. Each declaring slice takes the next mandatory surface-manifest reader rung on freshly fetched main at merge. Regenerate, run CI and re-fetch before push. Renumber if overtaken. The floor is the maximum across features. Check declaration, storage, operation/query/surface bindings and floor in both directions. Exercise the archived preceding production loader on a declaring release, including interval-only and mixed releases. Refuse missing bindings and understated floors before serving.
- Keep new parsers and rungs disabled fleet-wide until the operator records closure of the binary rollback window. Deployment must support the highest parser and reader floors any tenant has used, including after release rollback. [ADR-0085, binary admission](ADR-0085-platform-upgrades-for-customized-tenants.md#binary-admission-and-rollback-window)
- Each executable slice adds its member to UPGRADE-2’s independent, hand-written replay allowlist. Removing either must fail the vocabulary inventory by name. Check every ordered change-set member. Give each kind a named real replay test. Reproduce the source chain and roots, replay unchanged patches onto a compatible new base, read a saved value and write another through the upgraded form and query. On an occupied field ID report `FIELD_COLLISION` against the patch. On a changed bound type or scope use `INCOMPATIBLE_TYPE` or `INCOMPATIBLE_SCOPE`. The verified source keeps serving on refusal. Pointer rollback restores compatible field exposure and preserves stored values. [ADR-0085, replay admission](ADR-0085-platform-upgrades-for-customized-tenants.md#slice-1-replay-admission)
