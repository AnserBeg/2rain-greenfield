# ADR-0090. Plan work on a map and a resource timeline

**Proposed for independent Fable read · 2026-11-21 · PLANNER-1, slice 0.** The owner approved the capability. The decisions below are proposals. ADR-0086 continues to govern Board, Calendar, the resource timeline and its Booking gestures.

A dispatcher has twelve deliveries, including a pickup with no location yet. She wants to see which stops belong to the north route, put the pickup on truck 12 at 09:00 and check the finish time before committing. A service manager wants the same desk with work orders and technicians. The rentals survey entries *Dispatch board*, *Fleet, jobsite, and dispatch maps* and *Drag and drop* describe those jobs. Rain supplies the examples only. [Plan §§8–8.6](../greenfield-north-star-erp-platform-plan.md#8-surface-and-interaction-architecture) · [Surface family §12.2](../greenfield-north-star-erp-platform-plan.md#122-full-capability-families)

## 1. Draw the map on the server

In **Customize → Add view → Map**, choose a governed collection, record ID and link, label, one CONNECT-1 Address field, and optionally a group and route legs. The map is a deep-linkable **List** presentation in its existing dataGrid slot. The server draws a fixed-size static basemap with its own numbered pin and line overlay. **Fit this page**, pan and zoom are links or forms. All information and navigation work with scripts off. A bundled, CSP-hashed client library would buy smooth panning but would require client rendering and fetching for a task the static page can complete. Keep ADR-0036’s single owned script and current provider-network boundary. [ADR-0036 §§2a–7](ADR-0036-minimum-client-capability.md) · [ADR-0086](ADR-0086-board-calendar-and-resource-timeline.md)

| Choice | Display and refusal |
| --- | --- |
| Point | Read the whole logical Address through a bounded collection query. Batch the current company’s enrichment. A valid user pin takes precedence, then a matching, unexpired provider pin for the current record, field, revision and installation. Retain provenance and attribution through display. Missing, expired or incompatible points stay in the list with their permitted location state. Fit uses only plottable points. |
| Colour by group | Bind a readable choice or to-one relation by stable ID. Use a deterministic platform colour per group key, paired with a short label and distinct marker or line pattern in a legend. Use Ledger theme tokens with sufficient contrast in both themes. Reserve status roles and their glyphs for business status. An authorized null has the label **Ungrouped**. |
| Route line | Bind a route group and an optional typed **next stop** link to the same stop type. Draw a directed straight segment only for a stored edge with two permitted, located endpoints in the same route. Page overlays draw edges between displayed pins. A listed, authorized leg crossing a page boundary offers **View leg**, a bounded two-stop read with the same checks. The list names the endpoints and direction. Sorting visible stops and joining neighbors could invent a trip across a hidden or missing stop. Road routing, mileage and predicted arrival need a separate provider contract. |

Use one query result for the graphic and its visible HTML list. Give each plotted pin a matching list number and Record link. Include unlocated rows in paging, preserve filters and announce partial coverage. At **390 px** show the list first, with a labelled disclosure for the graphic, attribution and legend. Native controls and Record links have 44 px targets. Overlapping pins remain separately reachable in the list. A map background failure leaves the list, record links and paging usable.

## 2. Let CONNECT-1 own imagery and disclosure

The release names the provider-neutral connector read contract. The company installation selects its provider. Extend CONNECT-1 with a bounded static **viewport** read for a basemap, since the existing `address.staticMap` accepts a single pin. Only the host adapter resolves credentials and reaches its registered destination. It accepts viewport, zoom and size, with fixed bounds on pixels, bytes and deadline. It returns validated raster imagery, projection/extent and attribution. The ERP places the overlay in that same projection. Labels, job IDs, raw addresses, routes and ordered stop coordinates stay out of the request. Classify even the viewport as a location disclosure. A billable lookup needs the editor’s explicit request, an enabled purpose and the installation’s pre-I/O cost and quota reservation. Simply opening the planner or asking the assistant about a job cannot initiate billable fan-out. [ADR-0080](ADR-0080-connector-framework.md)

- **Google.** Use CONNECT-1’s address lookup, provenance, expiry and attributed coordinate-text rules. ADR-0080 disables Google static imagery under the host-only serving contract. Display the unavailable state and permitted text. Google-derived points are ineligible for an OSM map, its fit bounds and its lines. A proxy, a keyed browser URL or an automatic switch of provider would bypass the installation decision.
- **OpenStreetMap option.** Register a company-selectable adapter for operator-hosted OSM-derived raster tiles or a contracted source that permits same-origin delivery and overlay. Show visible OpenStreetMap contributor credit, licence link and required provider credits. Use independent user coordinates or enrichment admitted for that map. The community tile servers are outside this installation profile. [OSM attribution](https://www.openstreetmap.org/copyright) · [OSMF tile policy](https://operations.osmfoundation.org/policies/tiles/)
- **Serving and failure.** Deliver bounded, same-origin imagery. Reauthorize any image request before issuing bytes, under the same actor, company, view and fence. Keep personalized overlays and responses private and uncached. Share background bytes only as allowed by the installation, classification and source licence. On outage, disabled installation, exhausted quota or expiry, show what can still be read and label the missing layer. Apply CONNECT-1’s real-provider enablement gates. CI binds deterministic fake tiles and geocodes with network transport disabled. Test attribution, two companies using one shared asset, pin expiry, forbidden cross-provider plotting and zero credential or provider URL exposure.

## 3. Bind a timeline to the resource the company uses

Extend `addResourceTimelineViewRevision` with a versioned assignment binding. Reuse CALENDAR-1 slice 3a’s resource rows and bounded interval query. Customize chooses the resource collection and its typed key (Truck, Driver, Technician, Crew or another released record type), the jobs collection, an optional to-one resource field on the job targeting that exact key type, and an ADR-0087 **interval** field on the job. Pin query IDs, identity/revision, selected label and field contracts, granularity, zone source, end convention and view axis zone. A resource with zero visible jobs still has a row. Only a stored null resource is unassigned. A concealed link or inaccessible target cannot put a job in that queue. Restricting rows to bookable units would give an ordinary mechanic’s diary rental semantics. [ADR-0086, time windows and coverage](ADR-0086-board-calendar-and-resource-timeline.md#time-windows-coverage-and-page-budget) · [ADR-0087](ADR-0087-tenant-date-time-and-interval-fields.md)

**Assign and schedule** binds one named Semantic Operation and its exact job, target resource and full replacement interval argument roles. The compiler verifies the effect on that job’s resource relation and interval, write scope, target identity and supported field types. For ordinary customer-built jobs, slice 2 must supply a no-code path through the generated job update operation. A closed assignment binding restricts its writable operands to that pair, requires the unassigned source revision and uses the writer’s atomic validation, authorization, audit and receipt. Expose that binding as a declared assignment action in the operation catalog. Its gateway entry requires the reviewed decision even for a forged direct submission. The server checks the stored null relation and expected revision together at write time. Offer it only once that writer proves the contract. For domain packs bind an operation whose declared effect supplies those same guarantees and all pack guards. A general edit button, workflow start, pair of writes or Booking resize cannot satisfy the assignment contract. Without a qualifying writer the diary can be viewed, and Customize names the missing contract when assignment is requested. [ADR-0079, governed Tasks](ADR-0079-form-and-record-composition.md#a-button-opens-one-governed-task)

An ordinary assignment records a scheduled interval. Its Task says whether overlaps are allowed. Exclusive capacity requires a declared capacity writer that serializes competitors and rechecks the entire interval at commit. Admit that promise only when every write path affecting the commitment, including an ordinary Record edit, enforces the same capacity rule. For example, a shop can put two jobs on a technician’s morning diary, while a rental company can promise a truck only through its capacity writer. The generic diary makes no availability promise from gaps, even on a complete page. Booking keeps its own Change interval operation, actual-use legs and eligibility. A Booking layer requires the resource-window protocol and live resource and availability grants. Hidden or overdue commitments on a shared resource contribute only the pack’s coalesced anonymous busy spans across companies and page boundaries. Owner/record details and handles require separate grants. Only complete Booking unit coverage can say **Free as of** its read instant. A pool uses its quantity query. An unverified area says **Not loaded**. [ADR-0082, scheduling queries](ADR-0082-booking-over-time.md#what-the-picker-assistant-and-workflows-may-read)

## 4. Compose the desk and review one assignment

Publish a planner as a sibling List presentation. Its fixed composition in dataGrid is **Unassigned jobs**, **Map**, **Resource timeline**, in reading order. On desktop the queue sits beside the map and timeline. Bind three active child view IDs with compatible contracts. The List and map must refer to the same job identity, the queue’s null predicate to the timeline’s resource field, and the timeline to the declared assignment operation. Reject recursive compositions and incompatible scope or types at compile time. The server renders each child binding once in one shell with one context bar and right rail. Each child reports its own empty, failed or partial read. A failed map leaves the queue and eligible Task usable. A stale release or invalid company stops the whole request. Separate browser pages could disagree on company or release and could not share an offered target. [Plan §8.5](../greenfield-north-star-erp-platform-plan.md#85-binding-ux-grammar)

1. The dispatcher chooses **Schedule** beside the pickup, then truck 12 and 09:00. On desktop a drag from that same job to that row and tick submits **Open Schedule**. The existing ADR-0086 pointer behaviour in the owned script may select only server-offered job, row and tick values and submit the opening form. Ship the form first and gate the cross-view gesture on CALENDAR-1’s §2a amendment. Escape, cancellation or an outside drop submits nothing. The job stays in its committed position throughout preparation.
2. The server resolves the job’s current revision and stored owner, checks the target and asks for the finish if required. For a new interval the person enters the end. An existing interval is shown in full for explicit review or editing. For the pickup, the dispatcher enters 10:30 and sees “Unassigned → Truck 12, 09:00–10:30” with its date and offsets before confirming. A changed start never silently shifts the finish. Use the shared axis of at most **64** ticks and a form for finer times or another page. Show the zone, actual endpoints and offsets, required inputs, before/after resource and interval, and the operation’s effects. A date-only job keeps civil dates and its declared end convention. A typed DST gap refuses and a repeated hour requires choosing the offset. The axis and clipped bars supply no authoritative duration.
3. **Confirm assignment** is a deliberate yes to this operation, actor, scope, job revision, resource, interval, other arguments and release/activation fence. Editing, switching company or switching release away and back invalidates preparation. Preserve any stronger review or independent approval. The Semantic Operation rechecks live write and field grants, both record scopes, source state/revision and all guards under the writer’s concurrency control. Commit the full change, audit and idempotent receipt together. A lost response retries the same decision and key under current authority. A changed proposal requires fresh review and a new key.
4. On success, show the permitted receipt and redraw the queue, map and timeline from governed read-back. Two planners choosing the same job can produce one assignment. The other sees **This job changed**. A competing exclusive commitment gets **No longer available** without identifying its owner. Keep permitted input for correction, refresh the permitted state and require another decision. Revoked access withholds former details, even from a retry. Dropping, cancelling or going offline queues no write. The assistant uses the same plan, confirmation, receipt and verified state. An assignment authorizes no document access, message send, workflow credential or new database, network, secret or filesystem access. [ADR-0073](ADR-0073-workflow-isolate-and-authority.md#authority-boundaries) · [ADR-0078](ADR-0078-governed-documents-files-templates-and-signatures.md#assistant-and-workflow-access) · [ADR-0088](ADR-0088-governed-communications-and-reminders.md)

At 390 px stack queue cards, map/list and the resource selector with the selected row’s chronological appointments. Preserve window, filters, paging and Record links. Schedule works by keyboard or single taps with script off, including resource selection beyond the visible page. Return focus to the result or heading. On refusal focus the error and its control. A desktop-only drag would exclude the dispatcher using a phone.

## 5. Bound the read before drawing

Apply live tenant, environment, explicit company, row and field grants inside each governed Semantic Query before filters, joins, grouping, limiting or deriving pins, bounds, legends and counts. Authorize selections used only for ordering, route links or the unassigned predicate as well. Refuse the affected binding when a required field is unreadable. Return no hidden data in image coordinates, HTML attributes, cursors or assistant context. Opaque cursors bind principal, scope, policy epoch, release/fence, view revision, filters, sort, relevant viewport/window, resource page and source snapshot or revision. Reauthorize each page. Reject tampering and visibly restart a changed traversal, including on enrichment expiry. A returned cursor keeps no database transaction open. [ADR-0071](ADR-0071-read-decisions-are-live-per-request-writes-per-call.md)

| Read | Platform limit, reduced by the query’s own limit |
| --- | --- |
| Map | Page at most **100 records**, including unlocated records, in stable record-key order. Draw at most one pin and one outgoing leg per returned record. Probe one extra row for Next. Pan/zoom changes the projection of this page. **Fit this page** and the page count state precisely what is covered. |
| Unassigned List | **50 jobs** in stable job-key order, filtered to the authorized null relation before the page boundary. Its continuation is independent of the map and timeline. |
| Timeline | ADR-0086’s default 7 days, maximum 31 civil days, **20 resources**, **100 segments total**. Page resources by stable key and segments by resource, effective start and segment key. Preserve the pack snapshot or explicitly restart. Mark partial rows and later uncovered regions. |

Use scoped indexes or enforce a candidate-work ceiling before residual filtering. On exhaustion return a continuation or **Narrow the search**, never a false empty or free result. Batch labels, pin enrichment, edge targets and intervals. Meter the warm served page including shell and continuations. The whole planner and each standalone view must each fit **one** SPEED-1 budget of at most 2 database transactions, 40 statements and 3 authorization reads. Allow zero identical repeats, zero warm operation/query/manifest parses and at most one parse per distinct bound surface. Three independent page budgets would conceal repeated work. Pin measured sparse and full ceilings with flat statement counts. Measure p95 against the registered-query target of 400 ms and report cold imagery, Task writes, denials and policy-epoch retries separately. Exercise more than 100 stops and a week of hourly work on 20 resources. Observe the rendered rows, next pages, actual database work and connector calls. The warm path uses zero outbound calls. An explicit background load may make one bounded viewport request, independent of the number of jobs. ## Questions for the owner

- **Which live basemap should dispatch see first?** Recommend the OSM installation with independently entered pins. Keep Google for permitted address services and attributed text until CONNECT-1 has an accepted imagery contract.
- **Does a route line promise a drivable route?** Recommend the labelled straight leg between declared stops for this packet. Road directions and ETA would need a separately approved connector purpose.
- **May a technician have overlapping scheduled jobs?** Recommend allowing overlaps on the ordinary diary and requiring an exclusive-capacity operation when the business promises a reserved slot. Show the policy before confirmation.
