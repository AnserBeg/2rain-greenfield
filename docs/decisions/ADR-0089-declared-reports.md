# ADR-0089. Build reports from governed record queries

**Accepted pending a narrow re-read of B1/B2 · 2026-11-20.** Fable’s design read (ACCEPT WITH AMENDMENTS) is applied in [Amendments from the design read](#amendments-from-the-design-read) and in place below. B1 and B2 are re-read before slice 1 code starts; R6–R9 land before slice 2. An office worker can open **Customize → Add report** on Invoices or on a record type their company built, choose what one row represents, group it and publish the report. A colleague can run it with their own grants and export exactly the totals they can see. The rentals ERP inventory (§C) supplies the use cases for datasets, approved measures, charts and CSV. Receivables aging and customer statements in parked PR #34 are downstream examples. ## What a report declares

| Choice in Customize | What the compiler must resolve from the active package |
| --- | --- |
| Dataset | Owning record type and registered query ID, source contract, one business fact per row (grain), stable identity, archive rule, ownership, temporal basis and freshness. A source can be a generated collection or a first-party read model with verified lineage. |
| Filter | Declared, selectable operands and typed parameters. Start with equality, membership from a bounded choice list, and half-open date ranges. Combine them by AND with the source restrictions. The author can expose parameter inputs and narrower saved presets. |
| Group | Ordered, reportable dimension IDs. Group choices and references by stable value ID, with authorized labels for display. An optional absent dimension has a labelled **Unspecified** group. Calendar and age dimensions declare their source and boundary rules. |
| Measure | Stable measure ID, label, source query and grain, operator, operand selections, unit/currency binding, absence and result contract, permitted sinks and lineage to stored facts. The compiler derives types and verifies the whole dependency set, including derived inputs. |
| Presentation | Title, ordered group and measure columns, initial sort, eligible outputs and drill-through to a governed List with the same predicates. A chart binds axes/series to typed result columns. Customer data can configure only platform-owned components. |

The existing reporting projection lists reportable fields and their lineage. The current Q1 aggregate is a scalar required sum. Extend the **existing** reporting, query, policy, surface, agent and verification projections with an optional versioned report definition and a registered grouped Q1 query. The gateway returns a distinct grouped result with typed keys, cells, per-partition totals, coverage, read instant and continuation. A group has no business-record ID or revision. The scalar contract and row List keep their existing envelopes. Feed the compiler’s closed lowering plan to the provider using bound parameter values and catalog-resolved identifiers. Refuse fields with an unsupported lowering, classification, display-only sink or unavailable index during preview. [ADR-0022](ADR-0022-query-level-aggregate-contract.md) · [ADR-0074](ADR-0074-formula-rule-and-workflow-projection-admission.md) · [ADR-0077](ADR-0077-exact-decimal-calculated-display.md)

An approved measure can be reused by stable ID and contract revision. A business author can propose one from the same finite operators and reportable operands, preview its definition and trial it on authorized data. The publish diff shows the basis (for example, invoiced rent versus cash collected), grain, date, units, exclusions and consuming reports/cards. Human approval covers the exact candidate. Editing the measure produces a new revision and requires reverification of its consumers. Discovery offers only measures in the serving release whose dependencies and purpose the person may read. A prose request or display format cannot declare that a number is money. An existing invoice amount needs the authoritative amount/currency binding defined in [Amendment B1](#b1-amounts-and-currency). A tenant-built Inspection can start with count by outcome using its existing choice field.

## What contributes once

Slice 1 uses one source record per fact. A later report may traverse declared to-one links. A line report explicitly chooses **one row per line** and a declared, scoped parent relation. Verify target uniqueness, key types, cardinality, source permissions and owner scope at each hop. Collect authorization even for a field used only in a filter. An optional missing relation yields absence under its declared semantics. An unreadable target supplies neither a value nor evidence of its existence. Refuse a join if its scoped semantics cannot be proved. A parent amount can contribute only at parent grain. Refuse counting a parent sum once per line, sibling line joins, inferred text matches and other paths that multiply the measured fact. Distinct count of a declared parent identity at line grain is an explicit measure. A domain balance comes from its governed read model. [Query and authorization guarantees](ADR-0071-read-decisions-are-live-per-request-writes-per-call.md)

| Operator | Group and total semantics |
| --- | --- |
| Count | Count rows at the declared grain. Empty input gives zero. |
| Sum | Sum an exact decimal, quantity or governed amount that carries the B1 amount/currency binding (or a required exact decimal with a fixed unit). Rows without the amount are excluded and counted in a visible coverage figure. Preserve scale, unit and currency. A known empty partition has typed zero. An empty result invents no currency. |
| Min / max | Take the least/greatest present comparable typed value. Return tagged absence when there is none. |
| Average | Carry the exact sum and count of present numeric inputs per partition. An empty denominator gives tagged absence. Expose an exact ratio for a repeating decimal. Any rounded display needs a declared display precision and rounding rule in the measure and keeps the exact ratio in evidence. |
| Distinct count | Count distinct present typed values at the requested grain. Use canonical identities for references. Empty input gives zero. |

Partition every money measure by the currency supplied by the source contract (fixed canonical currency or a validated stored currency selection on that fact). Use the same key for grouped rows, totals, charts, prints, CSV and card drill-through. Make each partition visible even when the author omits Currency from the layout. Apply the same rule to incompatible quantity units. Reject incompatible partition bindings within one report, malformed operands and precision overflow. A monetary fact with no valid currency is never rejected as a run and never dropped: it forms its own labelled **No currency** partition (B1). Compare the provider output with a reference evaluator on signed, fractional, empty and boundary values. Compute totals from the full admitted fact set at its grain. Averaging group averages or adding group distinct counts would change the answer.

For day, Monday-based week and calendar month, use civil dates. The zone and day boundary are the **working company’s** business calendar (R2), and a civil-encoded date is never zone-converted (R1). Capture the business date and calendar once per run and show them on every output. Resolve the endpoints of **last month** independently through calendar boundaries. Age is the difference in civil days between the declared as-of business date and a due date. Band edges and labels are author-declared data (R6). The default proposal is **Not yet due**, **0–30**, **31–60**, **61–90**, **91+**, and **No due date**, so 90 belongs to exactly one band. Age classifies balances at the source’s own horizon. A request for last month’s outstanding balance requires a query supporting that historical horizon. Current balances alone can only answer current exposure. ## Who can read or export

Companies in one tenant/environment share the active report definition. Each run binds its own working company. The gateway resolves the trusted tenant, environment, principal, verified release/fence and permitted working company. The shell’s explicit company selection must be authorized. Derive ownership, customer, currency, revision and join keys from stored facts or their authoritative read models. Apply tenant/environment, company, parent, archive and live row policy **in the provider before grouping or counting**, on every participating input. Use tenant-shared sources only according to their declared ownership. A shared party link cannot admit another company’s invoices. Resolve effective field, classification, aggregate and export policy on every request, including filter, sort, currency, bucket, group, label, measure, join and drill-through dependencies. If a required binding is narrowed, withhold the dependent report in full and give a generic unavailable response. Omit it from discovery and cards. Denials, errors, CSV headers, chart legends and assistant evidence must also honor field narrowing. [ADR-0015](ADR-0015-legal-entity-business-dimension.md) · [ADR-0071](ADR-0071-read-decisions-are-live-per-request-writes-per-call.md)

Use one authorized read-only snapshot per request. Check the live policy epoch and serving fence before returning any bytes. Reauthorize each page, drill-through and export. A switch away and back changes the fence. A saved view, cursor, cached result or earlier approval confers no grant. Exports require both report read and the applicable export grant. Assemble the complete bounded output first. Commit a scoped audit receipt under current authority before handing bytes to transport. Bind the actual actor, scope, fence, report/measure revisions, canonical parameter digest, read horizon, output format, row counts and exact output digest. A failure to record the receipt withholds the file. The receipt records issuance, even if the network disconnects. A fresh download reauthorizes. Use the existing trust path or a scoped function for this append. Any new definer function fixes its search path to `pg_catalog, pg_temp`; grant the runtime only the necessary function execution. [ADR-0078](ADR-0078-governed-documents-files-templates-and-signatures.md)

## How a run is bounded

Proposed slice 1 ceilings per invocation are **10,000 input facts, 500 groups including currency partitions, 50 groups per page, 2 MiB serialized output and a 2-second database statement timeout**. These numbers are platform **reader policy** (R3). Apply the stricter of platform, registered query, export and policy bounds. The grouped query declares input-work and output limits separately. Budget all statements and retries under a 5-second monotonic request deadline. Check capability, parameter types/sizes, requested limits and plan shape before execution. Allow at most four group keys and eight measures, and bound selected field widths at compilation. Slice 2 may traverse at most two declared links, with at most one line collection establishing the grain. A later joined plan must account for visited rows across every input and intermediate, including rows rejected by residual predicates.

Push the trusted ownership scope into the index range wherever a company-leading index exists (B2 names which tables). Use an indexed scope/range scan with a cap-plus-one candidate probe **before** expensive residual filters, grouping and distinct work. The probe counts candidates after company scope. Apply authorization inside the query and release only complete authorized results. Count groups to their cap plus one before paging. A final SQL LIMIT on a grouped output would leave the input unbounded. On an exceeded scan, row, group, byte or time budget return **Narrow the filter** without counts, partial rows, totals or downloadable bytes. Omit hidden filter suggestions. Exercise the exact boundary and the next fact/group. A selective predicate over too many candidates must also refuse within budget.

At compile/prepare time list the required indexes and the reason for each. For a company-owned date-range report the candidate path is a company-leading index: equality on physical tenant, environment and company, then the stored date or the stable record ID (B2 says how it is built). A to-one lookup needs a scoped unique target key. Line traversal needs an ordered scope/parent/line key. Bucket after selecting the bounded date range. Derive keys from the storage mapping and verify actual index definitions and validity before activation. Build an index on a new managed table via its compiled storage transition. On an existing table use the ceiling-bounded locking build of B2, and above its ceiling refuse by name until the online concurrent-build family exists. Report execution cannot issue DDL. At launch-shaped cardinalities, observe the intended index actually used and the bounded work in PostgreSQL, including the probe with the index removed. [ADR-0011](ADR-0011-compiled-module-storage-transitions.md) · [ADR-0022](ADR-0022-query-level-aggregate-contract.md)

Order groups by a deterministic typed tuple with explicit absence order, collation and complete group/currency key as tie-breaker. Keyset pages seek strictly after that tuple. Each request recomputes the bounded complete authorized result in a fresh snapshot. Hash the ordered canonical keys, visible labels, cells and totals across all pages; keep the wall clock of the new request outside that comparison. Bind the opaque authenticated continuation to principal, tenant/environment/company, report revision, release/fence, policy epoch, filters, captured dates, order and digest of that complete result. On change, expiry or tampering require a fresh traversal. No transaction spans page requests. Totals accompany each page with their full scope labelled. CSV, chart and print consume the same complete bounded result or refuse. An export launched from a displayed result must detect a changed result and offer refresh before exporting it.

## How people use the result

The report opens as a deep-linkable grouped **List** in the owning module. Saved views are tabs with validated parameter presets and presentation choices. They can narrow the declared query. Desktop Customize provides the properties drawer, preview and publish diff. Compact renders group cards, currency-labelled totals and ordinary paging links. A chart has a labelled data table reachable with script off. A bar compares groups, a line needs an ordered dimension, and a stacked bar needs additive series with compatible units and currency. Separate currency panels prevent a visual combined total. CSV identifies group and total rows, quotes cells and neutralizes spreadsheet formula text while preserving signed typed numbers. A printable report includes company, customer filter where relevant, basis, horizon, currency, authorized detail and totals. Printable statement detail uses the declared invoice-grain drill-through under the same snapshot and budgets. An issued file uses the export authority and audit path. A DOCS-1 template may consume only these authorized bindings. [UX grammar](../../.agents/skills/ux-grammar/SKILL.md) · [ADR-0079](ADR-0079-form-and-record-composition.md)

A report-backed Today card binds a report ID, compatible revision, saved view/parameters, approved measure ID and partition selector. It reads the full report total under the viewer’s live grants. A multi-currency card shows labelled totals or asks for a currency if it requires a single number. Its link reopens the same report, company, parameters and period. A bound measure that changes meaning requires a new reviewed binding. Keep existing direct-List metric cards working. For “how much did we rent last month?”, the assistant discovers the declared basis, asks for clarification when several measures fit, then invokes `erp_query` with the report query ID and permitted time parameters. Show basis, company, exact window, currencies, freshness and a link to the same view. If a measure or historical source is missing, explain the capability gap. The typed gateway accepts no raw SQL or model-authored joins. [Plan §§9.2 and 10.2](../greenfield-north-star-erp-platform-plan.md)

## Admission, replay and build order

Propose a closed, versioned `addReportRevision` patch member (R5 spells its unions) with tenant-namespaced stable report ID, new revision ID, predecessor digest (absent only on creation), status and full effective definition. Rename or edit appends a successor. Retirement appends a tombstone and removes discovery and execution, including direct links. Prevent reuse of a retired ID. Propose separate versioned members for reusable measure revisions and report-card bindings when their slices ship. Each uses a stable ID and expected predecessor. A report may bind a reviewed measure from its own change set or a previously released one. Reject dangling dependencies unless their consumers are revised or retired in the same ordered change set. Preserve the original bytes and audit history. Preview the source, measures, grants needed, outputs, index plan and dependent changes. Verify the exact candidate, obtain human approval bound to its decision digest and current source fence, then activate by CAS. Compatible pointer rollback recovers the previous definitions under current grants.

Use optional nonempty v6 declarations (R4 rules the query branch rides v6 as an optional key). Bidirectionally verify declarations, compiled query/lowering, reporting metadata, all elected consumers and mandatory Surface reader floor. Exclude default keys, references, empty artifacts and new floors when declarations are absent. Against identical parents, reproduce a historical first-party lineage and a real tenant-customized lineage with no reports through production compile/persist/load. Read back and compare the revision’s stored `app_package_revisions.desired_state`, the full set of linked `release_artifact_blobs.canonical_bytes` (chunks and manifests), the reconstructed release envelopes, roots and floors byte for byte. For each newly incompatible capability, fetch main at executable merge and take its next free scalar rung. Recompute the maximum across *all* present features, regenerate and rerun CI on collision. Test the archived preceding **production loader** on persisted releases with and without the feature and test an understated manifest with the current verifier. Binary deployment respects every tenant’s highest used parser and reader even after pointer rollback. This design allocates no rung or migration. [ADR-0074](ADR-0074-formula-rule-and-workflow-projection-admission.md) · [ADR-0085](ADR-0085-platform-upgrades-for-customized-tenants.md)

Admit each new patch kind independently in the handwritten replay allowlist. Recursively check ordered change-set members. CI must name any vocabulary kind lacking admission. Reproduce original roots from retained bases and recorded inputs first. Exercise a compatible base addition and a real scoped conflict per kind, including a retired measure dependency or changed query grain. Preserve the verified source on refusal and identify the patch, stable subject and typed diagnostic. Do not repoint by label. If existing v6 meanings or required keys must change, return for a language ruling. A projection change for identical normalized input follows ADR-0047’s compiler-profile rule. ## Amendments from the design read

Fable’s design read of this ADR (ACCEPT WITH AMENDMENTS, blocking B1 and B2, required R1–R9, nits N1–N5) is applied below. Where an amendment changes a sentence above, the sentence has been edited in place. B1 and B2 await a narrow re-read before slice 1 code starts.

### B1. Amounts and currency

- **The binding.** A source contract may declare an **amount/currency binding**: one exact-decimal field and one currency field. The currency field is validated against the closed currency list, and the amount’s scale must equal that currency’s minor unit. A fixed canonical currency may stand in for the currency field.
- **Add-only.** The binding is an optional, add-only key with its own byte-identity proof and its own reader rung. Sources that do not declare it are byte-identical to before.
- **First-party Sales.** Adding the binding to Sales (Invoice) is a first-party base move, replayed against customized tenants under ADR-0085. Marking Invoice fields reportable is a first-party authored change in slice 1.
- **Tenant fields.** Tenant-built fields may use the same binding. Tenant-added fields are optional by construction, so the optional amount is the normal case.
- **No amount.** A fact with no amount is excluded and counted. The table, CSV, print and card all show a visible **N records without <measure>** coverage figure. Nothing is skipped silently (ADR-0021).
- **Amount without a valid currency.** The fact goes into its own labelled **No currency** partition. It is never merged into another partition and never dropped.
- **No whole-run refusal.** None of these cases refuses a whole run.
- **Reportability.** First-party fields default to `reportable: false`. Tenant-added fields default to `reportable: true`.

### B2. Access path

- **Existing tables.** A report’s index on an existing table uses the same ceiling-bounded locking build that [ADR-0087](ADR-0087-tenant-date-time-and-interval-fields.md) A4 adopted. That is a PR-6c `deferredOnlineFamily` `createIndex` in the approved attempt. The attempt probes the table to the ceiling plus one row under the build lock. The ceiling is deploy policy outside the release bytes, initially 10,000 rows. Above it, refuse by name until the online concurrent-build family exists. A report never issues DDL.
- **New record types.** Every new record type created from now on gets a same-plan company-leading index: tenant, environment, company, then the date or ID.
- **Named indexes.** Each slice-1 fixture (Invoices and the tenant Inspection) names the actual index it uses in its proof.
- **Missing or invalid index.** A missing index is refused at preview and at activation, naming the keys. At run time, an index that has become invalid is a typed **unavailable**, never **Narrow the filter**.
- **Probe.** The cap-plus-one probe counts candidates after company scope. The refusal must be identical whether the over-budget rows are readable or hidden. The probe is a coarse volume signal about rows the reader cannot see within the reader’s own company. That residual signal is accepted and recorded here.

### R1. Temporal basis

The source contract declares each temporal field’s basis: civil date, instant, or an ADR-0087 typed value. A civil-encoded instant (midnight UTC for a calendar-date entry) is read as its UTC calendar date with no zone conversion. An undeclared `instant` used for a date filter, bucket or age refuses at preview. This applies to slice 1 date-range filters too.

### R2. Zone

The zone and day boundary are the working company’s business calendar, captured once per run and shown on every output. For ADR-0087 per-record-zone values the report axis zone is the company calendar for instants and the entered civil date for date-only values. ADR-0087 v1’s refusal of filters and metrics on date-time and interval fields is a current gap.

### R3. Limits are reader policy

The 10,000 / 500 / 50 / 2 MiB / 2 s / 5 s numbers are platform reader policy (ADR-0086). They change without recompiling or changing a release byte. Only grammar bounds (four group keys, eight measures, two links) are compile-time. A released report may declare a stricter bound, never a looser one.

### R4. Profile and result versions

The widened aggregate profile is **query-aggregate-profile/v2**, with a distinct **grouped result contract v1**. Grouping, count and amount sums widen closed unions, following the enum-widen precedent. The grouped query branch is an **optional v6 key under ADR-0047 §7**, not a language event, while no existing v6 meaning or required key changes. The compiler **derives** the registered grouped query from the report definition, so no author writes a query, and it carries ADR-0031’s company scope operand.

### R5. Patch member shape

From slice 1 the member carries its own `schemaVersion` and discriminated `{kind, ...}` variants for source (generated collection | read model), filter operand, dimension (direct | calendar | age | link later), measure (inline | approved-measure reference later) and output (table | csv | chart | print later). An unknown variant refuses the whole patch, including inside a change set, before any edit. A new variant takes a bumped member version and its own reader rung. New parsers and rungs stay disabled until the binary rollback window is recorded closed (ADR-0085, ADR-0087).

### R6. Aging and customer accounts

- **Column dimension (slice 2).** A bounded COLUMN dimension over a finite, author-declared set (age bands, choice values). The cap counts rows, not cells.
- **Bands.** Edges and labels are author-declared, ordered and contiguous, validated for gaps and overlap.
- **Multi-source (slice 3).** A multi-source combination at customer grain. Each source is scoped, bounded and authorized separately. Sources merge only on an identical typed key. This covers customer accounts.
- **Named gap.** An activity statement (opening balance, payments, running balance) is a named gap. Slice 3’s statement is an open-item list.
- **As of.** An as-of date other than the run’s captured business date refuses unless the source declares a historical horizon.

### R7. Reference group keys

A group key over a reference needs a declared relation. A text field without one groups as text only. Unreadable targets fall into a single labelled **Restricted** group carrying their combined cells. It never shows the stable ID and is never folded into **Unspecified**.

### R8. Empty groups and averages

Finite dimensions (bands, choices) emit zero rows for empty members, with typed zero or absence. References never do. Average defaults to half-even rounding at the operand scale, or at the currency minor unit for amounts. Totals of averages are recomputed from sum and count.

### R9. Cards and assistant under refusal

A report-backed card or assistant answer that hits a bound, a withheld binding or a retired revision shows the typed state (**Narrow the filter** or not available), never zero or a stale number. Today has a per-page budget for report cards, because each card may spend the 5-second deadline.

### Nits

- **N1.** Consolidated multi-company runs (ADR-0015, ADR-0031 scope sets) are excluded because each run binds one working company. This is a named later gap.
- **N2.** A saved view or deep link to a revision removed by pointer rollback returns the typed **View not available** with a link to the permitted List (ADR-0086).
- **N3.** Every page recomputes the whole bounded result and compares a digest. This is correct and bounded. Implementers must not add a cross-request cache, because it would carry grants.
- **N4.** Slice 3 prints through the platform print layout only. Whether a DOCS-1 template can repeat over group rows is not decided here.
- **N5.** The 91+ label stands (the charter’s 90+ was wrong). The packet’s eight-date fixture is kept.
