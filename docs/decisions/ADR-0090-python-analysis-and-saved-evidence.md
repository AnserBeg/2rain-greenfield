# ADR-0090. Run Python on an authorized snapshot and save the finding

**Proposed, 2026-11-21.** The owner approved the ANALYZE-1 charter. The orchestrator's independent Fable read and ruling come before implementation. The ADR number is provisional until merge.

A buyer asks, “Which parts are likely to run short next month?” She chooses her company's receipts and issues, reviews the Python, and runs it. She saves the quantities, a chart and the assumptions behind the forecast. A colleague can inspect the same evidence and reproduce Tuesday's run after Wednesday's receipts arrive. A dispatcher can use the same facility to compare delivery sequences from an authorized stop list and travel-time matrix. Neither analysis needs to change a stock balance or publish a route.

## 1. Analysis produces evidence

REPORTS-1 owns the governed catalog of reusable datasets, measures and declared reports. An analysis can consume a catalog result where the query can account for every contributing source. Its own List shows saved analysis versions beside declared reports, labelled with their author and read instant. A forecast remains an estimate with units, assumptions and a method the reader can inspect. Business totals need the catalog's grain, currency and coverage contracts. That rules out registering arbitrary Python as a catalog measure.

This is the N5 analysis workspace. FORECAST-1 and ROUTES-1 may supply Python recipes with typed inputs and evidence outputs. A future callable extension inside an operation stays on N7's N2 pure-compute host with zero host grants. Reject a Python workflow SDK, connector credentials and a Python posting plug-in: the plan gives live business effects to named Semantic Operations. The rentals survey's examples of inspecting a result, reviewing a proposed measure and scheduling a repeat informed the workflow. Rain supplies no executable, data or service. ## 2. One sealed input per run

The snapshot builder resolves the signed-in person, tenant, environment, authorized working company and verified release/fence at the Semantic Query gateway. It admits only release-registered queries with typed bindings, stable row identities and complete authorization lineage. Read all sources and pages in one read-only, repeatable-read snapshot. Capture the read instant, source horizon and company calendar there. Use stored ownership, scoped parent/row predicates and current field, classification and analysis/export permissions **before** data leaves the provider. Omit unreadable optional fields from schema and bytes. Refuse a hidden required field, filter or join dependency, missing lineage, partial page set or incompatible horizon. Seal the capture before releasing the read transaction. Recheck the live policy epoch and release fence before releasing input to a worker and again before returning even a private trial result. A store that cannot participate in the same read snapshot is ineligible.

Start with at most four sources, **20,000 rows and 8 MiB of canonical uncompressed input across the run**, with a five-second monotonic capture deadline. Enforce source-specific lower ceilings and provider scan bounds. Probe one past the limit and count bytes as they stream. On overflow discard the whole capture and ask for a narrower date range. Give the same response for a policy refusal wherever names or counts would reveal hidden data. Reject silently taking the first page: a forecast over half a month could look plausible.

Keep ordered, typed values (including exact decimals, units, currency and nulls) and a host-owned manifest. It binds scope, release root/fence, read instant, query and contract IDs, normalized parameters, order, contributing record identities/revisions and every field dependency, including fields used only for selection. An aggregate needs the lineage of its contributors even when Python sees just one total. Cap the private lineage at 4 MiB and refuse an incomplete proof. Hash the manifest and exact payload with SHA-256 using a versioned, length-delimited encoding. The guest receives only the admitted data, safe column IDs and analysis parameters. Internal policy evidence stays with the host.

**Repeat these inputs** verifies the retained bytes and pins before launch and checks the caller's current access to the original sources. **Refresh with current data** captures again under the current release and grants and shows a new read instant. Store a private snapshot with its report under the same tenant/environment/company, encrypted storage, quota, backup, hold and retention controls. An unsaved run expires after 24 hours. For a saved version retain its snapshot while the version is retained. Refuse an original-input repeat if the capture, compatible contracts or allowed image are unavailable. Reject reconstructing Tuesday's input by filtering today's rows on a timestamp: a corrected row can have the same business date. [Live read decisions](ADR-0071-read-decisions-are-live-per-request-writes-per-call.md) · [Document retention](ADR-0078-governed-documents-files-templates-and-signatures.md#record-links-versions-and-retention)

Offer Python typed tables. If the author chooses a SQL transform, the host validates and executes one bounded read-only SELECT (including an admitted CTE) **inside an isolated worker over that snapshot only**. Resolve explicit columns, tables and functions against the authorized snapshot manifest, bind values, require an outer numeric LIMIT and cap rows, bytes and elapsed work during execution. Use an immutable, read-only local SQLite input, an engine authorizer and disabled extension loading. Refuse writes, attach, pragmas, file functions and multiple statements. Revalidate at execution. Reject a database SQL endpoint: a valid SELECT would still bypass Semantic Query row and field policy.

## 3. One disposable Linux container per run

A dedicated rootless launcher starts a fresh, non-root CPU-only OCI container from a locally admitted image digest. The credentialed API hands it bounded input through a narrow job protocol. The guest has a read-only root and input, one 128 MiB scratch tmpfs (including temporary files and library caches), private namespaces, dropped capabilities, no new privileges and a syscall policy denying sockets. Disable networking, inherited descriptors and environment, host directories, devices other than minimal private runtime devices, and access to any runtime socket. Supply only fixed locale, zone, seed and library settings. No database client credential, connector key, package installer or host shell is available to the job. A failed isolation or cgroup preflight refuses the run. Reject a Python import blacklist or a process inside the ERP server: native scientific libraries execute outside Python's language checks. [Rootless containers](https://docs.docker.com/engine/security/rootless/) · [Network isolation](https://docs.docker.com/engine/network/drivers/none/)

| Enforced by the host | Initial ceiling per run |
| --- | --- |
| CPU, memory, processes | One CPU, 60 aggregate CPU-seconds, 1 GiB RAM including scratch, zero swap, 32 processes/threads. One numerical-library thread by default. |
| Time and concurrency | 90 seconds by a monotonic supervisor clock. Two live containers per 16 GiB host, one per person. Use the same limits on CPU-only CI. |
| Output | 4 MiB total framed results, including charts, plus 64 KiB combined diagnostic streams. Cap input code at 64 KiB. Bound bytes as received, before parsing or buffering. |

The supervisor terminates the entire container on cancellation, deadline, quota failure or excess output. Verify teardown, discard partial output and erase scratch before releasing the slot. After restart reconcile named jobs against their leases and reap abandoned containers. A platform operator can disable all runs or revoke one image digest, and a tenant administrator can stop their tenant. Fence new and queued starts, terminate matching active runs and check the stop generation again at publication. A late result cannot restore a cancelled job. Reject a switch that only hides the Run button: scheduled work and already running jobs would continue. [Resource constraints](https://docs.docker.com/engine/containers/resource_constraints/)

Use one reviewed Linux/amd64 CPU image with CPython 3.12. The proposed first image pins pandas 2.3.3, NumPy 2.3.5, SciPy 1.16.3, statsmodels 0.14.5, scikit-learn 1.7.2, Matplotlib 3.10.7 (Agg) and OR-Tools 9.14.6206. These cover tables, time series, fitting, charts and vehicle routing on the same host. At image admission pin the exact interpreter/base digest, wheel versions and hashes including transitives, fonts, launcher protocol and final image digest. Build and smoke-test the complete lock on the target CPU with the limits above. Record the verified digest in the platform's allowed image profile before it can run. Reject mutable tags, user wheels and run-time installs: the exact executable and native dependencies must be identifiable months later. Updates produce a new profile and revocation can disable any old digest. [Hash-checked installs](https://pip.pypa.io/en/stable/topics/secure-installs/) · [scikit-learn release](https://pypi.org/project/scikit-learn/1.7.2/) · [OR-Tools release](https://pypi.org/project/ortools/9.14.6206/)

Pin code bytes, parameters, snapshot, image/platform, seed, single-thread settings and calendar in the receipt. Compare the digest of canonical tables, decoded chart pixels and finding text on a repeat, excluding issuance metadata. Show **Matched** or **Different result** with a link to the original, and preserve both receipts. A script can consult a clock or ignore a supplied seed. Reject claiming a match from identical input digests alone.

## 4. Save a version under Documents and recheck every source

The host accepts a closed stream of typed tables, static PNGs and plain UTF-8 findings. Allow up to eight tables (1,000 rows × 32 columns each), four images (at most 2 megapixels each) and 32 KiB of findings, all within the run's aggregate output cap. Validate lengths and types, decode images under resource limits and re-encode clean pixels. Escape all text. Refuse malformed results as a unit. The collector reads framed bytes only. Reject a directory of guest-named files, active formats and serialized Python objects: a host reader or a colleague's browser would otherwise interpret guest-controlled content.

**Save report** is an idempotent Semantic Operation. It creates a company-owned analysis record and an immutable DOCS-1 version, or appends a version to the authorized record at its expected predecessor. Admit a versioned, **internal, generated-only analysis evidence** content type through DOCS-1's content-policy adapter. The host encodes the validated tables, cleaned images, text, exact Python bytes and snapshot digest into one canonical bounded envelope. Bind the version to the snapshot handle, private source manifest and run receipt in the same commit. Bind recipe revision, actual actor, input and output digests, image/lock, parameters, read instant and release. The complete envelope must fit DOCS-1's size limit and pass a clean verdict on its exact bytes. Restrict this content type to the analysis publisher. Generic upload, template, signature, connector and customer-link paths cannot publish or disclose it. This requires a DOCS-1 reader/content-policy extension in slice 2. Reject calling arbitrary JSON an existing PDF type or keeping a second report blob store. [Documents content and version policy](ADR-0078-governed-documents-files-templates-and-signatures.md)

The version, retained snapshot and private lineage count against the DOCS-1 tenant/environment stored-byte quota (initially 100 MiB), with private staging under its separate quota. Reserve the actual bytes transactionally with publication. Record the run and request key so a timeout after commit returns the same version under fresh authority. A conflicting retry or failed scan, revoked grant, changed release fence or kill generation discards the pending publication. Restore checks digests, scope, holds and purge receipts before serving.

New reports are private. Sharing grants a named internal colleague access to one exact version. Require the sharer's share/disclosure grant and check the recipient at grant time. On **each** list, search, activity, metadata, preview, chart, download, secondary link, assistant access and rerun, intersect the report/version grant, governing record, working company and the viewer's live right to see **every original source, contributing row and field**. Resolve lineage via governed queries using stable identities and current restrictions for the historical data. If the provider cannot prove access to that version of a fact, withhold the entire result. Check byte/export authority and live policy epoch before the first response byte. Enforce the source restriction in DOCS-1 itself, including generic version reads. Apply the same check to private previews, code and logs. A transfer to another company, a hidden cost field or a single unreadable contributor removes the title, count and bytes from that viewer's reach. Reject filtering the rendered report or trusting the original author's role: a number or one pixel can encode any input.

An authorized reader may open a **prefilled Task** for an operation bound at recipe publication. The server resolves its stable ID, pinned contract, current target, scope, grants and allowed input positions. Treat suggested ordinary values as untrusted, editable proposals labelled with their source. Never prefill protected Tier B dependencies, authority or approval evidence. The person reviews the operation's own effects and confirms as its contract requires. Opening or saving a report has zero business effect. Reject feeding a solver result straight into dispatch or purchasing. [Record actions and Task inputs](ADR-0079-form-and-record-composition.md#a-button-opens-one-governed-task)

## 5. Author and run through the same governed path

Use Customize for a reusable recipe, a server-rendered Task for a private trial and the existing List and Record for saved evidence. The assistant writes an analysis body using permitted query/field IDs, types and synthetic examples. The author can inspect and edit the entire Python source in a plain textarea. Show the exact code/diff, selected sources, company, parameters, read mode, resource limits and maximum charge before a live-data run. An affirmative **Run this code** binds the exact code and contract digests, source selections, parameter values, original snapshot digest or explicit fresh-capture choice, release/fence and person to one run. Edits need fresh review. Permit a one-off private trial of a validated draft through this same path. Reusing a recipe across people or on a schedule requires human approval of its published revision. Sharing the evidence grants no execution authority. With JavaScript off the Task submits, status refreshes by link and the full report renders. Reject a browser notebook, a second script or guest-supplied chart code. [Minimum client capability](ADR-0036-minimum-client-capability.md) · [Server-rendered fallback](ADR-0086-board-calendar-and-resource-timeline.md#one-document-script-and-an-equivalent-form)

The assistant can draft and request that reviewed run. The host enforces a narrow tool contract. Keep snapshot rows, logs, generated charts and findings out of the drafting/model prompt in v1. The Python computes the written finding from its inputs. Display its output to the person as attributed evidence. Treat even a catalog label, code comment or message saying “send this report” as untrusted data. Text cannot authorize a tool call, disclosure, grant change or follow-up run. Error feedback to the drafter uses host-owned codes and sanitized schema diagnostics. Reject an autonomous code/repair loop or sending raw rows to a model provider: both would expand what one approval discloses or spends. [Prohibited agent paths](../greenfield-north-star-erp-platform-plan.md#925-prohibited-agent-paths) · [Connector authority](ADR-0080-connector-framework.md)

Apply both tenant and person budgets across environments for that tenant, including private trials, failures and scheduled occurrences. Start with **20 starts/person and 100/tenant per UTC day**, one active run/person and two/tenant, further limited by host capacity. For analysis model calls start at **USD 1/person and USD 5/tenant per UTC day** with a USD 0.25 maximum reservation per call. Tenant policy and existing agent limits may narrow these ceilings. Compute-only repeats spend a run slot but have no model fee. Reserve both budgets atomically before a new start or model call. Bound tokens using trusted prices, refuse unknown cost or exhausted limits, settle actual usage, and hold an uncertain charge for reconciliation. Stable request keys prevent duplicate charges or launches on retry. Record initiator, sponsor, scope, counters and decision without raw rows or logs. Reject charging only successful saves: a failed script can use the whole CPU allowance.

## 6. Publish stable choices and prove compatibility

Require a per-member `schemaVersion` and closed payload variants, including for retirement. `addAnalysisRecipeRevision` records the stable recipe/revision IDs, expected predecessor, active or retired disposition, source/query IDs and pinned input contracts, selected field IDs and types, parameters, exact Python bytes/digest, image profile and typed result contract. `addAnalysisReportBindingRevision` binds a recipe to the governing record, document content contract and optional named Task operation and input positions. `addAnalysisScheduleRevision` binds a published recipe and report binding to a workflow schedule with a stable ID. The schedule carries recurrence and scope requirements. A person's consent, spend limits and credentials are never patch operands. Editing or retiring appends a revision. A single verified release selects the active revisions. Unknown members or variants, stale predecessors, collisions and dangling active references refuse the whole ordered change set.

At authoring bind stable choices once. Reproduce historical roots and check recorded digests exactly on the authoring base. Elsewhere validate the stored choices structurally against the new base, including input types, scope/grain and allowed output/operation contracts. Labels render from the active release. Report a lost source/field/operation by ID (`RETIRED_TARGET`) or changed contract by ID (`INCOMPATIBLE_TYPE`), keeping the verified release serving. Only the final active revision needs live bindings. Verify identity and predecessor for retired/superseded revisions. Release rollback restores the earlier bindings, stops new work under removed recipes and preserves existing versions under their recorded restrictions. Reject deriving the recipe again from today's List columns: adding an unrelated field must work with a recipe both active and retired. Check declaration and projections in both directions. Each incompatible capability, including a stored type or optional parsed key, takes its own next free scalar reader rung at its executable merge. Fetch main, allocate, regenerate, re-fetch and renumber on collision. Forward migrations follow the same rule. At each step the actual preceding serving binary must answer a featureless query and refuse the feature-bearing release by name before service. An older parser rejects the member inside a change set before edits. Honor the rollback window and fleet parser/reader high-water marks.

The visual builder and in-app AI emit the **same ordered change set** with the same plain diff, verify, human approval, activation and rollback. Ship schema-generated drafter vocabulary, a live AI-BUILD-1 success and refusal case, and independent fail-closed replay and drafter inventories for **each** new member in the slice that introduces it. Cover a compatible relabel/addition and a lost binding per member. Slice 3 improves interactive Python authoring. It cannot postpone the rule-12 drafter for slices 1 or 2. Reject a parallel AI recipe registry: an upgrade must replay the exact intent a person approved. ## 7. Schedule a fresh version through the workflow scheduler

An authorized person opts in for one published recipe revision, company, parameters, destination report, recurrence, IANA zone, expiry and resource budget. Use the workflow scheduler's durable timer and journal. Derive the occurrence key from tenant, environment, company, schedule ID and scheduled instant. Carry the schedule revision and consent digest in the occurrence. Treat a schedule-bearing release as workflow-bearing for Manual activation. Record the sponsor and activation approver. At claim, capture and publish, intersect the bounded automation actor, sponsor's live grants, activation authority ceiling and explicit delegation. Each due occurrence refreshes data, charges the sponsor and tenant and appends one version. Retry the same occurrence against its original capture or committed receipt. Show a missed occurrence and skip catch-up bursts. Resolve a local time in a gap to the first valid instant after it and an overlap to its earlier offset under ADR-0088 R8. Pin the boundary rule, tzdb version and resolved UTC deadline. Revoke or pause on sponsor departure, denied sources, changed recipe or stale fence, including a switch away and back. Resume requires current authority and fresh consent where the pin changed. Each occurrence runs the approved Python without a model call. Its new version is private until shared. Honor the existing scheduler enablement and sign-in gates. Reject a cron job running as a service administrator: it could keep publishing after the sponsor lost access. ## Delivery after the design read

1. **Runner and snapshot.** Run a buyer's private trial. Observe the actual isolated process, bounded capture, denied company/field access, limits, kill and teardown. Repeat a deterministic forecast after a receipt changes, then refresh to see the difference.
2. **Saved reports and sharing.** Save, share and inspect an exact DOCS-1 version. Withdraw one row or field grant and check the List, chart and direct document read. Retry publication after a lost response. Open a suggested Task and observe zero business writes until normal submission.
3. **AI authoring.** From a business question, review and edit the Python, run it and read its finding. Inject an instruction in a data value, race the last budget slot and retry an identical request. Observe tool receipts, spending and report versions.
4. **Schedules.** Opt into a Monday refresh. Restart after publication but before scheduler acknowledgement and observe one version and one charge. Revoke the sponsor's access and exercise a release switch away and back before wake.

## Questions for the owner

- **How long should exact repeats be available?** Recommend retaining the input for the life of each saved version and expiring unsaved trials after 24 hours. This makes a saved forecast reproducible and charges the storage to the tenant.
- **What spend should a small office start with?** Recommend the 20/100 daily starts and USD 1/5 daily model budgets in decision 5, then adjust platform policy using observed run cost and refusals.
- **Who gets Monday's refresh?** Recommend a private new version for the sponsor, with a separate explicit share for colleagues. A person who saw last week's chart may have lost source access since then.
