# ADR-0090. Run Python on an authorized snapshot and save the finding

**Slice 0 accepted, 2026-11-21.** The orchestrator accepted the design at `65bdc9f1`. The targeted check added entry conditions for slices 1b/2 and 3. The ADR number is assigned at merge.

A buyer asks, “Which parts are likely to run short next month?” She chooses her company's receipts and issues, inspects the Python and saves the quantities, a chart and the assumptions behind the forecast. After Wednesday's receipts arrive, an authorized colleague can inspect Tuesday's finding and, while its inputs are retained, rerun the code and compare results. A dispatcher can use the same facility to compare delivery sequences from a stop list and travel-time matrix.

## 1. Analysis produces evidence

REPORTS-1 owns the governed catalog of reusable datasets, measures and declared reports. An analysis can consume a catalog result where the query can account for every contributing source. Its own List shows saved analysis versions beside declared reports, labelled with their author and read instant. A forecast remains an estimate with units, assumptions and a method the reader can inspect. Business totals need the catalog's grain, currency and coverage contracts. That rules out registering arbitrary Python as a catalog measure.

This is the N5 analysis workspace. FORECAST-1 and ROUTES-1 may supply Python recipes with typed inputs and evidence outputs. A future callable extension inside an operation stays on N7's N2 pure-compute host with zero host grants. The host accepts start, cancel, save, share, revoke and schedule changes only as named Semantic Operations with scoped grants, audit and idempotency. The Python guest has zero host calls. This rules out a Python workflow SDK, connector credentials and posting plug-ins. The rentals survey's examples of inspecting a result, reviewing a proposed measure and scheduling a repeat informed the workflow. Rain supplies no executable, data or service. ## 2. One sealed input per run

The snapshot builder resolves the signed-in person, tenant, environment, authorized working company and verified release/fence at the Semantic Query gateway. It admits only release-registered queries with typed bindings, stable row identities and complete authorization lineage. Read all sources and pages in one read-only, repeatable-read snapshot. Capture the read instant, source horizon and company calendar there. Use stored ownership, scoped parent/row predicates and current field, classification and analysis/export permissions **before** data leaves the provider. Omit unreadable optional fields from schema and bytes. Refuse hidden dependencies required for output, filtering or joining, missing lineage, partial page set or incompatible horizon.

Seal the capture before releasing the read transaction. Recheck the live policy epoch and release fence before releasing input to a worker and again before returning even a private trial result. A store that cannot participate in the same read snapshot is ineligible.

Start with at most four sources, **20,000 rows and 8 MiB of canonical uncompressed input across the run**, with a five-second monotonic capture deadline. Enforce source-specific lower ceilings and provider scan bounds. Probe one past the limit and count bytes as they stream. On overflow discard the whole capture and ask for a narrower date range. Give the same response for a policy refusal wherever names or counts would reveal hidden data. Silently taking the first page could make half a month look like a full month.

Keep ordered, typed values (including exact decimals, units, currency and nulls) and a host-owned manifest. It binds scope, release root/fence, read instant, query and contract IDs, normalized parameters, order, contributing record identities/revisions and every field dependency, including fields used only for selection. An aggregate needs the lineage of its contributors even when Python sees just one total. Cap the private lineage at 4 MiB and refuse an incomplete proof. Hash the manifest and exact payload with SHA-256 using a versioned, length-delimited encoding. The guest receives only the admitted data, safe column IDs and analysis parameters. Internal policy evidence stays with the host.

The Run Task offers three choices. Both original-input modes require the live authorization decision in §4 and verified retained bytes, code and compatible contracts.

| Run choice | Inputs and execution |
| --- | --- |
| **Repeat these inputs** | Use the exact capture, code, parameters and original admitted image. Show why this choice is unavailable if a pin or input is unavailable. |
| **Same inputs on the current image** | Use the retained capture, code and parameters on today's admitted compatible image. Show both image digests and record the change, including when the original image was revoked. |
| **Refresh with current data** | Capture under today's release and grants, run on the current image and show the new read instant. |

A saved result stays readable under §4 if a repeat is unavailable. Filtering current rows by business date cannot recover the contents of a corrected row. [Live read decisions](ADR-0071-read-decisions-are-live-per-request-writes-per-call.md)

Python receives typed tables. A script may use the bundled SQLite library in its own sandbox over those sealed inputs. V1 has no SQL transform, host SQL validator or database SQL endpoint.

A dense travel-time matrix fits about **140 stops** when the stop list and matrix together fit the row and byte limits (140² + 140 = 19,740 rows). A 150-stop matrix alone exceeds the cap. ROUTES-1 must first supply a stored, governed **travel-time matrix Semantic Query** with typed origin and destination stop IDs, travel duration and unit, read horizon and contributor lineage. The runner cannot fetch directions. A parts forecast fits **1,000 part-periods per output table**, for example 100 parts over ten periods. A larger job must narrow its inputs or partition its results within §4's aggregate caps.

## 3. One disposable Linux container per run

A dedicated rootless launcher starts a fresh, non-root CPU-only OCI container from a locally admitted image digest. A versioned job protocol carries bounded input, status, cancellation and framed results by job ID. The transport can target a dedicated runner host. The API holds the database credentials and the guest has no access to the transport. The guest has a read-only root and input, one 128 MiB scratch tmpfs (including temporary files and library caches), private namespaces, dropped capabilities, no new privileges and a syscall policy denying sockets. Disable networking, inherited descriptors and environment, host directories, devices other than minimal private runtime devices, and access to any runtime socket. Supply only fixed locale, zone, seed and library settings. No database client credential, connector key, package installer or host shell is available to the job. A failed isolation or cgroup preflight refuses the run. An import blacklist or a process inside the ERP server would leave native scientific libraries outside Python's language checks. [Rootless containers](https://docs.docker.com/engine/security/rootless/) · [Network isolation](https://docs.docker.com/engine/network/drivers/none/)

| Enforced by the host | Initial ceiling per run |
| --- | --- |
| CPU, memory, processes | One CPU, 60 aggregate CPU-seconds, 1 GiB RAM including scratch, zero swap, 32 processes/threads. One numerical-library thread by default. |
| Time | 90 seconds by a monotonic supervisor clock. Apply the same per-run limits on CPU-only CI. |
| Output | 4 MiB total framed results, including charts, plus 64 KiB combined diagnostic streams. Cap input code at 64 KiB. Bound bytes as received, before parsing or buffering. |

**Slice 1a starts with a capability spike** on this WSL laptop and on a GitHub-hosted Linux runner. On both, launch the rootless fixture, observe the effective limits under load, cancel it and verify the whole job and scratch are gone. A platform that cannot enforce these controls refuses jobs. The owner’s 2026-11-21 ruling makes the GitHub-hosted proof the slice 1a build gate. Until the owner provisions rootless Docker and the same spike passes locally, the WSL runner must refuse with ANALYSIS_RUNTIME_UNAVAILABLE and name the missing capability.

Default to one live job on a single-tenant development host. Configure the host slot count explicitly. A shared host requires at least two configured slots and limits each tenant to one live job, aggregated across environments. Allow one live job per person. At dispatch, reserve worker and collector memory and verify measured available memory will leave at least 2 GiB for the OS, Postgres and app after outstanding reservations. Queue at most eight jobs per host and two per tenant. Dispatch fairly between tenants, refuse overflow immediately and expire a queued start after 30 monotonic seconds. Co-resident tenants could infer activity from timing if both run cooperating scripts. This is an accepted residual risk.

The supervisor terminates the entire container on cancellation, deadline, quota failure or excess output. Verify teardown, discard partial output and erase scratch before releasing the slot. After restart reconcile named jobs against their leases and reap abandoned containers. A platform operator can disable all runs or revoke one image digest, and a tenant administrator can stop their tenant. Fence new and queued starts, terminate matching active runs and check the stop generation again at publication. A late result cannot restore a cancelled job. A switch that only hides the Run button would leave scheduled and active jobs running. [Resource constraints](https://docs.docker.com/engine/containers/resource_constraints/)

Deployment requires linux/amd64 with CPython 3.12. An ARM host would require amd64 emulation and the same capability proof. The proposed first image pins pandas 2.3.3, NumPy 2.3.5, SciPy 1.16.3, statsmodels 0.14.5, scikit-learn 1.7.2, Matplotlib 3.10.7 (Agg) and OR-Tools 9.14.6206. These cover tables, time series, fitting, charts and vehicle routing on the same host. At image admission pin the exact interpreter/base digest, wheel versions and hashes including transitives, fonts, launcher protocol and final image digest. Build and smoke-test the complete lock on the target CPU with the limits above. Record the verified digest in the platform's allowed image profile before it can run. Mutable tags, user wheels and run-time installs would make the executable and native dependencies impossible to identify from the profile months later. Updates produce a new profile and revocation can disable any old digest. [Hash-checked installs](https://pip.pypa.io/en/stable/topics/secure-installs/) · [scikit-learn release](https://pypi.org/project/scikit-learn/1.7.2/) · [OR-Tools release](https://pypi.org/project/ortools/9.14.6206/)

The receipt identifies the exact Python bytes, bound parameters, snapshot digest and order, image and wheel lock, launcher protocol, CPU feature class, fonts, company calendar and tzdb. Pin process time zone to UTC, locale to C.UTF-8, `PYTHONHASHSEED=1`, and the default Python, NumPy and supported estimator/solver seeds to 1. Pin BLAS, OpenMP and solver workers to one, Matplotlib to Agg, and record the actual settings and solver stopping rule. A deterministic fixture on a matching image and CPU class must match. Scripts can ignore a seed, a different CPU can change floating-point results, and a time-limited OR-Tools search can finish with a different route on a busy host.

Compare digests of canonical tables, decoded chart pixels and finding text, excluding issuance metadata. Display **Matched** or **Different result** only after comparing the actual outputs. Preserve both receipts, the selected run mode and a link to the original.

**Slice 1a runner trust (R4).** The controller accepts the pinned SSH runner's machine ID, receipt and validated output. A compromised runner could claim another runner's machine ID or forge a result. Deploy the runner inside the trusted infrastructure boundary.

**Worker loss (R5).** If the supervisor exits during execution, the cgroup limits continue and the sleeper exits at 120 seconds. The guest could consume up to 120 wall seconds and about 120 CPU-seconds. A stopped container can persist until recovery. A permanently unavailable runner holds the person's cross-host slot because 1a has no operator lease-release operation.

## 4. Save a version under Documents and recheck every source

The host accepts a closed stream of typed tables, static PNGs and plain UTF-8 findings. Allow up to eight tables (1,000 rows × 32 columns each), four images (at most 2 megapixels each) and 32 KiB of findings, all within the run's aggregate output cap. Slice 1a's collector checks lengths and types. A fresh credential-free sandbox of the runner's isolation class checks PNG dimensions from the header before decoding, bounds allocation and re-encodes clean pixels. Only validated output leaves the collector. Escape all text. For an approved Task binding, also accept one optional set of suggested values keyed by the binding's typed input IDs. Count it within the 4 MiB cap. Refuse malformed results as a unit. The collector reads framed bytes only. Reject a directory of guest-named files, active formats and serialized Python objects because a host reader or a colleague's browser would interpret guest-controlled content.

**Save report** is an idempotent Semantic Operation. It creates a company-owned analysis record and an immutable DOCS-1 version, or appends a version to the authorized record at its expected predecessor. Admit a versioned, **internal, generated-only analysis evidence** content type (`analysisEvidenceV1`) through DOCS-1's content-policy adapter. The host encodes the validated tables, cleaned images, text, suggested values, exact Python bytes, and snapshot digest into one canonical bounded envelope. Bind the version to the snapshot handle, private source manifest and run receipt in the same commit. Bind recipe revision, actual actor, input and output digests, image/lock, parameters, read instant and release. The complete envelope must fit DOCS-1's size limit and pass a clean verdict on its exact bytes. Restrict this content type to the analysis publisher. Generic upload, template, signature, connector and customer-link paths cannot publish or disclose it. This stored type gets its own DOCS-1 reader rung in slice 2. The actual preceding binary must refuse it by name before serving bytes. Reject calling arbitrary JSON an existing PDF type or keeping a second report blob store. [Documents content and version policy](ADR-0078-governed-documents-files-templates-and-signatures.md)

Store snapshot payloads as private PostgreSQL `bytea` in the analysis provider and keep the bounded authorization manifest separately so it survives input expiry. DOCS-1 stores the evidence envelope in its existing governed blob provider. Scope both by tenant, environment and company, encrypt retained bytes and backups and restrict byte access to their providers. Proposed analysis sub-quota per tenant/environment is **256 MiB saved plus 40 MiB staging**, accounted separately from the ordinary document allowances of 100 MiB stored and 40 MiB staging. Charge analysis envelopes, trial output, snapshots and lineage to analysis only. Reserve actual bytes transactionally, including the staging-to-saved transfer. Evict the oldest completed unsaved trials first until an incoming reservation fits. Trials expire after 24 hours even below the cap. Refuse a reservation if active jobs or retained evidence leave insufficient space.

Keep a one-off saved version's repeat input for its retained life, subject to source purge. Per scheduled destination, rotate full inputs at successful publication so only the latest **four** versions retain repeat inputs. Keep older versions' results, lineage and receipts. Label them “Repeat inputs expired” and offer refresh while authorized. Count bytes until actually releasable, respect holds and refuse a publication that cannot fit after rotation. The run/request key returns the same version on retry under fresh authority. A conflicting retry, failed scan, revoked grant, changed fence or kill generation discards pending publication.

The proposed default **Analysis evidence — 90 days** is a minimum from publication for the saved result, its lineage and receipt. A longer policy or legal hold extends it. The repeat payload has the separate lifetime above. Under ADR-0078 an approved source purge must include **all** affected retained snapshot copies, including trials. Resolve them by contributor identity, lock the affected references, withhold the versions globally and erase the payload bytes as part of the purge. A hold that protects a required copy blocks completion of the source purge. Keep a purge tombstone and audit, and reapply the purge ledger before restored data can be served. [Document retention](ADR-0078-governed-documents-files-templates-and-signatures.md#record-links-versions-and-retention)

Capture sealing (1b) and source purge (1b for trials, 2 for saved copies) take the same transaction lock for the tenant and environment before any counter, reference or document locks. The repeatable-read transaction supplies the complete lineage and holds its snapshot open while a separate READ COMMITTED writer seals it. After taking the lock, the writer reads the committed purge ledger in a fresh statement. A tombstone for any contributor discards the pending bytes. Otherwise it commits payload and lineage together before releasing the lock. Purge takes that lock before scanning references and commits the tombstone and erasure together. Test both orders with two connections and a barrier. Pause after reading a contributor, commit its purge, then resume sealing and assert zero retained payload bytes and no usable handle. When sealing commits first, purge must find and erase the copy. Exercise a trial in 1b and the saved-version path in 2.

**One access rule for reads and repeats.** New reports are private. Sharing a precise version requires the sharer's disclosure grant and a live check of the named internal recipient. At every list, search, activity entry, metadata read, chart, preview, download, secondary link and original-input repeat (on either image), intersect the caller's version grant, governing-record read and working company with current governed access to **every original source, contributing row/revision and field**, including selection and join dependencies. A repeat also requires a run grant. Apply the rule in generic DOCS-1 paths and to private trial results, code and logs using the private run as governing record. A saved version grant permits a human read. Only the person's analysis session in §5 can disclose eligible data to a model, after this same check and its additional consent and filtering.

Batch candidate versions across the request and make one set-based governed check per source, including its authorized archive path for archived contributors. Bound the whole request to 32 source checks, 25,000 (version, contributor identity) pairs and two monotonic seconds. Bound a single capturable lineage to the same identity budget. Withhold every unproved version, including its title, count and bytes, on overflow, timeout, missing proof or a purged row. Never return a partial chart. With other budgets available, a List can release versions proved within 25,000 pairs. A candidate needing pair 25,001 is withheld in full. Test that boundary and a direct version read after access changes. Recheck byte/export authority and live policy epoch before the first response byte.

On the Save and Share screens tell the author, “If you lose access to any source row or field, you lose access to this report too.” On denial show a generic unavailable response. A purged contributor withdraws the whole version even from its author.

An authorized reader may open a **prefilled Task** for an operation bound at recipe publication. The server resolves its stable ID, pinned contract, current target, scope, grants and allowed input positions. Treat suggested ordinary values as untrusted, editable proposals labelled with their source. Never prefill protected Tier B dependencies, authority or approval evidence. The person reviews the operation's own effects and confirms as its contract requires. Opening or saving a report has zero business effect. No query, declared report, workflow or connector may consume a saved analysis table as input in v1. FORECAST-1 and ROUTES-1 can carry results into business work only through this prefilled Task. ## 5. Author and run through the same governed path

Its governing record is the private analysis run, scoped to the person, tenant, environment and company. The host derives its sources from the verified query catalog. A person can inspect and edit the complete Python in a plain textarea. For a manual start, **Run this code** binds the exact code, parameters, source contracts, snapshot or fresh-capture choice, release/fence and person. Show the code diff, company, read mode, limits and maximum charge. A colleague with a run grant can repeat a shared version as a new private trial under §4. Customize publishes reusable recipes. The existing List and Record show saved versions. Without JavaScript the Task submits, status refreshes by link and the report renders. Supply plain finding text (up to 4 KiB) and a sanitized exception type, line and message (up to 512 bytes). Keep chart pixels and raw logs out of the model.
4. Every disclosure belongs to the requesting person's session and sealed capture. Apply that person's current `erp_query` row, field and model-facing classification rules to all channels. 5. Within both ceilings the assistant may edit and rerun privately without another click. Recheck authority and remaining budget on each call and run. Before **Save, Share, Schedule or publish recipe**, a human reviews the exact Python and confirms its digest, source contracts, scope, fence and specific effect, including the version or recipe revision. An edit invalidates that review.
6. Starting with the first model call containing a data-derived profile, sample or output, and for as long as any remains in context, the only tools are **draft code**, **run on this same sealed snapshot** and **finish**. Treat cells, labels, comments, errors and findings as data. A request for another source, sharing, scheduling, a business operation or a connector must leave this context and receive fresh confirmation in the host UI. Slice 3 tests a first call containing only the data-derived profile, before any sample or run output. Inspect its exact advertised tool set and attempt a share through dispatch. Expect refusal and no share.
7. The tenant may opt into **schema only** to supply permitted schema and synthetic examples with no profile, samples or data-derived feedback. In either mode fields classified **not-for-model** never reach the model, even through profiles, findings or errors. Withhold the entire run's feedback if it derives from a protected field or if the host cannot establish independence from a protected input.
8. Slice 1a defines a receipt with the exact iteration code and a list of model-call disclosure digests (empty for a manual run). ## 6. Publish stable choices and prove compatibility

All three members carry a `schemaVersion`, stable logical and revision IDs, expected predecessor and an active or retired disposition. Retirements have a closed payload. `addAnalysisRecipeRevision` records source/query IDs and pinned input contracts, selected field IDs and types, parameters, exact Python bytes and their digest, image profile and typed result contract. `addAnalysisReportBindingRevision` binds a recipe to the governing record, document content contract and optional named Task operation and input positions. `addAnalysisScheduleRevision` binds a published recipe and report binding to a workflow schedule with a stable ID. The schedule carries recurrence and scope requirements. A person's consent, spend limits and credentials are never patch operands. Editing or retiring appends a revision. A single verified release selects the active revisions. Unknown members or variants, stale predecessors, collisions and dangling active references refuse the whole ordered change set.

At authoring bind stable choices once. Reproduce historical roots and check recorded digests exactly on the authoring base. Elsewhere validate the stored choices structurally against the new base, including input types, scope/grain and allowed output/operation contracts. Labels render from the active release. Report a lost source/field/operation by ID (`RETIRED_TARGET`) or changed contract by ID (`INCOMPATIBLE_TYPE`), keeping the verified release serving. Only the final active revision needs live bindings. Verify identity and predecessor for retired/superseded revisions. Release rollback restores the earlier bindings, stops new work under removed recipes and preserves existing versions under their recorded restrictions. Deriving a recipe again from today's List columns would break a compatible upgrade. Prove that adding an unrelated field and arranging the List work with the recipe active and again after retirement. ## 7. Schedule a fresh version through the workflow scheduler

Use the workflow scheduler's durable timer and journal. Each due occurrence refreshes data, reserves one start in the sponsor and tenant scheduled pools and appends one version. Retry the same occurrence against its original capture or committed receipt.

Show a missed occurrence and skip catch-up bursts. Resolve a local time in a gap to the first valid instant after it and an overlap to its earlier offset under ADR-0088 R8. Pin the boundary rule, tzdb version and resolved UTC deadline. Revoke or pause on sponsor departure, denied sources, changed recipe or stale fence, including a switch away and back. Resume requires current authority and fresh consent where the pin changed. Each occurrence runs the approved Python without a model call. Its new version is private to its sponsor until explicitly shared. Standing shares for scheduled destinations are deferred. Any later standing share would still need §4 on every open. Honor the existing scheduler enablement and sign-in gates. A cron job running as a service administrator could keep publishing after the sponsor lost access.
